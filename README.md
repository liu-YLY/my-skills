# My Skill - AI 技能集合项目

> 基于 AI 的智能技能系统，提供测试策略、测试用例生成、性能测试、Bug 根因分析、状态机测试、变更影响分析、前端测试准备、离线测试数据生成与校验、微信公众号排版等专业技能

## 项目简介

My Skill 是一个 AI 驱动的技能集合项目，旨在通过人工智能技术提升工作效率。项目包含多个专业领域的技能模块，每个技能都经过精心设计，能够理解用户需求并提供高质量的专业输出。

### 核心特性

- **AI 赋能**：基于大语言模型，理解自然语言需求
- **专业化输出**：每个技能都有明确的输出规范和质量标准
- **模块化设计**：技能独立运行，可按需组合使用
- **知识库支持**：内置专业知识库，确保输出的专业性和准确性
- **MCP 增强**：部分 skill 配套 MCP Server，提供确定性机器校验（未安装时降级为纯 LLM 推理）

> 上表中 **testing-bundle** 为 bundle 入口，按用户意图把请求路由到 8 个专业子 skill；**frontend-test-preparation** 仅在明确要求读前端代码、定位入口或维护页面索引时接入，普通「测试前端功能」仍由 test-case-engineer 处理。

**9 条混合意图链**：
- 链 1：Bug 分析 + 补充用例 → bug-analyzer → case-engineer
- 链 2：测试策略 + 分层用例 → strategy → case-engineer
- 链 3：性能测试 + 瓶颈定位 → performance（内部完成）
- 链 4：性能瓶颈 + 代码缺陷 → performance → bug-analyzer
- 链 5：状态机建模 + 用例生成 → state-machine → case-engineer
- 链 6：评审→覆盖缺口验证 → case-engineer 评审模式 → change-impact-analyzer
- 链 7：评审→风险用例根因反推 → case-engineer 评审模式 → bug-analyzer
- 链 8：编写/修订用例→离线数据准备 → case-engineer → test-data-generator
- 链 9：前端测试准备→用例编写 → frontend-test-preparation → case-engineer

已有用例或组合矩阵只需准备数据时，直接使用 test-data-generator，保留用例编号与固定维度。数据校验通过只表示已声明约束通过，系统执行仍为 `not_run`。

#### 路由型 Skill：testing-bundle 的任务转发场景

`testing-bundle` 自身不产出测试内容，只负责**意图判断与上下文转交**。8 个子 skill 都能独立使用，因此并非所有请求都需要经过 bundle。

| 场景 | 由谁处理 | 说明 |
|---|---|---|
| 意图单一且明确（只想生成用例 / 只想分析 Bug / 只想定位瓶颈） | 直连对应子 skill | runtime 直接命中子 skill，bundle 不介入 |
| 请求同时包含多个动作（如「分析 Bug 并补充用例」「评审用例并验证覆盖缺口」） | bundle 按混合意图链串联 | 按业务依赖顺序转交，一次授权内连续执行 |
| 目标模糊或用户明确要求路由（"不确定用哪个测试能力"） | bundle 追问后路由 | 先列出 8 个能力与适用场景，不默认选择 |
| 只给了代码改动，要影响范围 / 回归测试内容 | bundle 路由到 change-impact-analyzer | 不因出现「测试内容」自动转为完整用例生成 |
| 只说了「测试前端功能 / 测这个页面」 | bundle 路由到 test-case-engineer | 仅明确要求读前端代码、定位入口或维护页面索引时才转 frontend-test-preparation |
| 已有用例只要求造数或校验文件 | bundle 路由到 test-data-generator | 出现「用例 / 状态 / 并发」不自动触发用例生成、状态机建模或性能测试 |

**路由判定顺序**：提取意图三要素（对象 / 动作 / 交付物）→ 命中混合意图链则按链执行 → 未命中查单意图路由表 → 仍无法判断则追问（🔴 CHECKPOINT）。

**转交行为约定**：

- 转交时携带用户原始请求、上游产物、已完成步骤与下游待办，不丢失上下文
- 混合链结束时列出转交依据与未决事项，便于用户确认
- 子 skill 不可用时标注「子 skill 不可用」，只交付上游产物与方向性建议，不假装完成
- bundle 只做路由，不重复实现专业流程；单意图请求直接命中子 skill，无需经过 bundle

典型说法与转发目标：

| 用户说法 | 转发到 | 类型 |
|---|---|---|
| "制定项目测试策略 / 风险矩阵 / 准入准出" | test-strategy-engineer | 单意图 |
| "写用例 / 评审用例 / 梳理测试点" | test-case-engineer | 单意图 |
| "Bug 根因 / 复现 / 5 Whys" | bug-analyzer | 单意图 |
| "性能测试 / 压测 / RT 飙升定位瓶颈" | performance-test-engineer | 单意图 |

| "按已有用例生成离线数据 / 校验 JSON" | test-data-generator | 单意图 |
| "分析 Bug 并补充用例" | bug-analyzer → test-case-engineer | 链 1 |
| "状态机建模 + 生成完整用例" | state-machine-test-engineer → test-case-engineer | 链 5 |

## 快速开始

### 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows / macOS / Linux | 跨平台支持 |
| 运行环境 | Claude Code / Cursor / Codex / OpenCode 等 | 能够读取 skills 目录的 AI runtime |

### 安装

三种方式任选其一，完整步骤与故障排查见 [docs/installation.md](docs/installation.md)。

#### 方式 1（推荐）：npx skills add

通过 [skills CLI](https://skills.sh) 安装，自动适配 Claude Code / Cursor / Codex / OpenCode 等 70+ runtime。

```bash
# 前置：安装 Node.js v18+

# 步骤 1（可选）：查看仓库内所有可安装的 skill
npx skills add liu-YLY/my-skills --list

# 步骤 2：按需安装
# 2a. 安装全部 10 个 skill（testing-bundle + 8 个专业子 skill + wechat-formatter）
npx skills add liu-YLY/my-skills --skill "*" -g -y

# 2b. 仅安装测试插件全部 9 个 skill（bundle + 8 个专业子 skill）
npx skills add liu-YLY/my-skills \
  --skill testing-bundle --skill test-strategy-engineer \
  --skill test-case-engineer --skill performance-test-engineer \
  --skill bug-analyzer --skill state-machine-test-engineer \
  --skill change-impact-analyzer --skill test-data-generator \
  --skill frontend-test-preparation -g -y

# 2c. 仅安装微信公众号排版 skill
npx skills add liu-YLY/my-skills --skill wechat-formatter -g -y

# 2d. 指定目标 runtime（示例：同时装到 Claude Code 与 Cursor）
npx skills add liu-YLY/my-skills --skill testing-bundle -a claude-code -a cursor -g -y
```

> **Windows cmd 引号注意**：cmd.exe 不识别单引号，`--skill 'state-machine-test-engineer'` 会把两个单引号原样传给 CLI，导致报 `No matching skills found`，而下方 Available skills 里明明列出了该名字。cmd 下请用双引号或不加引号（名字无空格时可不加）；PowerShell / bash 下单双引号均可。含通配符时必须加引号（如 `--skill "*"`），否则会被 shell 提前展开。

常用参数：

| 参数 | 说明 |
|---|---|
| `-g, --global` | 全局安装（`~/<agent>/skills/`）；不加则装到项目级（`./<agent>/skills/`） |
| `-a, --agent` | 指定目标 runtime（`claude-code` / `cursor` / `codex` / `opencode` 等） |
| `-s, --skill` | 按 skill 名选择，支持通配符（如 `"test-*"`，需加引号），`"*"` 表示全部 |
| `-y, --yes` | 跳过确认提示（CI/CD 友好） |
| `--copy` | 复制文件而非 symlink（默认 symlink，便于后续更新） |

#### 方式 2：Plugin Marketplace（Claude Code 原生）

Claude Code 用户可通过原生 `/plugin` 命令按 plugin 粒度一键安装。

```text
# 步骤 1：注册 marketplace（只需执行一次）
/plugin marketplace add liu-YLY/my-skills

# 步骤 2：安装测试插件（含 testing-bundle + 8 个子 skill）
/plugin install testing-bundle@my-skill-marketplace

# 步骤 3：安装微信公众号排版 skill（可选）
/plugin install wechat-formatter@my-skill-marketplace
```

#### 方式 3：手动复制（离线兜底）

适用于未安装 Node.js 或需要离线安装的场景。先确认目标 runtime 的 skills 目录（Claude Code：`~/.claude/skills/`，Cursor：`~/.cursor/skills/`，Codex：`~/.codex/skills/`），再复制对应 plugin 下的 skill 子目录。

```bash
# 步骤 1：按实际 runtime 修改目标目录
SKILLS_DIR="$HOME/.codex/skills"
mkdir -p "$SKILLS_DIR"

# 步骤 2：复制 testing plugin 下全部 9 个 skill（含前端测试准备）
for skill_dir in plugins/testing/skills/*; do cp -R "$skill_dir" "$SKILLS_DIR/"; done

# 步骤 3：复制 wechat-formatter（可选）
cp -R plugins/wechat-formatter/skills/wechat-formatter "$SKILLS_DIR/"
```

Windows 用户可直接运行仓库内的 PowerShell 脚本：

```powershell
# 默认装到 ~\.claude\skills
.\scripts\install-testing-bundle.ps1

# 指定安装目录
.\scripts\install-testing-bundle.ps1 -TargetDir "C:\Users\<用户名>\.cursor\skills"

# 卸载
.\scripts\install-testing-bundle.ps1 -Uninstall
```

### 安装后配置与验证

1. **重启 runtime**：完全重启（而非新建终端窗口），让其重新扫描 skills 目录，技能会自动识别注册。
2. **（可选）安装脚本依赖**：安装 skill 本身不会自动安装依赖脚本。使用 test-data-generator 离线引擎需 Python 3.11+，并安装其 `scripts/requirements.txt`；使用 test-case-engineer 的文档转换脚本需 `pip install -r plugins/testing/skills/test-case-engineer/scripts/requirements.txt`。
3. **验证安装**：在 runtime 中输入技能名称或直接描述需求即可触发，正常激活会显示技能名称与版本信息。

```
测试用例工程师
我有一个用户登录功能需要测试...
```

> **依赖提示**：单独安装 bug-analyzer 时，因缺少 `test-case-engineer/knowledge/bug-patterns.md`，其「对照缺陷模式库」能力会降级（仍有通用模式兜底），**建议与 test-case-engineer 一起安装**。review-checker / state-machine-testing 为可选 MCP Server，未安装时对应 skill 降级为纯 LLM 推理，详见 [docs/installation.md](docs/installation.md)。

## 配置说明

### Git 提交规范

项目遵循 Conventional Commits 规范，提交信息格式 `<type>(<scope>): <subject>`，默认使用中文描述。完整规范详见 [rules/git-commit-message.md](rules/git-commit-message.md)，TRAE 用户会通过 [.trae/rules/git-commit-message.md](.trae/rules/git-commit-message.md) 自动注入硬约束。

### Git 工作流

采用 feature 分支工作流，禁止直接修改 main，PR 默认使用 squash merge，单个 PR 变更不超过 400 行。详见 [.trae/rules/git-workflow.md](.trae/rules/git-workflow.md)。

### Agent 工作规范

[AGENTS.md](AGENTS.md) 是跨工具通用 Agent 规范入口（TRAE / Cursor / Codex / Cline 均可读取），整合了 Git 提交规范、工作流规范、代码变更规范。

**分层设计**：

| 层级 | 位置 | 作用 | 读取方 |
|---|---|---|---|
| 跨工具通用 | `AGENTS.md` | 软规范 + 全景导航 | 所有 IDE |
