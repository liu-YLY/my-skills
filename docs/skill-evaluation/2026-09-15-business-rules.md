## 模型行为对照

固定 [9 个任务与 27 条判定标准](business-regressions.json)，覆盖 8 个 Skills（用例生成与评审各一个任务）。每轮包含全部 9 项；有 Skill／无 Skill 各独立重复 3 次。所有评测代理继承同一父任务模型配置，未覆盖 model 或 reasoning 参数。无 Skill 组只读取任务材料，不读取 Skill 正文；这不是移除全部系统说明的纯模型实验。

最终有 Skill 组读取文件的 SHA256 与交付正文一致。初期调试轮次不纳入以下统计。由主代理完整阅读答案并按预先给出的标准人工判定，**未做盲评**。

| 指标 | 有 Skill | 无 Skill |
|---|---:|---:|
| 任务数 | 27 | 27 |
| 判定条目通过 | 81/81 | 81/81 |
| 判定范围内业务遗漏／确定误判 | 0/0 | 0/0 |
| 每轮 9 任务总耗时均值 ± 样本标准差 | 292.8 ± 32.5 秒 | 93.9 ± 13.3 秒 |
| 总耗时范围 | 267.7～329.5 秒 | 79.0～104.6 秒 |
| 每轮输出字符数均值 | 2,886 | 2,134 |
| token／费用 | 无工具计量，未估计 | 无工具计量，未估计 |

**结论**：本组简单、明确的反例未显示 Skill 的正确率优势；有 Skill 组提供了更明确的项目字段、检查点和未评估项，但总耗时更长。无 Skill 三轮均提出“测试点编号可能需要场景唯一”的条件性建议，现有材料没有这条规则；因为没有判为确定问题，未计入确定误判。该观察可用于后续降低候选提示噪声，不能据此宣称整体质量提升。

可执行性仍有环境边界：生成的订单用例需要落实商品、收货资料及支付渠道；案例文字通过评测不等于业务已执行。耗时包含文件读取和工具处理，且运行时存在并发负载；不能用这组数字推算纯模型速度或计费成本。
