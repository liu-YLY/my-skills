# 经验库

> 只沉淀**有执行证据、可迁移**的经验。每条必须写清证据、适用范围与不适用边界。
> 本库不把「结构分上涨」或「确定性规则通过」当作质量提升结论。

## E-001 单一权威源去重能降低上下文而不改变确定性行为

- **场景**：多个知识文件对字段、句式、模糊词、反例各维护一份副本。
- **做法**：指定一个权威源（`writing-rules.md`），其余文件只留指针；把可延迟的细则移到按需文件。
- **证据**：
  - 四个写作文件 25,584 → 12,920 字符（-49.5%）；
  - test-case default 64,028 → 36,394（-43.2%），review 33,545 → 19,566（-41.7%）；
  - 6 个仓库脚本、pytest 36、10 份历史产物 0 error 全部通过。
- **可迁移**：字段/格式/术语/反例在多文件重复维护的 skill。
- **边界**：只证明「确定性行为未回退」与「上下文下降」，不证明模型质量提升。
- **证据强度**：确定性。

## E-002 原文逐字回查是需求评审最硬的防伪造闸门

- **场景**：评审报告可能出现「原文看起来像，但 PRD 里没有」的问题，尤其是补造数值、文案、时限。
- **做法**：要求每条问题带 `location` + 逐字 `quote`；校验器以 `--prd` 做归一化回查，矛盾引用按 ` / ` 分段回查。
- **证据**：
  - `validate_requirement_review.py` 的 `RR_QUOTE_NOT_FOUND` 能拦截伪造 quote；
  - 单元测试 `test_fabricated_quote_is_error` 通过；
  - 5 份 gold 报告 25/25 条问题全部可回查，0 error。
- **可迁移**：需求评审、PRD 审计、合规检查、任何要求「引用原文」的报告。
- **边界**：只能拦截「引文不存在」，不能判断「引文被误读」或「问题级别不合理」。
- **证据强度**：确定性。

## E-003 结构化产物应在阶段闸门做 schema 校验，而不是留到最终评审

- **场景**：测试点清单与评审报告字段多、枚举多，人工逐条核对成本高。
- **做法**：为每类产物提供独立校验器，接入阶段闸门（测试点 0 error 进阶段 3；评审报告 0 error 才交付）。
- **证据**：
  - `validate_points.py` 覆盖 ID/维度/优先级/重复/追溯/裁剪/预算/需求覆盖；
  - `validate_requirement_review.py` 覆盖 9 列必填/枚举/统计/维度/原文；
  - 两个校验器 10 项单元测试 + gold 样例 10/10 通过。
- **可迁移**：测试点、评审报告、影响分析报告、任何固定 schema 的中间产物。
- **边界**：只覆盖 D 类可布尔规则；覆盖度、语义正确性仍需 J 类评审。
- **证据强度**：确定性。

## E-004 旧版本历史产物只能做代理基线，不能当当前质量分数

- **场景**：用历史 `with_skill` 产物做失败聚类时，产物来自旧 skill 版本，且 22/42 不可解析为用例格式。
- **做法**：把历史产物标为「确定性代理基线」，只用于发现格式/结构类问题和构造回归集，不用于计算当前版本通过率。
- **证据**：
  - 42 份产物中 20 份可解析、153 条用例，10 error / 26 WARN；
  - 失败集中在 `TITLE_SEPARATOR` 13、`ARRANGE_DECLARE` 7、`VAGUE_WORD` 7；
  - 这些产物与 v7.2 的 70 个 task 不能一一对应。
- **可迁移**：任何跨版本复用历史产物做评测的场景。
- **边界**：代理基线可发现规则漂移，但不能证明当前 skill 仍失败或已修复。
- **证据强度**：代理（确定性校验）。

## E-005 没有独立 runner/judge 时，必须把优化停在提案而不是合并

- **场景**：harness² 要求 base/inv1/dom1 同模型、同参数、同套件 Probe，并按 +5pp 主指标与护栏门槛采纳。
- **做法**：缺 runner/judge/API key 时，只产出失败聚类、INV/DOM 提案与经验；不合并未 Probe 的改动，不宣称质量提升。
- **证据**：
  - 阶段 4 环境无 `opencode`/`zcode`/`codebuddy`/`claude`/`codex`，无模型 API key；
  - v7.2 输入校验可运行，但 `skill-evals.py` 明确只做输入校验；
  - 阶段 1 基线同样因同一原因标 `blocked`。
- **可迁移**：所有依赖模型行为的优化流程。
- **边界**：静态提案可以准备，但不能替代 Probe；一旦 runner 可用，应按冻结套件与采纳规则重跑。
- **证据强度**：环境事实。
