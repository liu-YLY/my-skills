# 拼多多风格电商交易需求文档

> 文档编号：PRD-PDD-TRADE-001
> 版本：1.0.0（评测冻结版）
> 状态：冻结。评测周期内不得修改；任何变更必须升级版本、记录变更原因并重新生成 SHA256。
> 适用端：移动端 App / H5 / 微信内置浏览器
> 语言与地区：简体中文，中国大陆手机号，Asia/Shanghai
> 用途：作为 Skill 评测的固定业务输入，覆盖登录注册、购物车、购买三条主链路；不作为可直接上线的最终产品需求。

---

## 1. 背景与目标

### 1.1 业务背景

借鉴拼多多移动端交易体验，设计一条从新用户进入、登录注册、商品加购、确认订单、支付到拼单结果的完整交易链路。业务特征：

- 手机号验证码是主注册/登录方式，微信授权是重要补充入口。
- 购物车承载跨店铺商品，价格、库存、优惠券、运费在结算时实时校验。
- 购买支持「单独购买」与「拼单」两种模式，拼单失败自动退款。
- 资金、库存、优惠券属于强一致敏感域，必须防重复、防超卖、防越权。

### 1.2 评测目标

本文档用于稳定复跑以下三类任务：

1. 需求评审：发现规则冲突、歧义、缺失定义与高风险场景。
2. 测试点提取：从需求中提取可执行、可追溯、覆盖风险维度的测试点。
3. 测试用例编写：基于需求与测试点输出可执行、可判定的用例。

### 1.3 产品目标（仅作背景，不作为验收条件）

- 新用户从进入登录页到完成注册不超过 3 个页面。
- 有效商品从加购到提交订单的主链路不因非必要弹窗中断。
- 支付成功、拼单结果、退款状态对用户可查。

## 2. 用户角色与核心场景

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| 游客 | 未登录用户 | 先浏览、可加购，登录后不丢购物车 |
| 新用户 | 无账号手机号 | 快速注册并完成首单 |
| 老用户 | 已有账号 | 快速登录、管理购物车、复购 |
| 拼单发起人 | 开团用户 | 以拼单价购买，等待成团 |
| 参团人 | 加入他人拼单的用户 | 加入已有团，成团后享受拼单价 |
| 运营/客服 | 后台角色 | 查询订单、支付、退款状态，处理异常 |

核心场景：

1. 新用户手机号验证码注册 → 加购 → 单独购买 → 微信支付成功。
2. 老用户密码登录 → 购物车修改数量 → 使用优惠券 → 提交订单 → 支付宝支付。
3. 用户微信授权登录 → 绑定手机号 → 加购 → 发起 2 人拼单 → 成团。
4. 用户发起拼单 → 24 小时未成团 → 自动退款。
5. 用户在支付页停留超过 15 分钟 → 订单关闭 → 库存与优惠券释放。

## 3. 范围与边界

### 3.1 本期范围

| 模块 | 本期包含 | 本期不包含 |
|---|---|---|
| 账号 | 手机号验证码注册/登录、密码登录、微信授权登录、绑定手机号、登出、找回密码、会话管理、基础风控、账号注销 | 邮箱注册、海外手机号、实名认证、会员等级、积分 |
| 购物车 | 加购、列表、选择、数量修改、删除/清空、失效商品、价格变化、优惠计算、运费、游客购物车合并、跨端同步、结算 | 收藏夹、比价、跨店满减、预售、定金 |
| 购买 | 确认订单、地址选择、优惠券选择、提交订单、库存锁定、支付、支付回调、订单查询、取消、超时关闭、拼单、拼单失败退款 | 发货、物流、售后/退货/换货、发票、评价、客服工单 |

### 3.2 明确不做

- 不做商品搜索、推荐、店铺装修、直播带货。
- 不做余额支付、货到付款、分期支付。
- 不做完整售后流程；仅支持拼单失败自动退款。
- 不做多语言、多币种、跨境交易。

## 4. 术语

| 术语 | 定义 |
|---|---|
| SKU | 最小库存单元，同一商品的不同规格分别对应不同 SKU |
| 单独购买 | 用户不参与拼单，按单独购买价直接下单 |
| 拼单 | 用户以拼单价发起或加入 2 人团，成团后交易成立 |
| 成团 | 拼单人数达到 2 人，拼单成功 |
| 锁库存 | 提交订单时占用库存，超时或取消后释放 |
| 幂等键 | 客户端生成的唯一键，用于避免重复提交产生重复订单 |
| 会话 | 用户登录后服务端签发的访问凭证与刷新凭证 |
| 失效商品 | 下架、SKU 删除或库存为 0 的购物车商品 |
| 偏远地区 | 新疆、西藏、内蒙古、宁夏、青海、甘肃 |

## 5. 全局规则

| ID | 规则 |
|---|---|

| G-02 | 所有时间以服务端时间为准，时区 Asia/Shanghai；15 分钟 = 900 秒，24 小时 = 86400 秒 |

## 6. 账号与登录注册

### 6.1 功能清单

| ID | 功能 | 说明 | 优先级 |
|---|---|---|---|
| AUTH-F01 | 手机号验证码注册/登录 | 未注册自动注册，已注册直接登录 | P0 |
| AUTH-F02 | 密码登录 | 手机号 + 密码 | P0 |
| AUTH-F03 | 微信授权登录 | 微信授权 + 手机号绑定 | P0 |
| AUTH-F04 | 登出 | 当前设备退出登录 | P0 |
| AUTH-F05 | 找回/重置密码 | 手机号验证码重置 | P1 |
| AUTH-F06 | 会话管理 | 访问令牌、刷新令牌、设备数限制 | P0 |
| AUTH-F07 | 账号安全与风控 | 限流、防枚举、图形验证码、滑块 | P0 |
| AUTH-F08 | 用户协议与隐私 | 协议勾选、手机号脱敏 | P0 |
| AUTH-F09 | 账号注销 | 7 天冷静期，注销后手机号可重新注册 | P2 |

### 6.2 主流程

#### 6.2.1 手机号验证码注册/登录

1. 用户进入登录页，输入手机号。
2. 客户端校验手机号格式；格式错误直接提示 AUTH-1001，不请求验证码。
3. 用户点击「获取验证码」；服务端校验发送频率与风控规则。
4. 服务端生成 6 位数字验证码，哈希存储，调用短信通道发送。
5. 用户输入验证码，勾选用户协议与隐私政策，点击「登录/注册」。
6. 服务端校验协议、验证码、有效期、尝试次数。
7. 校验通过后：手机号未注册则创建账号；已注册则直接登录。
8. 服务端签发访问令牌与刷新令牌，返回用户信息与登录态。
9. 客户端进入首页或原跳转页；游客购物车在登录后合并。

#### 6.2.2 密码登录

1. 用户选择「密码登录」，输入手机号与密码。
2. 客户端校验手机号格式；密码不做格式提示，避免泄露规则。
3. 服务端校验账号状态、密码、失败次数、锁定状态、图形验证码。
4. 校验通过后签发令牌；失败统一返回 AUTH-1004。
5. 连续失败达到阈值触发锁定或图形验证码。

#### 6.2.3 微信授权登录

1. 用户点击「微信登录」，跳转微信授权。
2. 客户端获取授权码，服务端换取 `openid` / `unionid`。
3. 若 `unionid` 已绑定账号，直接登录。
4. 若未绑定，进入手机号绑定页；手机号验证码校验通过后绑定并登录。
5. 同一 `unionid` 只能绑定一个账号；同一手机号只能绑定一个微信账号。

#### 6.2.4 登出

1. 用户在「我的」页点击「退出登录」。
2. 服务端撤销当前设备的访问令牌与刷新令牌。
3. 客户端清除本地登录态与游客态缓存，跳转登录页。
4. 其他设备登录态不受影响。

#### 6.2.5 找回/重置密码

1. 用户输入手机号并获取验证码。
2. 验证码校验通过后设置新密码。
3. 新密码校验规则同注册密码。
4. 重置成功后，该账号所有设备会话失效，需重新登录。

#### 6.2.6 账号注销

1. 用户在账号设置中申请注销。
2. 服务端校验无进行中订单、无进行中退款、无未结算资金。
3. 提交成功后进入 7 天冷静期；期间用户登录可撤销注销。
4. 冷静期结束后账号不可登录，手机号进行匿名化处理。
5. 订单、支付、退款记录按法律法规要求保留；手机号可在注销完成后重新注册。

### 6.3 业务规则

| ID | 规则 |
|---|---|
| BR-AUTH-01 | 手机号必须匹配 `^1[3-9]\d{9}$`；提交前去除首尾空格；非中国大陆手机号拒绝 |
| BR-AUTH-02 | 验证码为 6 位数字，有效期 5 分钟；同一手机号 60 秒内不可重复发送；同一手机号每日最多 10 条、同一设备每日最多 20 条、同一 IP 每日最多 50 条 |
| BR-AUTH-03 | 验证码最多校验 5 次；第 5 次失败后当前验证码立即失效，必须重新获取 |
| BR-AUTH-04 | 验证码仅保存哈希；验证成功后立即失效；任何日志与接口响应不得返回明文验证码 |
| BR-AUTH-05 | 未注册手机号验证码校验通过后自动创建账号；已注册手机号直接登录；同一手机号只能存在一个有效账号 |
| BR-AUTH-06 | 登录/注册前必须勾选《用户协议》和《隐私政策》；默认不勾选；未勾选返回 AUTH-1006 |
| BR-AUTH-07 | 密码长度 8-20 位，至少包含字母和数字；不得与手机号相同；不得为连续 6 位以上数字；注册与重置时校验 |
| BR-AUTH-08 | 密码连续错误 5 次锁定 15 分钟；第 3 次失败起要求图形验证码；锁定期间即使密码正确也拒绝；登录成功后失败计数清零；锁定到期后计数清零；错误提示统一为「手机号或密码错误」 |
| BR-AUTH-09 | 微信登录未绑定手机号时必须绑定；绑定需短信验证；同一 `unionid` 只能绑定一个账号，同一手机号只能绑定一个微信账号 |
| BR-AUTH-10 | 登出后当前设备的访问令牌与刷新令牌立即失效；其他设备不受影响 |
| BR-AUTH-11 | 访问令牌有效期 2 小时，刷新令牌有效期 7 天；刷新时旋转刷新令牌；旧刷新令牌重放时撤销该会话族；同一账号最多 5 台设备在线，第 6 台登录踢出最早登录设备；同一 `device_id` 只计一台设备 |
| BR-AUTH-12 | 找回密码需手机号 + 验证码；新密码规则同 BR-AUTH-07；重置成功后所有设备会话失效 |
| BR-AUTH-13 | 账号注销需 7 天冷静期；冷静期内登录可撤销；注销完成后手机号匿名化，可重新注册；订单与支付记录按法规保留 |
| BR-AUTH-14 | 手机号展示必须脱敏为前 3 位 + 4 个 `*` + 后 4 位；日志与接口响应不得返回完整手机号 |
| BR-AUTH-15 | 验证码登录不得提示手机号是否已注册；密码登录统一提示「手机号或密码错误」；图形验证码或滑块按风控结果触发 |
| BR-AUTH-16 | 同一设备 1 小时内注册超过 5 个账号必须触发滑块验证；可疑 IP 或设备直接拦截并返回 AUTH-1010，同时展示客服入口 |
| BR-AUTH-17 | 短信通道失败返回 AUTH-1011；失败不计入发送次数；记录通道错误日志并支持重试 |
| BR-AUTH-18 | 登录态过期时，客户端跳转登录；重新登录后恢复原页面与购物车勾选状态；已提交订单不因重新登录重复创建 |

| ID | 验收条件 |
|---|---|
| AC-AUTH-01 | 输入 10 位手机号、以 12 开头的手机号或含字母的手机号，均不发送验证码并提示格式错误 |

| AC-AUTH-10 | 手机号在页面与日志中均脱敏展示 |
| AC-AUTH-11 | 结算过程中登录态过期，重新登录后可恢复原页面与购物车勾选状态，已提交订单不重复创建 |

## 7. 购物车

### 7.1 功能清单

### 7.2 主流程

#### 7.2.1 加入购物车

1. 用户在商品详情页选择 SKU。
2. 用户选择数量，点击「加入购物车」。
3. 客户端提交 SKU、数量、来源页面。
4. 服务端校验 SKU 状态、库存、购物车容量。
5. 同 SKU 合并数量；不同 SKU 新增一行。
6. 返回成功，客户端展示 toast 并更新购物车角标。

#### 7.2.2 购物车结算

1. 用户进入购物车，默认全选有效商品。
2. 用户可取消选择、修改数量、删除商品、切换优惠券。
3. 页面实时展示商品小计、店铺优惠、优惠券优惠、运费、合计。
4. 用户点击「结算」，客户端提交勾选的 `cart_item_ids`。
5. 服务端校验商品有效性、库存、价格变化、优惠券可用性。
6. 校验通过后跳转确认订单页；校验失败定位到具体商品并提示。

### 7.4 购物车计算示例

固定示例数据见 §13。示例：

- SKU-001 单价 59.90，数量 2，商品小计 119.80。
- 店铺满减：满 100 减 10，优惠 10.00。
- 优惠券 C1：满 100 减 5，门槛按 109.80 计算，可用，优惠 5.00。
- 商品实付金额：119.80 - 10.00 - 5.00 = 104.80，≥ 99，包邮。
- 应付金额：104.80。

若收货地址为新疆，则运费 12.00，应付金额 116.80，且不享受包邮。

### 8.2 主流程

#### 8.2.1 单独购买

1. 用户从购物车或商品详情进入确认订单页。
2. 页面展示默认地址、商品清单、商品小计、店铺优惠、优惠券、运费、应付金额。
3. 用户选择地址、优惠券，点击「提交订单」。
4. 服务端重新计算金额、校验地址、校验优惠券、锁定库存。
5. 创建订单，状态为「待支付」，返回订单号与支付参数。
6. 用户选择支付方式并支付。
7. 支付渠道回调服务端；服务端验签、校验金额、幂等更新订单。
8. 订单状态变为「已支付/待发货」，客户端展示支付成功页。

#### 8.2.2 拼单购买

1. 用户在商品详情页选择「发起拼单」或「单独购买」。
2. 发起拼单时创建待支付订单并锁库存；支付成功后订单进入「拼单中」，拼单记录生效，24 小时倒计时开始。
3. 其他用户通过分享链接参团；参团订单提交时锁库存，支付成功后加入拼单。
4. 人数达到 2 人时成团，订单状态变为「拼单成功」，支付成功的订单进入待发货。
5. 24 小时未成团，拼单失败，订单进入「退款中」，自动原路退款，退款成功后状态为「已退款」。
6. 成团后不可取消；拼单失败后库存与优惠券按规则释放/返还。

#### 8.2.3 支付超时与取消

1. 订单创建后 15 分钟未支付，定时任务关闭订单。
2. 关闭时释放锁定库存、释放优惠券、订单状态变为「已关闭」。
3. 用户在待支付期间可主动取消；取消后同样释放资源，状态变为「已取消」。
4. 已支付订单不可直接取消。

## 11. 状态机

### 11.1 订单状态

```text
PENDING_PAYMENT --支付成功--> PAID
PENDING_PAYMENT --用户取消--> CANCELLED
PENDING_PAYMENT --15 分钟超时--> CLOSED
PENDING_PAYMENT --拼单支付成功--> GROUP_FORMING --2 人成团--> GROUP_SUCCESS
GROUP_FORMING --24 小时未成团--> GROUP_FAILED --> REFUNDING --> REFUNDED
```

约束：

- `PAID`、`CANCELLED`、`CLOSED`、`GROUP_SUCCESS`、`REFUNDED` 为终态。
- 终态不可回退。
- 只有 `PENDING_PAYMENT` 可取消。
- 只有 `GROUP_FORMING` 可因超时失败。
- 退款只由拼单失败触发。

### 11.2 支付状态

```text
INIT --回调成功--> SUCCESS
INIT --回调失败--> FAILED
INIT --订单关闭--> CLOSED
```

约束：

- 一个订单最多一条 `SUCCESS` 支付记录。
- `SUCCESS` 支付记录不可回退。
- 重复回调不改变状态。

### 11.3 会话状态

```text
ACTIVE --登出/过期/被踢/重置密码--> INVALID
```

### 11.4 购物车商品状态

```text
VALID --下架/删除/库存为 0--> INVALID
```
