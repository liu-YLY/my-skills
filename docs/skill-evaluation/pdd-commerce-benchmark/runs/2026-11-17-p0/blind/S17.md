# 需求评审报告：购买、订单与支付

> 评审对象：PRD-PDD-TRADE-001 v1.0.0
> 评审范围：订单确认、提交、支付、回调、取消、超时、拼单、退款、对账及其与购物车/账号的接口

## 1. 需求理解摘要

1. 订单主链路为：确认订单 → 提交订单（锁库存）→ 支付 → 渠道回调 → 订单已支付；待支付订单 15 分钟超时关闭。
2. 金额由服务端重算，顺序为商品小计 → 店铺满减 → 优惠券 → 运费，购物车、确认页、支付三处金额必须一致。
3. 提交订单必须幂等，同一用户 + 同一幂等键 60 秒内只生成一个订单，库存与优惠券只锁定一次。
4. 支付回调必须验签、校验渠道流水号唯一、金额一致、订单状态可支付；重复回调幂等。
5. 拼单为 2 人团，支付成功后进入拼单中，24 小时未成团自动失败并原路退款。
6. 拼单失败退款金额为实际支付金额，未过期优惠券返还，已过期不返还。
7. 订单只能由本人查看和操作，越权不泄露订单是否存在。
8. 支付成功但订单未更新时，以渠道流水为准补偿，补偿必须幂等。
9. 本期不包含发货、物流、售后、发票、评价；拼单失败退款是唯一退款路径。
10. 第 14 节开放问题中，与本模块相关的是退款节假日口径、不可配送区域维护、拼单并发上限。

## 4. 建议补充的验收标准

1. **AC-ORDER-X1 关闭后回调**：订单已关闭后收到支付成功回调，系统必须进入明确的退款/补偿流程，订单终态不可回退，并生成可查询的退款单或补偿记录。
2. **AC-ORDER-X2 乱序回调**：先成功后失败的重复/乱序回调不得改变成功支付记录，必须记录异常并告警。
3. **AC-ORDER-X3 拼单并发上限**：同一用户同时参与的拼单数量达到上限时，新开团/参团被拒绝，已占用库存按规则释放。
4. **AC-ORDER-X4 退款失败兜底**：退款连续失败达到上限后进入人工处理状态，用户可查询到「退款处理中/失败待处理」。
5. **AC-ORDER-X5 券返还口径**：拼单失败后未过期券返还，返还券的有效期、门槛、可用范围有明确规则并可验证。
6. **AC-ORDER-X6 0 元单**：当优惠后应付为 0 时，系统按产品确认的规则处理（0 元支付或最低 0.01 元），订单与支付记录一致。
7. **AC-ORDER-X7 地址拦截时机**：确认页与提交时均校验不可配送区域，错误码与提示一致，且不产生订单。
8. **AC-ORDER-X8 金额一致性**：在价格变化、优惠券切换、拼单、退款场景下，购物车、确认页、支付、退款金额均可追溯且一致。
