# 订单支付模块需求评审

## 1. 需求理解摘要

1. 用户可以选择商品、填写地址、使用优惠券并提交订单。
2. 订单提交后进入待支付状态，用户选择微信或支付宝完成支付。
3. 支付成功后订单变为已支付，支付失败可以重试。
4. 订单超过一定时间未支付会关闭。
5. 支持拼单，拼单失败会退款。
6. 用户可以取消待支付订单。

## 3. 风险清单

| 风险 | 等级 | 说明 | 建议验证 |
|---|---|---|---|
| 支付安全 | 高 | 支付金额可能被客户端篡改 | 校验服务端金额与回调 |
| 重复提交 | 高 | 用户快速点击可能生成多个订单 | 验证提交按钮防抖与幂等 |
| 库存不足 | 中 | 下单时可能没有校验库存 | 验证库存不足提示 |
| 退款异常 | 中 | 拼单失败后退款可能失败 | 验证退款重试 |
| 订单越权 | 中 | 用户可能访问他人订单 | 验证订单权限 |
| 超时关闭 | 中 | 订单可能未按时关闭 | 验证定时任务 |

## 4. 建议补充的验收标准

1. 支付金额必须与服务端订单金额一致。
2. 重复提交只能生成一个订单。
3. 库存不足时不能提交订单。
4. 拼单失败后必须退款并更新订单状态。
5. 用户只能查看自己的订单。
6. 待支付订单超时后必须关闭。
