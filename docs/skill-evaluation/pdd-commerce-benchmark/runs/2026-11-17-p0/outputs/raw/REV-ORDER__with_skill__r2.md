# 订单支付模块需求评审（复跑）

> 评审对象：PRD-PDD-TRADE-001 v1.0.0
> 运行：REV-ORDER__with_skill__r2（A/A 复跑）

## 1. 需求理解摘要

- 订单由确认页、提交、支付、回调、结果页组成；提交时锁库存 15 分钟，超时关闭并释放资源。
- 支付成功以渠道回调为准，必须验签、校验金额与状态，并保证重复回调幂等。
- 拼单是 2 人团，支付成功进入拼单中，24 小时未成团失败并退款。
- 退款只发生在拼单失败；退款金额为实际支付金额，优惠券按是否过期决定是否返还。
- 用户只能访问自己的订单；所有金额以服务端重算为准。
- 本期不做发货、物流、售后、发票。

## 3. 风险清单

| 风险 | 等级 | 说明 | 建议验证 |
|---|---|---|---|
| 支付回调重复/并发 | S1 | 重复回调可能重复记账 | 同一流水号并发回调，核对支付记录唯一 |
| 库存超卖 | S1 | 提交、取消、超时、拼单失败并发释放 | 并发抢购同一 SKU，核对库存不为负 |
| 优惠券重复使用 | S1 | 同一券被多订单同时使用 | 并发用券，核对仅一单成功 |
| 金额不一致 | S1 | 购物车、确认页、支付金额分别计算 | 价格变化/切券/拼单场景核对三处金额 |
| 订单越权 | S1 | 订单号可枚举或直接访问 | 跨用户访问核对无权限且不泄露存在性 |
| 拼单退款与券返还 | S2 | 退款金额、券状态、退款单不一致 | 拼单失败后核对三者 |
| 关闭与回调竞态 | S2 | 终态可能不唯一 | 注入并发，核对终态与资金可追溯 |
| 对账补偿 | S2 | 支付成功订单未更新 | 模拟更新失败，核对补偿与告警 |

## 4. 建议补充的验收标准

1. 关闭后支付回调必须进入明确的退款/补偿流程，订单终态不可回退。
2. 乱序回调不得改变成功支付记录，必须告警。
3. 拼单并发上限达到时拒绝新开团/参团，并释放已占用资源。
4. 退款失败达到上限后进入人工处理，用户可查询状态。
5. 券返还后的有效期与门槛有明确规则。
6. 0 元单按产品确认的规则处理，订单与支付记录一致。
7. 不可配送地址在确认页与提交时均被拦截，错误码一致。
8. 价格变化、切券、拼单、退款场景下金额可追溯且一致。
