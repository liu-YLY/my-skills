# 购买、订单与支付模块需求评审（第三次运行）

## 1. 需求理解摘要

- 订单链路：确认订单 → 提交（锁库存 15 分钟）→ 支付 → 渠道回调 → 已支付。
- 金额由服务端重算，顺序为商品小计 → 店铺满减 → 优惠券 → 运费，三处金额必须一致。
- 提交必须幂等；支付回调必须验签、校验金额与状态、重复回调幂等。
- 拼单 2 人成团，24 小时未成团失败并退款；退款金额为实际支付金额。
- 仅待支付订单可取消；已支付订单不可直接取消。
- 本期不含发货、物流、售后、发票。

## 4. 建议补充的验收标准

1. 关闭后回调必须进入明确退款/补偿流程，终态不可回退。
2. 乱序回调不得改变成功支付记录，必须告警。
3. 拼单并发上限达到时拒绝新开团/参团。
4. 退款失败达到上限后进入人工处理，用户可查询。
5. 券返还后的有效期与门槛有明确规则。
6. 0 元单按产品确认规则处理，订单与支付记录一致。
7. 不可配送地址在确认页与提交时均被拦截。
8. 价格变化、切券、拼单、退款场景下金额可追溯。
