# 订单支付模块需求评审（第三次运行）

## 1. 需求理解摘要

- 订单流程包括确认订单、提交订单、支付和支付结果。
- 订单提交后进入待支付，超时关闭。
- 支付支持微信和支付宝。
- 拼单需要两人成团，失败退款。
- 用户可以取消待支付订单。
- 订单状态需要在页面上展示。

## 3. 风险清单

| 风险 | 等级 | 说明 | 建议验证 |
|---|---|---|---|
| 重复支付 | 高 | 回调重复可能重复记账 | 重复回调测试 |
| 订单超时 | 中 | 订单可能未关闭 | 定时任务测试 |
| 库存不足 | 中 | 下单时库存可能不足 | 库存校验 |
| 退款异常 | 中 | 拼单失败退款可能失败 | 退款重试 |
| 权限问题 | 中 | 用户可能查看他人订单 | 越权测试 |
| 金额错误 | 高 | 优惠计算可能错误 | 金额计算测试 |

## 4. 建议补充的验收标准

1. 支付回调必须幂等。
2. 订单金额必须可追溯。
3. 库存不足时不能下单。
4. 拼单失败必须退款。
5. 用户只能访问自己的订单。
6. 待支付订单按时关闭。
