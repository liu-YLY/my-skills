# 订单支付模块需求评审（第二次运行）

## 1. 需求理解摘要

1. 用户从购物车进入确认订单页，选择地址和优惠券后提交订单。
2. 订单提交后待支付，支付成功后变为已支付。
3. 待支付订单超时会关闭，用户可以取消。
4. 支持拼单，拼单失败会退款。
5. 支付方式包括微信和支付宝。
6. 用户可以查询自己的订单。

## 3. 风险清单

| 风险 | 等级 | 说明 | 建议验证 |
|---|---|---|---|
| 支付金额被篡改 | 高 | 客户端可能传入错误金额 | 服务端重新计算 |
| 重复下单 | 高 | 用户快速点击可能生成多个订单 | 防重复提交 |
| 库存不足 | 中 | 下单时库存可能变化 | 提交时校验库存 |
| 订单越权 | 中 | 用户可能访问他人订单 | 校验订单归属 |
| 退款失败 | 中 | 拼单失败后退款异常 | 退款重试与告警 |
| 超时未关闭 | 中 | 定时任务可能失败 | 监控订单关闭任务 |

## 4. 建议补充的验收标准

1. 支付金额必须与服务端订单金额一致。
2. 重复提交不能生成多个订单。
3. 库存不足时不能下单。
4. 拼单失败必须退款。
5. 用户只能查看自己的订单。
6. 待支付订单必须按时关闭。
