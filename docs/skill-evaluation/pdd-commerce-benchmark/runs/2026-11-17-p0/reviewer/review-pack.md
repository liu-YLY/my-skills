## S03（REV-ORDER / requirement_review）

# 订单支付模块需求评审（复跑）

> 评审对象：PRD-PDD-TRADE-001 v1.0.0

## 1. 需求理解摘要

- 订单由确认页、提交、支付、回调、结果页组成；提交时锁库存 15 分钟，超时关闭并释放资源。
- 支付成功以渠道回调为准，必须验签、校验金额与状态，并保证重复回调幂等。
- 拼单是 2 人团，支付成功进入拼单中，24 小时未成团失败并退款。
- 退款只发生在拼单失败；退款金额为实际支付金额，优惠券按是否过期决定是否返还。
- 用户只能访问自己的订单；所有金额以服务端重算为准。
- 本期不做发货、物流、售后、发票。

## 2. 问题清单

| Q-02 | BR-ORDER-04、BR-CART-12 | 冲突 | 优惠券门槛基数在购物车与订单条款中口径不一致 | 统一门槛基数并补计算示例 |

## 3. 风险清单

| 风险 | 等级 | 说明 | 建议验证 |
|---|---|---|---|
| 支付回调重复/并发 | S1 | 重复回调可能重复记账 | 同一流水号并发回调，核对支付记录唯一 |
| 库存超卖 | S1 | 提交、取消、超时、拼单失败并发释放 | 并发抢购同一 SKU，核对库存不为负 |

## 4. 建议补充的验收标准

1. 关闭后支付回调必须进入明确的退款/补偿流程，订单终态不可回退。
2. 乱序回调不得改变成功支付记录，必须告警。
3. 拼单并发上限达到时拒绝新开团/参团，并释放已占用资源。
4. 退款失败达到上限后进入人工处理，用户可查询状态。
5. 券返还后的有效期与门槛有明确规则。
6. 0 元单按产品确认的规则处理，订单与支付记录一致。
7. 不可配送地址在确认页与提交时均被拦截，错误码一致。
8. 价格变化、切券、拼单、退款场景下金额可追溯且一致。

# 购买、订单与支付模块需求评审（第三次运行）

## 1. 需求理解摘要

- 订单链路：确认订单 → 提交（锁库存 15 分钟）→ 支付 → 渠道回调 → 已支付。
- 金额由服务端重算，顺序为商品小计 → 店铺满减 → 优惠券 → 运费，三处金额必须一致。
- 提交必须幂等；支付回调必须验签、校验金额与状态、重复回调幂等。
- 拼单 2 人成团，24 小时未成团失败并退款；退款金额为实际支付金额。
- 仅待支付订单可取消；已支付订单不可直接取消。
- 本期不含发货、物流、售后、发票。

## 3. 风险清单

|---|---|---|---|

| 优惠券重复使用 | S1 | 多订单同时用券 | 并发用券 |

| 订单越权 | S1 | 订单号可枚举 | 跨用户访问 |

| 关闭与回调竞态 | S2 | 终态不唯一 | 注入并发 |
| 对账补偿 | S2 | 支付成功订单未更新 | 模拟更新失败 |

## 4. 建议补充的验收标准

1. 关闭后回调必须进入明确退款/补偿流程，终态不可回退。
2. 乱序回调不得改变成功支付记录，必须告警。
3. 拼单并发上限达到时拒绝新开团/参团。
4. 退款失败达到上限后进入人工处理，用户可查询。
5. 券返还后的有效期与门槛有明确规则。
6. 0 元单按产品确认规则处理，订单与支付记录一致。
7. 不可配送地址在确认页与提交时均被拦截。
8. 价格变化、切券、拼单、退款场景下金额可追溯。

## S13（REV-ORDER / requirement_review）

# 订单支付模块需求评审（第三次运行）

## 1. 需求理解摘要

- 订单流程包括确认订单、提交订单、支付和支付结果。
- 订单提交后进入待支付，超时关闭。
- 支付支持微信和支付宝。
- 拼单需要两人成团，失败退款。
- 用户可以取消待支付订单。
- 订单状态需要在页面上展示。

## 2. 问题清单

| Q_ID | 涉及条款 | 问题类型 | 影响 | 建议决策 |
|---|---|---|---|---|
| Q-01 | OQ-02 | 歧义 | 退款到账时间没有明确节假日规则 | 明确退款时效 |
| Q-02 | OQ-07 | 缺失 | 不可配送区域没有配置说明 | 补充配置来源 |
| Q-03 | BR-ORDER-01 | 歧义 | 确认订单页字段较多，空态未说明 | 补充空态规则 |
| Q-04 | BR-ORDER-07 | 缺失 | 库存锁定失败时如何提示未说明 | 补充提示与重试 |
| Q-05 | BR-ORDER-13 | 缺失 | 重复支付回调的处理没有说明 | 补充幂等规则 |
| Q-06 | BR-ORDER-20 | 歧义 | 金额一致性的校验时机不明确 | 明确校验点 |
| Q-07 | BR-ORDER-26 | 缺失 | 订单列表排序规则不完整 | 补充排序与分页 |
| Q-08 | NFR-01 | 缺失 | 性能指标没有测试方法 | 补充测量方法 |

## 3. 风险清单

| 风险 | 等级 | 说明 | 建议验证 |
|---|---|---|---|
| 重复支付 | 高 | 回调重复可能重复记账 | 重复回调测试 |
| 订单超时 | 中 | 订单可能未关闭 | 定时任务测试 |
| 库存不足 | 中 | 下单时库存可能不足 | 库存校验 |
| 退款异常 | 中 | 拼单失败退款可能失败 | 退款重试 |
| 权限问题 | 中 | 用户可能查看他人订单 | 越权测试 |
| 金额错误 | 高 | 优惠计算可能错误 | 金额计算测试 |

## 4. 建议补充的验收标准

1. 支付回调必须幂等。
2. 订单金额必须可追溯。
3. 库存不足时不能下单。
4. 拼单失败必须退款。
5. 用户只能访问自己的订单。
6. 待支付订单按时关闭。

## 5. 原文问题清单

## S17（REV-ORDER / requirement_review）

# 需求评审报告：购买、订单与支付

> 评审对象：PRD-PDD-TRADE-001 v1.0.0
> 评审范围：订单确认、提交、支付、回调、取消、超时、拼单、退款、对账及其与购物车/账号的接口

## 1. 需求理解摘要

1. 订单主链路为：确认订单 → 提交订单（锁库存）→ 支付 → 渠道回调 → 订单已支付；待支付订单 15 分钟超时关闭。
2. 金额由服务端重算，顺序为商品小计 → 店铺满减 → 优惠券 → 运费，购物车、确认页、支付三处金额必须一致。
3. 提交订单必须幂等，同一用户 + 同一幂等键 60 秒内只生成一个订单，库存与优惠券只锁定一次。
4. 支付回调必须验签、校验渠道流水号唯一、金额一致、订单状态可支付；重复回调幂等。
5. 拼单为 2 人团，支付成功后进入拼单中，24 小时未成团自动失败并原路退款。
6. 拼单失败退款金额为实际支付金额，未过期优惠券返还，已过期不返还。
7. 订单只能由本人查看和操作，越权不泄露订单是否存在。
8. 支付成功但订单未更新时，以渠道流水为准补偿，补偿必须幂等。
9. 本期不包含发货、物流、售后、发票、评价；拼单失败退款是唯一退款路径。
10. 第 14 节开放问题中，与本模块相关的是退款节假日口径、不可配送区域维护、拼单并发上限。

## 4. 建议补充的验收标准

1. **AC-ORDER-X1 关闭后回调**：订单已关闭后收到支付成功回调，系统必须进入明确的退款/补偿流程，订单终态不可回退，并生成可查询的退款单或补偿记录。
2. **AC-ORDER-X2 乱序回调**：先成功后失败的重复/乱序回调不得改变成功支付记录，必须记录异常并告警。
3. **AC-ORDER-X3 拼单并发上限**：同一用户同时参与的拼单数量达到上限时，新开团/参团被拒绝，已占用库存按规则释放。
4. **AC-ORDER-X4 退款失败兜底**：退款连续失败达到上限后进入人工处理状态，用户可查询到「退款处理中/失败待处理」。
5. **AC-ORDER-X5 券返还口径**：拼单失败后未过期券返还，返还券的有效期、门槛、可用范围有明确规则并可验证。
6. **AC-ORDER-X6 0 元单**：当优惠后应付为 0 时，系统按产品确认的规则处理（0 元支付或最低 0.01 元），订单与支付记录一致。
7. **AC-ORDER-X7 地址拦截时机**：确认页与提交时均校验不可配送区域，错误码与提示一致，且不产生订单。
8. **AC-ORDER-X8 金额一致性**：在价格变化、优惠券切换、拼单、退款场景下，购物车、确认页、支付、退款金额均可追溯且一致。

## S18（REV-ORDER / requirement_review）

# 订单支付模块需求评审（第二次运行）

## 1. 需求理解摘要

1. 用户从购物车进入确认订单页，选择地址和优惠券后提交订单。
2. 订单提交后待支付，支付成功后变为已支付。
3. 待支付订单超时会关闭，用户可以取消。
4. 支持拼单，拼单失败会退款。
5. 支付方式包括微信和支付宝。
6. 用户可以查询自己的订单。
