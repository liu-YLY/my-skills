## 增量评审执行说明

**结论**：当前无法直接执行增量评审。增量评审子模式依赖 git diff 定位「本次变更的用例」；用例文件不在 git 仓库中，缺少变更集判定依据，R1 无法确定评审范围。

**判定依据**（review-mode.md / review-reference.md「增量评审子模式」）：
- 增量评审触发条件：用户指定「增量评审」时，仅解析 git diff 中变更的用例。
- 失败模式：用例格式不规范无法解析 → 列出已识别字段，提示补充后重新评审；无需求文档 → 仅检查内部一致性，标注「溯源维度降级」。

**需要你提供（任一即可）**：
1. 用例文件本身（Markdown 表格 / `### TC-xxx` 块、CSV、JSON；Excel 请转 CSV 或粘贴），并告知本次变更范围（新增/修改的用例 ID 或模块）。
2. 或直接粘贴变更用例内容 + 需求文档/测试点基线。

**收到输入后的执行路径**：
- R1：解析用例结构（ID / 标题 / 优先级 / 类型 / 步骤 / 预期结果 / 前置条件），按你指定的变更集圈定评审范围；无需求文档则标注「溯源维度降级」。
- R2：执行 10 维度评审（覆盖度、优先级合理性、字段规范、可执行性、冗余、溯源、可维护性、可自动化、测试数据依赖、语义一致性）。
- CHECKPOINT：输出意见表 + 改进建议清单 + 评审度量报告；未经授权不修订用例。
- 第 10 维度：优先抽取 SemanticFacts 做前置条件矛盾 / 同输入异预期 / 依赖闭环检测；MCP 不可用时按独立模式执行并标注「⚠ 独立模式（语义一致性未校验）」。

**若文件实际在别的目录/仓库**：请告知路径，我可先尝试读取；仍非 git 管理则按「全量 + 指定范围」处理。

**报告文件化**：增量评审用例 ≥20 条或评级 C/D 时，按 `docs/review-reports/{YYYYMMDD}-{module}-incremental.md` 输出。
