# 用例评审方案与抽样策略（120 条 · CSV）

## 一、模式判定

- 触发：输入为已有用例 + 「评审」→ **评审模式**，不走四阶段生成。
- 规模：120 条 > 100 → 叠加 large-scale-review，只决定「评哪些、分几批」，不改变单条判定标准。
- 输入形态：仅表头 + 3 条示例行，其余 117 行未随附 → 本轮交付**方案与抽样设计**，真实 R2/R3 待补全后执行。
- MCP：⚠ **独立模式（未校验）**，R2/R3 由 AI 规则推理；第 10 维度自行抽取 SemanticFacts 执行 3 类冲突规则，标注「语义一致性未校验」。

## 二、R1 解析规则（CSV 列 → 用例字段）

| CSV 列 | 映射字段 | 解析约定 |
|---|---|---|
| 用例ID | case_id | 按 `TC_{模块}_{功能}_{序号}` 校验规范性与唯一性 |
| 模块 | module | 分组维度，用于分层抽样与报告文件命名 |
| 标题 | title | 校验「对象+条件+预期」可定位性（长标题仅提示） |
| 前置条件 | preconditions | 空值标「无前置」；含数据依赖记入测试数据维度 |
| 步骤 | steps | 以 `;` 拆为多步，逐条编号 |
| 预期结果 | expected_results | 以 `;` 拆分；与步骤顺序对齐，多余/缺失记候选线索 |
| 优先级 | priority | 校验 P0–P3 取值合法 |

- 缺失列处理：无 `test_point_id` → **溯源维度降级**，仅检查用例内部一致性；无 `checkpoints` → 按顺序推断预期归属并标注。
- 格式异常：某行列数不符 → 列入已识别字段，提示补充；仅评审可解析部分并标「格式不规范，评审不完整」。

示例行解析结果（仅演示，候选不计分）：
- TC_LOGIN_001：预期「跳转首页」无具体路径/位置 → JUDGEABLE_RESULT 候选。
- TC_LOGIN_002：预期「提示错误」无具体文案 → 同上候选。
- TC_ORDER_001：预期「优惠金额正确」无具体数值 → 同上候选；前置为空。

## 三、抽样策略

**分层轴**：模块（登录/订单/支付/个人中心）× 优先级（P0–P3）× 类型（正向/反向/边界/权限）。

1. **强制全量层**：全部 P0 + 各模块 Happy Path/主流程，逐条评审，不入抽样。
2. **抽样层**：每模块每优先级随机抽 ≥30% 且 ≥3 条；边界值、权限差异、异常路径加权上调。
3. **资金加权**：支付模块涉资金，P0/P1 全量，P2/P3 抽样比例上浮至 ≥50%。
4. **分批**：每批 ≤50 条，建议 3 批（登录+个人中心 / 订单 / 支付）；单批耗时超限再拆。
5. **去重前置**：同标题、相同前三步仅列候选线索，核实业务等价性后才确认冗余。
6. **语义一致性**：按模块分批抽 facts，每批 ≤50；成本过高则分层抽样并标「语义一致性抽样检测」。

## 四、R2 十维度口径（本 CSV 适用）

| 维度 | 判定要点 | 本批处理 |
|---|---|---|
| 覆盖度 | 仅对需求明确 required_scenarios 查缺失 | 无需求原文 → 记未评估，不从标题猜 |
| 优先级合理性 | 分布只描述，核对业务风险依据 | 全 P0 或矛盾无解释才报 |
| 字段规范 | 必填缺失/检查点越界 P0；可读性 P2 | 标题长度仅提示 |
| 可执行性 | 占位操作 P0；模糊结论 P1 | 不按步骤数扣分 |
| 冗余 | 同目标同条件 | 先 candidate 后确认 |
| 溯源 | 有基线才评 | **降级：未评审（缺需求/编号）** |
| 可维护性 | 未声明跨用例依赖、绝对坐标 | P2 提示 |
| 可自动化 | 模糊断言/缺造数方案 | P2，人工用例不降级 |
| 测试数据依赖 | 生产/三方数据无替代 | 提示核实，不强制 mock |
| 语义一致性 | 单用例同 subject/state 既肯定又否定 P0；依赖闭环 P1 | 独立模式自抽 facts |

输出分 `confirmed` 与 `candidate`，候选项不计入问题密度与通过率。

## 五、度量与交付

- 同时展示 `assessed_dimensions` 与 `not_assessed`；结构 A 级不代表需求全量验证。
- 评级：已确认 P0 → 整体 D；否则 A（≥95% 且密度<0.5）/ B（≥80%）/ C（≥60%）/ D（<60%）。
- **文件化触发成立**（≥20 条）：输出 `docs/review-reports/{YYYYMMDD}-{module}-full.md`；跨 4 模块建议按模块拆 4 份或用主模块命名。
- 交付物：意见表 + 改进建议清单 + 度量报告；未授权修订时仅交付意见。

## 六、下一步所需输入

1. 完整 120 行 CSV（或文件路径），Excel 请先转 CSV/Markdown 或粘贴。
2. 是否有需求文档/测试点基线（决定溯源与覆盖度能否评估）。
3. 是否授权修订闭环（V1–V4）。

补齐后即可按上述批次执行 R2/R3 并出报告。
