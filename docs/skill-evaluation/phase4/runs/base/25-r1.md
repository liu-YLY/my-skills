## 3. 三步法复核（逐条判定，不通过者降级或裁剪）

对每条 P0 按以下顺序复核，任一环节不成立即降级为 P1/P2 或移出本次范围：

1. **业务影响**：失败是否导致核心流程不可用、资金/数据损失、关键安全边界失效？支付模块默认高危项：金额精度、重复支付、部分退款、支付状态流转、超时/结果未知、对账不一致、越权操作。
2. **发生可能性与回归必要性**：结合使用频率、历史缺陷、替代路径、本次变更点判断；仅「理论存在」而无触发路径的场景降级。
3. **定级**：保留 P0 须写明依据（如「重复支付导致资金损失，无替代路径」）；依据不足者按实际影响下调。

**判定口径**：支付涉及资金，P0 偏高通常有业务合理性；但「涉及资金」不能自动推导为 P0，须逐条给出具体失败后果。

## 4. 处置

- 保留：复核后仍满足第 3 节第 1 条阻断风险的 P0 用例。
- 降级：仅有资金模块标签、无具体损失路径的 P0 → 降 P1。
- 裁剪：服务故障类（断网/5xx/超时降级）默认不写，除非需求明确要求容错。
- **禁止**：为把占比压到某个目标值而批量降级或删除用例。
