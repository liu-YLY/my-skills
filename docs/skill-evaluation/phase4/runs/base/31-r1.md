# 登录改版用例评审方案

## 一、会议目标

对齐登录改版测试范围与验收口径，向产品/UI/前端/后端确认：需求覆盖完整、用例可执行、无阻断级缺陷遗留。产出一份经干系人确认的评审意见表与用例修订清单。

## 二、参会角色与关注点映射

| 角色 | 关注点 | 评审材料侧重 |
|---|---|---|
| 产品 | 业务流程、需求场景是否覆盖、验收标准 | 需求-用例覆盖矩阵、Happy Path 与异常路径 |
| UI | 视觉还原、交互状态、文案 | UI 用例、多端/多状态渲染清单 |
| 前端 | 表单校验、交互逻辑、兼容性 | 字段校验用例、错误提示、断点/弱网 |
| 后端 | 接口契约、鉴权、安全与并发 | 安全用例、权限差异、幂等/重试语义 |

## 三、测试思路

**分层覆盖**（自下而上）：

1. **接口/数据层**：登录接口参数校验、鉴权 token 签发与过期、密码错误次数限制、账号状态（未激活/锁定/注销）。
2. **业务功能层**：账号密码登录、验证码/短信登录、第三方授权登录、记住登录、自动续期、退出登录。
3. **UI/交互层**：输入框状态、错误提示位置与文案、按钮置灰/加载态、密码明文切换、键盘适配。
4. **安全与合规层**：越权、SQL/注入、暴力破解防护、敏感信息脱敏、日志审计。
5. **非功能层**：并发登录、弱网/超时、多端兼容、可观测性（埋点/告警）。

**优先级策略**：核心登录链路与安全边界 P0（准入）；高频异常与权限 P1；边界与低风险 P2/P3。

## 四、需求覆盖度汇报框架

以「需求条目 → 测试点 → 用例」三级映射汇报，逐项标注状态：

| 需求编号 | 需求条目 | 测试点数 | 用例数 | 覆盖状态 | 备注 |
|---|---|---|---|---|---|
| R-01 | 账号密码登录 | 8 | 8 | ✅ 全覆盖 | |
| R-02 | 验证码登录 | 6 | 6 | ✅ 全覆盖 | |
| R-03 | 第三方授权登录 | 5 | 5 | ✅ 全覆盖 | |
| R-04 | 错误次数锁定 | 4 | 4 | ✅ 全覆盖 | 边界含锁定/解锁 |
| R-05 | 记住登录/续期 | 3 | 3 | ✅ 全覆盖 | |
| R-06 | 退出登录 | 3 | 2 | ⚠️ 部分 | 多端互踢未覆盖 |
| R-07 | UI 状态与文案 | 7 | 7 | ✅ 全覆盖 | 需设计稿比对 |
| R-08 | 安全与鉴权 | 6 | 6 | ✅ 全覆盖 | |

覆盖度结论 = 已覆盖条目 / 需求总条目；对未覆盖项在「裁剪说明」写明理由（低风险/本次不改/环境限制），无理由的列入缺口。

## 五、评审维度（10 维度干系人视角）

覆盖度、优先级合理性、字段规范、可执行性、冗余、溯源、可维护性、可自动化、测试数据依赖、语义一致性。重点向干系人汇报：**覆盖度、优先级合理性、可执行性、语义一致性**；其余维度作为内部质量项。

## 六、议程安排（建议 90 分钟）

1. 需求与测试范围对齐（10 min，产品）
2. 测试思路与分层策略说明（15 min，QA）
3. 需求覆盖度逐项过审（25 min，全员）
4. 安全/兼容性专项确认（15 min，后端+前端）
5. 用例问题确认与修订分工（20 min，全员）
6. 结论与后续排期（5 min，产品）

## 七、输出物

- 评审意见表（按用例 ID + 字段 + 问题 + 依据）
- 需求覆盖度报告（含未覆盖清单与裁剪理由）
- 用例修订清单（P0 必修 / P1 建议）
- 会议结论与行动项（含责任人与时间）

## 八、待会前确认项

- 登录改版 PRD 与 UI 设计稿是否定稿
- 第三方登录渠道清单与沙箱账号
- 错误次数锁定阈值与解锁策略
- 多端互踢是否为本次范围
- 性能/并发指标是否已给出

> 说明：本方案基于 `test-case-engineer` 评审模式与 review-plan 规范编写；实际覆盖度数据需以最终用例集与 PRD 填充后生成。
