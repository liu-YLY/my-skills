## R3 改进建议清单

1. **补 ID**：按 `TC_{模块}_{功能}_{三位序号}` 命名；模块/功能缩写从已有用例提取，无先例时统一用 `LOGIN`，如 `TC_LOGIN_LOGIN_001`，避免后续编号跳跃。
2. **补步骤**：写明具体对象与输入值，例如「在『用户名』输入框输入已注册手机号 138xxxx」「在『密码』输入框输入正确密码」「点击『登录』按钮」。禁止「填写相关信息」类占位话术。
3. **补可判定预期**：首词给位置，含具体状态，例如「页面跳转至 `/home`，右上角显示该用户昵称」，避免「登录成功」。
4. **补优先级与依据**：主流程建议 P0（核心流程阻断风险），并写明判断理由。
5. **补前置条件**：写明测试账号、密码来源与环境，消除跨用例依赖。
6. **补场景**：确认需求后按需补密码错误、空值校验、账号锁定等反向/边界点；若本次不覆盖，须在裁剪说明写明理由。
