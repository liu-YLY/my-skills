## 修订后用例

### TC_001 订单-支付回调: 支付成功回调后订单状态与支付记录更新

- 优先级：P0
- 类型：functional
- 前置条件：存在待支付订单 `ORDER_20261118001`，金额 100.00 元；支付平台回调地址已配置。
- 步骤：
  1. 支付平台向订单系统发送支付成功回调：订单号 `ORDER_20261118001`、支付流水 `PAY_1001`、金额 100.00 元、状态 `SUCCESS`。
  2. 按订单号查询订单详情。
  3. 查询该订单的支付记录列表。
- 预期结果：
  1. 回调接口返回 HTTP 200，响应体 `code=0`、`message=success`。
  2. 订单状态由「待支付」变为「已支付」，支付时间非空且与回调时间误差在 1 秒内。
  3. 支付记录新增 1 条：流水号 `PAY_1001`、金额 100.00 元、状态「支付成功」；记录总条数为 1。

### TC_002 订单-优惠券上限: 优惠金额触及单笔上限时按上限计算

- 优先级：P1
- 类型：functional
- 前置条件：优惠券 `C1` 规则为「满 100 减 30，单笔订单最高优惠 20 元」；订单 `ORDER_20261118002` 商品金额 200.00 元。
- 步骤：
  1. 下单时使用优惠券 `C1`。
  2. 查看订单优惠金额与实付金额。
- 预期结果：
  1. 订单优惠金额为 20.00 元（计算依据：满 100 减 30 应付 30.00 元，超过单笔上限 20.00 元，按上限 20.00 元计）。
  2. 实付金额为 180.00 元（200.00 − 20.00）。
  3. 优惠券 `C1` 状态变为「已使用」，使用订单号为 `ORDER_20261118002`。

### TC_003 订单-越权访问: 访问他人订单返回无权限且不泄露订单信息

- 优先级：P1
- 类型：security
- 前置条件：用户 `U1` 已登录并持有有效 token；用户 `U2` 名下存在订单 `ORDER_20261118003`（状态「已支付」）。
- 步骤：
  1. 使用 `U1` 的 token 请求订单详情接口 `/api/orders/ORDER_20261118003`。
  2. 查看响应状态码、响应体；若为页面访问则查看页面提示。
- 预期结果：
  1. 接口返回 HTTP 403，响应体 `code=40301`、`message=无权限访问该订单`。
  2. 响应体不包含订单号、金额、收货地址等任何订单字段。
  3. 前端页面展示「您无权访问该订单」，不展示订单详情。
