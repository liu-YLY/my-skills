## 增量评审：前置条件检查

### 结论
当前无法直接执行增量评审，存在 2 个阻塞项：用例正文未提供、用例文件不在 git 仓库，git diff 无法用于定位变更范围。

### 阻塞项

| # | 阻塞项 | 原因 | 影响 |
|---|--------|------|------|
| 1 | 无用例内容 | 输入中无用例正文 | R1 无法解析 ID/标题/优先级/步骤/预期 |
| 2 | 不在 git 仓库 | 增量评审以 git diff 变更为输入 | 变更范围无法定位，退化为全量 |

### 不依赖 git 的「增量」定义方式（任选其一）

1. **用例 ID 清单**：给出新增/修改的 TC 编号，其余视为未变更，仅评这些。
2. **双版本对比**：提供基线版本与当前版本，按 `TC_{模块}_{功能}_{序号}` 做集合 diff，识别新增/修改。
3. **粘贴变更块**：直接粘贴本次新增/修改的用例，并标注「新增」或「修改前→修改后」。
4. **本地建基线**：文件在本地但未被跟踪时，可 `git init` + 首次 commit 作为基线（属写操作，需你授权），之后正常 diff。
