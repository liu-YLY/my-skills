# 用例评审方案与抽样策略（120 条 · CSV）

## 0. 前置说明
- 实际仅提供表头 + 3 行样本，完整 120 行未给出 → 本交付为**方案与抽样策略**，并对 3 条样本做解析初评；全量 10 维度结论需补齐 CSV 后执行。
- 评审主体：AI 规则核对，`⚠ 独立模式（未校验）`（无 MCP）。
- 未提供需求文档 → **溯源维度降级**，仅检查用例内部一致性。
- 120 条 > 100 → 叠加规模化评审，分 4 批、每批 ≤30 条。

## 1. R1 CSV 列解析
| CSV 列 | 解析字段 | 说明 |
|---|---|---|
| 用例ID | case_id | 需符合 `TC_{模块}_{功能}_{三位序号}`；模块段 login/order/payment/profile |
| 模块 | module | 登录/订单/支付/个人中心 |
| 标题 | title | 需可定位对象 + 条件 + 预期 |
| 前置条件 | preconditions | 空值须确认是「无前置」还是漏填 |
| 步骤 | steps | `;` 分隔，按序执行 |
| 预期结果 | expected_results | `;` 分隔，逐条对应步骤 |
| 优先级 | priority | P0–P3，非法值报错 |

解析风险：步骤/预期内含 `;`，CSV 字段必须引号包裹，否则列错位；解析前先校验列数 = 7。

## 2. 抽样策略（L1–L5）
| 层级 | 范围 | 抽样方式 | 预计量 |
|---|---|---|---|
| L1 | P0 | 全量 | ~15–20 |
| L2 | 各模块 Happy Path 正向主流程 | 每模块 ≥2 | 8 |
| L3 | 反向/边界/异常 | 每模块抽 30% | ~12 |
| L4 | 权限/联动/资金/并发 | 全评或抽 50% | ~8 |
| L5 | P3 低风险 | 抽 10% | ~3 |

- 实评约 45 条（覆盖率 ~37.5%）；未抽中写入**未评审清单**并声明风险，不计入通过率分母。
- 批次：登录 → 订单 → 支付 → 个人中心，每批 ≤30 条。
- 每批必含：Happy Path ≥1、反向 ≥1、边界 ≥1、权限 ≥1（如适用）。
- 支付涉资金 → L4 提级，P0 全量。

## 3. R2 10 维度（判定口径）
覆盖度、优先级合理性、字段规范、可执行性、冗余、溯源（降级）、可维护性、可自动化、测试数据依赖、语义一致性。每条意见引用 `用例ID + 字段 + 原文`；`candidate` 与 `confirmed` 分列，候选不计入问题密度与通过率。
