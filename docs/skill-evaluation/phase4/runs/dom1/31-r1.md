# 登录改版用例评审方案

**适用**：登录改版用例评审会 · 参会：产品 / UI / 前端 / 后端 / QA
**目标**：① 需求覆盖无遗漏；② 测试策略与优先级达成共识；③ 用例可执行、可自动化；④ 遗留风险有结论、有责任人。
**对象**：登录改版用例集（功能 `TC_login_*`，性能 `TC_login_PERF_*`，安全 `TC_login_SEC_*`）。

## 一、测试思路

### 1. 分层策略与责任方
| 层级 | 关注点 | 主责 |
|---|---|---|
| 功能 | 账密登录、短信/邮箱验证码、第三方登录绑定解绑、记住我、自动登录、登出、多端互斥、找回密码、锁定解锁 | 产品+后端 |
| UI | 布局还原、暗黑模式、错误提示位置与措辞、加载/禁用态、可访问性 | UI+前端 |
| 接口 | 字段契约、状态码、幂等与防重放、限流、Token 签发与刷新 | 后端 |
| 安全 | 暴力破解、注入、会话固定、越权、敏感信息脱敏 | 后端+安全 |
| 兼容 | 主流浏览器/机型/分辨率/系统版本 | 前端 |
| 性能 | 登录时延、并发登录、接口吞吐 | 后端 |

### 2. 优先级判定（三步法）
按「失败业务影响 → 发生可能性/频率/历史缺陷/替代路径 → 回归必要性」定级，不从类型机械推导。登录主流程、鉴权会话、数据/权限边界为 P0 候选；提示样式、低风险分支为 P2/P3。

### 3. 覆盖基线
- Happy Path：每种登录方式至少 1 条完整正向。
- 字段校验：仅覆盖本次改动字段，有阈值取一组三点边界。
- 权限差异：需求明确的角色/端形态。
- 辅助操作：取消/返回/刷新冒烟。
- 非焦点内容只留 1 条冒烟；断网/超时/5xx/降级默认不写，除非需求明确要求容错。

### 4. 回归范围
本次属大功能迭代 → 登录模块 P0/P1 全量 + 上下游受影响 P0（注册、找回密码、个人中心鉴权）。

## 二、需求覆盖度（核心）

会前由 QA 填初稿，会上逐行确认「已覆盖 / 缺口 / 裁剪」。

| 需求编号 | 需求要点 | 测试点 | 用例数 | 优先级 | 状态 | 说明 |
|---|---|---|---|---|---|---|
| REQ-01 | 账密登录成功/失败 | TP-01~04 | 4 | P0 | ✅ | |
| REQ-02 | 验证码下发/校验/重发/过期 | TP-05~09 | 5 | P0 | ✅ | |
| REQ-03 | 第三方登录绑定/解绑 | TP-10~12 | 3 | P1 | ⚠️待补 | 缺绑定冲突场景 |
| … | | | | | | |

**统计口径**：按模块输出 `需求点数 / 测试点数 / 用例数 / 覆盖率 / 未覆盖项`；未覆盖必须在「裁剪说明」写明理由，否则计为缺口。
**双向核对**：正向查需求点是否有用例；反向查用例是否越界（需求无依据却展开多步），避免为凑数造用例。
**争议裁决**：现场无法达成一致的项记入遗留清单，由产品拍板并回填需求。

## 三、面向四类干系人的评审维度

| 干系人 | 关注问题 | 判定依据 |
|---|---|---|
| 产品 | 业务规则完整性、边界与异常、文案一致性 | 覆盖度、溯源、语义一致性 |
| UI | 视觉还原、交互状态、提示位置/措辞、暗黑与适配 | 字段规范/可读性、UI 用例 |
| 前端 | 字段校验、状态流转、异常兜底、多端兼容 | 可执行性、可维护性、可自动化 |
| 后端 | 接口契约、鉴权、幂等并发、限流、数据一致性 | 语义一致性、可自动化、测试数据依赖 |

统一按 10 维度判定：覆盖度、优先级合理性、字段规范、可执行性、冗余、溯源、可维护性、可自动化、测试数据依赖、语义一致性。问题分 P0–P3，逐条引用「用例 ID + 字段 + 原文证据」。

## 四、会议议程（90 分钟）

| 时段 | 内容 | 主导 |
|---|---|---|
| 0–10' | 改版背景、范围与目标 | 产品 |
| 10–35' | 测试思路、分层与优先级口径确认 | QA |
| 35–65' | 需求覆盖度逐项过审、缺口裁决 | 全员 |
| 65–85' | 分歧用例、高风险项与优先级校准 | 全员 |
| 85–90' | 行动项、责任人、复审时间 | QA |

## 五、输出物与跟进

- 评审意见表（用例 ID / 字段 / 问题 / 判定依据 / 修改建议 / 级别）
- 改进建议清单（责任人 + 截止时间）
- 度量报告（通过率、问题密度、维度与等级分布、残留 P0）
- 缺口与裁剪说明归档；**残留 P0 未闭环不得进入下一阶段**

**会前准备**：QA 提前发出用例集与覆盖矩阵初稿；产品带需求原文；前后端确认接口契约版本与造数方案。

> 本方案为评审组织框架，实际质量结论以 R2 十维度判定与度量报告为准。
