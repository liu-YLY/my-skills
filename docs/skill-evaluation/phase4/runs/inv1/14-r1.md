## 二、修订后用例

### TC_001 订单-支付回调

- 优先级：P0
- 类型：functional
- 前置条件：订单 `O20261117001` 已创建，`order_status=pending`；支付渠道回调接口可用
- 测试步骤：
  1. 构造回调报文：`order_id=O20261117001`、`amount=100.00`、`trade_no=PAY20261117001`、`status=SUCCESS`
  2. 向 `/api/order/pay/callback` 发送该报文
  3. 查询订单表与支付流水表
- 预期结果：
  1. 接口返回 HTTP 200，`body.code=0`
  2. 订单表 `order_status` 由 `pending` 变为 `paid`，`paid_amount=100.00`
  3. 支付流水表新增 1 条：`trade_no=PAY20261117001`、`status=paid`、`amount=100.00`；重复回调不新增记录
- 需求追溯：PRD 支付回调

### TC_002 订单-优惠券上限

- 优先级：P1
- 类型：functional
- 前置条件：优惠券 `C1` 规则为「按订单金额 10% 抵扣，单笔上限 20.00 元」；用户 `U1` 持有 `C1`；订单金额 300.00 元
- 测试步骤：
  1. 下单时选择优惠券 `C1`
  2. 查看订单金额明细与应付金额
- 预期结果：
  1. 优惠金额 = `min(300.00 × 10%, 20.00)` = **20.00 元**（触发上限）
  2. 订单应付金额 = `300.00 - 20.00` = **280.00 元**
  3. 明细行显示「优惠券抵扣 -20.00」，且不超过上限 20.00 元
- 需求追溯：PRD 优惠券

### TC_003 订单-越权访问

- 优先级：P1
- 类型：security
- 前置条件：用户 `A` 已登录；用户 `B` 的订单 `O-B-001` 存在
- 测试步骤：
  1. 用户 `A` 调用 `GET /api/orders/O-B-001`
  2. 查看接口响应与页面提示
- 预期结果：
  1. 接口返回 HTTP 403，`body.message="无权限访问该订单"`
  2. 页面显示「无权限访问该订单」
  3. 响应不包含 `O-B-001` 的 `order_id`、金额、收货地址等订单字段
- 需求追溯：PRD 权限/越权
