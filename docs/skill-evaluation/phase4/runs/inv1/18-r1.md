## 增量评审前置说明

**当前无法启动增量评审。** 增量评审子模式依赖 git diff 定位「本次变更的用例」（新增/修改），用例文件不在 git 仓库中时，无法自动圈定增量范围，R1 解析阶段即被阻断。

### 三种可选处理方式

| 方式 | 操作 | 适用场景 |
|------|------|----------|
| A. 纳入版本控制 | 将用例文件提交到仓库，基于基线 commit 生成 diff | 希望保留自动增量识别 |
| B. 直接粘贴用例 | 提供用例全文 + 变更基线（旧版本或变更说明），由我按差异人工圈定增量 | 文件确实不入库，但能提供对照 |
| C. 降级为全量评审 | 不区分增量，对整批用例走 R2 十维度评审 | 只关心整体质量，不区分新旧 |

### 进入评审所需输入

请补充以下任一组合：

1. **用例文件**：Markdown / CSV / JSON（或直接粘贴）
2. **增量范围**：变更用例 ID 清单，或基线版本（用于比对）
3. **需求文档**（可选）：有则做溯源维度，无则标注「溯源维度降级，仅检查用例内部一致性」
4. **评审模式标记**：是否启用 MCP 增强模式；未安装则按独立模式执行

### 评审模式标记说明

- 有需求 → 完整溯源；无需求 → 溯源降级
- 用例 >100 条 → 叠加 large-scale-review 方案
- 仅评审不修订；如需修订请明确授权范围（可只修 P0）

收到上述输入后，我将按 R1 解析 → R2 十维度评审 → R3 输出意见表 + 改进建议 + 度量报告（含通过率、问题密度、评级）执行。请指定采用 A/B/C 哪种方式，并提供用例内容。
