# 评审方案与抽样策略（120 条 · CSV）

**模式**：评审模式 · 规模化（>100 条，叠加 large-scale-review）· 分批评审
**评审主体**：`⚠ 独立模式（未校验）`（MCP 不可用，纯 AI 规则核对）
**溯源状态**：无需求文档 → 溯源维度降级，仅检查用例内部一致性

## 一、R1 输入解析（CSV 列映射）

| CSV 列 | 用例字段 | 备注 |
|--------|----------|------|
| 用例ID | id | 格式校验 `TC_{模块}_{功能}_{三位序号}` |
| 模块 | module | 用于提取报告名与分批 |
| 标题 | title | 关键词关联功能 |
| 前置条件 | preconditions | 空值需区分「可空」与「漏填」 |
| 步骤 | steps | 分号 `;` 拆分为有序步骤 |
| 预期结果 | expected_results | 逐条对应步骤 |
| 优先级 | priority | P0–P3 |

**缺失字段处理**：无「类型」列 → 默认 `functional`；无「追溯/test_point_id」列 → 溯源仅做编号存在性核对，不反推需求。

**分组统计**：登录 / 订单 / 支付 / 个人中心 四模块，按模块 + 优先级二维计数，作为抽样分层依据（实际分布需读全 120 行后回填）。

## 二、规模化评审组织（L1–L5）

| 层级 | 范围 | 动作 |
|------|------|------|
| L1 全量结构扫描 | 120 条全部 | 脚本级校验 ID/字段/必填/可读性 |
| L2 强制全量 | P0 + 主流程 + 含「提交/支付/删除/权限」行为 | 逐条 10 维度 |
| L3 分层抽样 | 非焦点模块与 P2/P3 | 抽样评审 |
| L4 语义一致性 | 全量抽 SemanticFacts，按模块分批 ≤50 条 | 3 类冲突检测 |
| L5 汇总 | — | 意见表 + 建议清单 + 度量报告 |

分批交付：每批 ≤50 条，批内先出意见再进下一批；任何批次失败按 Fallback 记录原因。

## 三、抽样策略

- **分层维度**：模块 × 优先级 × 场景类型（正向/反向/边界/权限/异常）。
- **样本量**：P0 全量；每模块抽样 ≥40%（总体约 50 条），且每模块不少于 15 条；若某模块 <10 条则全量。
- **必选样本（每模块至少各 1）**：Happy Path 完整正向流程；密码/金额/状态等反向异常；权限差异；数值边界（有阈值取三点）；空值/超长输入。
- **不抽**：重复标题、同前三步同构用例只抽 1 条代表，其余列入候选线索。
- **可复现**：固定随机种子，输出样本 ID 清单随报告归档。
- **语义抽样**：按模块分批，每批 ≤50 条；facts 数 ≠ 用例数时重试一次，仍不等则跳过该维度并标注。

## 四、10 维度判定口径

| 维度 | 判定要点 | 等级 |
|------|----------|------|
| 覆盖度 | 仅对明确基线判缺口；不从标题猜 | P0–P1 |
| 优先级合理性 | 业务影响推导，分布只描述 | P1 |
| 字段规范 | 必填缺失、检查点越界 → P0 | P0/P2 |
| 可执行性 | 占位操作 → P0；模糊结论 → P1 | P0/P1 |
| 冗余 | 同标题/同前三步先列 candidate | P2 |
| 溯源 | 基线缺失，未评估 | — |
| 可维护性 | 未声明跨用例依赖、绝对坐标 | P2 |
| 可自动化 | 缺造数方案/断言模糊 | P2 |
| 测试数据依赖 | 生产/三方数据无替代方案 | P2 |
| 语义一致性 | 同 subject/state 自相矛盾 → P0；同输入异预期先 candidate；依赖闭环 → P1 | P0/P1 |

## 五、度量与输出

- **统计**：确认问题数 / candidate 数分开；candidate 不计入问题密度与通过率。
- **通过率**：`pass_rate = 1 - 确认问题数/已评审用例数`；空集合记 `null`，不评 A。
- **评级**：有确认 P0 → D；否则 A ≥95% 且密度 <0.5，B ≥80%，C ≥60%，D <60%。
- **报告**：`docs/review-reports/{YYYYMMDD}-{module}-batched.md`（多模块用 `multi` 或分模块出多份）。
- **CHECKPOINT**：先交付意见表 + 建议清单 + 度量报告；未授权修订时不改用例。
