# 420 条测试用例评审方案

## 一、评审约束与已知信息

| 项目 | 内容 |
|------|------|
| 用例总量 | 420 条 |
| 模块数 | 8 个 |
| 评审人力 | 3 人 |
| 评审窗口 | 下周（约 5 个工作日） |
| 评审模式 | 规模化评审（>100 条），分层抽样 + 全量清单兜底 |

**假设条件**（请确认）：① 各模块用例数分布不均，按模块规模分档；② 3 名评审人具备业务知识，可按模块认领主审；③ 已有需求文档/测试点基线可供溯源；④ 评审前可执行脚本校验（validate_cases.py）。

---

## 二、评审范围分层（L1–L5）

按风险与回归必要性分层，不搞 420 条平均用力：

| 层级 | 范围 | 评审方式 | 目标量 |
|------|------|----------|--------|
| L1 全量清单 | 8 模块 P0 + 主流程用例 | 脚本校验 + 主审逐条过 | 约 80–100 条 |
| L2 主审深度 | 各模块非 P0 用例 | 主审全读 + 交叉复核抽查 | 约 150–180 条 |
| L3 交叉复核 | 每模块按 20% 抽样 | 非主审人复核，验证判定一致性 | 约 80–100 条 |
| L4 专项复核 | 资金/权限/状态机/并发模块 | 主审 + 产品/开发会审 | 按模块实际 |
| L5 未评审清单 | 低风险 P2/P3 且无基线用例 | 登记未评审原因与风险 | 剩余部分 |

**分批原则**：按模块维度分批，每批聚焦 1–2 个模块，单批评审量控制在 60–80 条，避免单日评审超过 80 条导致判定质量下降。

---

## 三、评审排期（5 个工作日）

| 日期 | 批次 | 内容 | 主审 | 产出 |
|------|------|------|------|------|
| D1 上午 | 预检 | 脚本校验 420 条，生成全量清单（P0/主流程） | 全员 | 校验报告 + 分层清单 |
| D1 下午–D2 | 批次 1 | 模块 A、B 全量评审 | 主审 A/B + 交叉 | 意见表 + 问题清单 |
| D3 | 批次 2 | 模块 C、D、E 全量评审 | 主审 C/D/E + 交叉 | 意见表 + 问题清单 |
| D4 | 批次 3 | 模块 F、G、H 全量评审 + 专项复核 | 全员 | 意见表 + 问题清单 |
| D5 上午 | 汇总 | 合并意见、评级、输出报告 | 全员 | 评审度量报告 |
| D5 下午 | 缓冲 | 遗留问题澄清、修订计划 | 主审 | 修订清单 |

**关键约束**：D1 预检必须完成，脚本 0 error 才进入人工评审；D5 预留缓冲应对评审超时。

---

## 四、人员分工

| 角色 | 职责 | 人数 |
|------|------|------|
| 主审人 | 每模块 1 名主审，负责本模块全量评审、意见填写、修订验证 | 3 人轮转 |
| 交叉复核人 | 复核非本人主审模块的抽样用例，验证判定一致性 | 3 人互审 |
| 评审负责人 | 统筹排期、裁决争议、汇总度量报告、对接产品/开发 | 1 人（可兼任） |

**认领规则**：按模块熟悉度认领，避免一人主审超过 3 个模块；交叉复核人与主审人不得为同一人。

---

## 五、准入与准出标准

**准入**：
- 脚本校验 0 error（格式、必填字段、词表）
- 分层清单已生成，P0/主流程用例已标记
- 需求文档/测试点基线可访问（用于溯源）

**准出**：
- L1 全量清单 100% 评审完成
- 已确认 P0 问题修复率 100%
- 已确认 P1 问题修复率 ≥90%
- 输出评审度量报告（通过率、问题密度、维度分布、残留问题）
- 未评审用例已登记原因与风险，干系人确认接受

---

## 六、单批次评审流程

1. **预读**：主审阅读模块需求与测试点基线（15 分钟）
2. **逐条评审**：按 10 维度（覆盖度、优先级合理性、字段规范、可执行性、冗余、溯源、可维护性、可自动化、测试数据依赖、语义一致性）判定
3. **意见填写**：每条问题引用用例 ID + 字段 + 原文证据，区分 confirmed / candidate
4. **交叉复核**：复核人抽查 20%，标记判定不一致项
5. **批次汇总**：合并意见，标记 P0/P1/P2，输出批次意见表
6. **修订闭环**（如授权）：主审修订 → 复核人复审 → 关闭问题

---

## 七、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 单批评审量过大导致判定质量下降 | 漏评、误判 | 单批 ≤80 条，超时则削减 L3 抽样比例 |
| 评审人业务不熟悉 | 语义判定偏差 | 评审前 30 分钟模块业务培训；争议项提交评审负责人裁决 |
| 需求文档缺失导致溯源降级 | 溯源维度无法评估 | 标注「溯源维度降级」，仅检查内部一致性，登记风险 |
| P0 问题修复时间不足 | 准出标准不达标 | D4 提前识别 P0，D5 优先修复；无法修复的升级干系人 |
| 模块间用例冗余 | 评审重复消耗 | 评审前用标题/步骤相似度预聚类，冗余项合并处理 |

---

## 八、交付物清单

1. 脚本校验报告（D1）
2. 分层评审清单（L1–L5，含 P0 标记）
3. 各批次评审意见表（用例 ID + 字段 + 原文 + 优先级 + 修订建议）
4. 评审度量报告（通过率、问题密度、维度/严重等级分布、残留问题）
5. 未评审用例清单（含原因与风险）
6. 修订闭环记录（修订条数、复审通过率、残留问题数）
