# 优先级分布评审

## 结论

**无法仅凭分布数字判定合理性**。分布本身只作为观察信息，不设固定扣分阈值，优先级必须逐条依据业务风险与回归必要性推导（test-standards.md「三步法」）。

## 观察

| 项 | 值 |
|---|---|
| P0 | 1 条（5%） |
| P1 | 12 条（60%） |
| P2 | 7 条（35%） |
| P3 | 0 条 |

- P0 仅 1 条：若本功能含核心流程，需核实是否为 1 条，是否存在应 P0 却降为 P1 的用例。
- P1 占 60%：可能合理，也可能存在「按类型机械分配」或「同类场景优先级互相矛盾」问题。
- P3=0：需确认是否确无低影响场景，而非漏标。

## 判定依据（J7 PRIORITY_BASIS）

| 检查项 | 判定 | 依据 |
|---|---|---|
| 全部同一优先级且无风险说明 | 不适用（分布分散） | — |
| P0 是否含核心流程/资金/数据/权限边界 | **待核实** | 未提供用例内容 |
| 同类场景优先级是否矛盾 | **待核实** | 未提供用例内容 |
| P1 是否对应高频业务、重要权限、主要异常路径 | **待核实** | 未提供用例内容 |
| P3 缺失是否有理由 | **待核实** | 未提供裁剪说明 |

## 结论性意见

**暂不判 FAIL**。分布未出现「全部 P0」或「机械均匀分配」等明显异常，但 **P0=1 与 P1=60% 的合理性必须结合 20 条用例的具体标题、步骤与业务影响逐条核实**。

## 需补充证据

1. 每条 P0/P1 用例的**失败业务影响**说明（核心流程/资金/数据/权限/用户范围）。
2. 是否存在**同类场景优先级不一致**（如两条同为「登录异常」，一条 P0 一条 P2）。
3. P3=0 的**裁剪说明**（确认无低风险场景，或说明为何不设 P3）。
