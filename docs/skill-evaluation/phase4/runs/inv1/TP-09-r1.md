## 测试点清单（快速模式，未做完整需求理解；未脚本校验：本轮未使用工具）

**需求**：用户修改手机号后，系统在合理时间内生效，并给出友好提示。
**焦点**：修改生效时效、生效后新/旧号状态、友好提示。
**系统类型**：账户/通知（手机号）+ 状态联动（新号生效、旧号失效）。

**裁剪说明汇总**
- 服务故障类（断网、5xx、超时、依赖不可用、短信通道故障）：默认 0 条；需求未要求容错/降级，归平台与运维。
- 边界值膨胀：需求未给出手机号格式、验证码次数/有效期、生效时长等阈值，除格式非法外不取边界；如需阈值先在原文问题清单标缺失。
- 非重点内容：原手机号登录、账户注销、其他资料修改等与本次改动无关，不写；仅保留第 2/9 条低强度验证。
- 产品知识：未找到对应产品知识文件，按通用流程。

**待确认项（影响用例可执行性）**
1. 「合理时间」的具体 SLA 阈值（用于判定生效时效）。
2. 修改手机号的身份校验方式（旧号验证码 / 密码 / 人脸）及是否本次新增。
3. 生效后原手机号是否立即失效、是否保留登录能力。
4. 新号重复、格式校验规则是否为本次改动范围。
5. 友好提示的具体文案与展示位置（决定第 3 条判定标准）。
