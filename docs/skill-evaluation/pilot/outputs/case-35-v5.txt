## 需求理解（压缩）

功能概述：账号本人在「修改昵称」页修改单个昵称字段，保存后新昵称在列表页与详情页同步显示。

需求追溯：

| 条目 | 需求ID/PRD章节/Story | 备注 |
|------|----------------------|------|
| 昵称长度 1–20 字符 | 待补充（需求原文#35） | 需求原文未提供正式 ID |
| 允许中文、英文、数字 | 待补充（需求原文#35） | 同上 |
| 保存后列表与详情页同步显示 | 待补充（需求原文#35） | 同上 |

用户角色：已登录的账号本人。需求仅涉及单一角色，其他角色裁剪。

业务规则：
1. 昵称长度为 1–20 个字符。
2. 昵称允许中文、英文、数字三类字符；其他字符类型不在允许范围内。
3. 保存后列表页与详情页均显示保存后的昵称。

数据规则：
- 昵称写入账号资料，列表页与详情页读取同一昵称字段。
- 列表与详情页同步显示属于同一字段在两个视图的展示一致性，需求原文已判定「无跨模块联动」。

待确认项：
- 长度按字符数还是字节数计，需求未明确 → 待产品确认；本用例集按「1 个汉字计 1 个字符」理解。
- 是否允许首尾空格、保存时是否去除首尾空格，需求未明确 → 待产品确认。
- 超长与非法字符的拦截方式（前端截断 / 提交时拒绝 / 按钮置灰）与提示文案，需求未明确 → 待产品确认；用例以按钮状态与字段值等可观察事实作预期，不预设具体文案。

### TC_PROFILE_NICKNAME_001: 修改昵称 - 输入「测试用户」保存后列表与详情页显示新昵称

- 优先级: P0
- 类型: functional
- 需求追溯: TP-01 / TP-10 / TP-11
- 来源: ai-generated
- 人工审核状态: not-reviewed
- 业务背景: 验证账号本人把昵称改为合法中文值并保存后，列表页与详情页都显示该值

前置条件:
- 账号 A 已登录，处于「修改昵称」页
- 账号 A 原昵称为「旧昵称」

测试步骤:
1. 清空「昵称」输入框
2. 在「昵称」输入框输入 `测试用户`
3. 点击「保存」
4. 打开账号列表页
5. 打开账号 A 的详情页

业务结果:
- 账号列表页中账号 A 的「昵称」列显示 `测试用户`
- 账号 A 详情页的「昵称」字段显示 `测试用户`

后置条件:
- 将账号 A 的昵称复位为「旧昵称」

标签: profile, nickname-edit, data-consistency
