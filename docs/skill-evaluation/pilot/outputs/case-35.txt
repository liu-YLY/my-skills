阶段 1：理解需求

模式：快速模式（单字段纯校验类自动路由，压缩阶段 1/4 说明）。
功能概述：用户修改个人昵称，保存后列表与详情页同步显示新值。
复杂度与预算：单字段纯校验（无跨模块联动、无状态机、无资金属性），用例集预算 ≤8 条；本集 7 条。

需求条目（分母，来源：对话轮次#1 用户请求）：
- R1 昵称长度 1–20 字符
- R2 仅允许中文、英文、数字
- R3 空值不可保存
- R4 保存后列表与详情页同步显示

业务规则：字符数按字符计（1 个汉字计 1 字符）；白名单外字符拒绝保存；保存只改动昵称一个字段。
风险分析：R4 数据一致性为 P0 主路径；长度与白名单校验为 P1；低风险维度按风险裁剪（见阶段 2）。
待确认项 / 原文问题清单：
- 对话轮次#1｜模糊｜「字符」计数口径（按字符还是字节）未明确，用例按 1 汉字 = 1 字符理解。
- 对话轮次#1｜缺失｜保存提示与拒绝提示文案未给出；用例中「已保存」「昵称仅支持中文、英文、数字，长度 1-20」为占位，待 UI 确认，判定以界面值与数据未变为准。
信息来源：对话轮次#1 用户请求原文；未找到对应产品知识文件，按通用流程执行。

### TC_NICKNAME_EDIT_001: 修改昵称 - 输入 2 个中文字符保存后列表与详情页显示新昵称
- 优先级: P0
- 类型: functional
- 需求追溯: R1 / R2 / R4 | TP01 / TP02 / TP06
- 业务背景: 验证中文昵称保存后，列表与详情页读取到同一新值
- 前置条件:
  - 账号 A 已登录，处于「修改昵称」页
  - 账号 A 当前昵称为「旧昵称」
- 测试步骤:
  1. 在「昵称」输入框输入「张三」
  2. 点击「保存」
  3. 打开账号 A 的列表页
  4. 打开账号 A 的详情页
- 关键检查点:
  - 步骤 2 后：页面顶部显示「已保存」
- 业务结果:
  - 列表页账号 A 行显示「张三」
  - 详情页「昵称」字段为「张三」
- 后置条件: 将账号 A 昵称改回「旧昵称」
- 标签: profile, nickname, consistency

等价场景合并与去重：
- TP01（保存生效）与 TP02（两处同步展示）合并到 TC_NICKNAME_EDIT_001 的关键检查点与业务结果，不拆成两条用例。
