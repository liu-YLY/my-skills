## 阶段 1：需求理解

功能概述：账号通过手机号与验证码登录，支持勾选「记住登录」保持 7 天登录态、主动退出登录，并在与常用登录地不同的地点登录成功后收到提醒；验证码连续错误会触发账号锁定。

| R2 验证码错误锁定 | 待补充（需求原文#37 条目 2） | 同上 |
| R3 记住登录 7 天 | 待补充（需求原文#37 条目 3） | 同上 |

| R5 异地登录提醒 | 待补充（需求原文#37 条目 5） | 同上 |

用户角色：已注册账号本人；未注册手机号访问者（仅作为反向场景输入，不单独出用例）。短信网关、消息投递与 IP 归属地为外部依赖，不列入用户角色。

业务规则：
1. 使用手机号 + 验证码完成登录。
2. 验证码错误达到锁定条件后账号进入锁定状态，锁定期内无法登录。
3. 勾选「记住登录」后 7 天内免登录，超过 7 天需重新登录。
4. 退出登录后当前会话失效。
5. 与历史常用登录地不同的地点登录成功后，向账号发送异地登录提醒；常用地登录不发送。

状态规则：
- 初始状态：未登录。
- 状态切换：未登录 → 已登录 → 已退出；已登录并勾选记住 → 7 天内自动登录；验证码错误累积 → 账号锁定。
- 状态保存：登录会话与记住登录凭据持久化 7 天。
- 状态互斥：账号锁定与登录成功互斥；已退出与已登录互斥。
- 非法状态：锁定期内登录成功；退出后仍保持已登录；勾选记住登录并退出后仍自动登录。

配置联动规则：
- 上游配置：锁定阈值（触发次数、锁定时长）、记住登录时长（需求给定 7 天）、异地判定口径、提醒渠道。
- 下游行为：登录态决定登录后页面与「退出登录」入口是否可用；异地登录触发提醒消息投递。
- 配置优先级：需求未给出，待确认。
- 配置冲突：需求未给出，待确认。

默认值规则：
- 「记住登录」默认是否勾选，需求未给出 → 待产品确认。
- 登录页「手机号」「验证码」输入框初始为空（可观察初始态）。

异常规则：
- 验证码错误、验证码为空、账号锁定 → 登录不成功。
- 网络异常、服务端 5xx、消息投递失败：需求未涉及，本次裁剪。

数据规则：
- 手机号与验证码为登录输入；登录会话与记住登录凭据有效期 7 天。
- 异地判定依赖登录来源归属地与账号历史登录地。

业务系统识别：权限系统（登录 / 会话 / Token 过期）+ 通知系统（异地登录提醒的发送与不发送）。按 core.md「业务系统识别」补充角色权限矩阵、越权访问、Token 过期、通知链路（发送 / 不发送 / 重复 / 失败）、用户状态等维度；其中依赖未给出规则的部分列入待确认场景清单。

## 阶段 2：测试点清单

风险与优先级（粗分级）：变更面为登录主链路 5 个功能点；业务影响涉及账号安全与会话有效期；技术复杂度含状态流转、凭据有效期与外部消息投递。综合判定为高风险，P0 集中在登录成功、锁定后拒绝、7 天边界、退出与异地提醒。

- 反向校验：验证码错误、验证码为空、注入输入。
