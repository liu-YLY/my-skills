阶段 1：理解需求

功能概述：创建一条 Webhook 配置。用户选定 Version 与 Trigger，填入 Endpoint URL，点击 Add endpoint 提交。
界面控件：Version 下拉框、Trigger 选择框、Endpoint URL 输入框、Add endpoint 按钮。
业务系统类型：通知订阅类配置（Webhook）。
业务规则（据用户描述推断，标注待确认）：
  - Endpoint URL 为必填项。
  - Endpoint URL 需为 http 或 https 开头的地址。
  - Version 与 Trigger 由选择框取值。
  - Add endpoint 提交后生成一条 Webhook 记录。
风险分析：
  - 高风险字段：Endpoint URL，自由文本输入，涉及必填、格式与注入。
  - 低风险字段：Version、Trigger，枚举选择，取值受控。
  - 提交动作：Add endpoint，需防重复提交。
复杂度判定：常规单功能。单页面、单角色主流程、少量规则约束。用例集预算 ≤15 条。
信息来源：用户描述（对话轮次#1）；本次未加载产品知识文件。
待确认项：
  - 必填校验呈现方式（Add endpoint 置灰 / 提交后内联提示）待产品确认，本集按提交后内联提示设计。
  - Endpoint URL 合法格式细则（是否仅 http 与 https）待产品确认。
  - 相同 Endpoint URL 是否允许重复创建待产品确认，列入待确认场景，不生成可执行用例。
  - Version 与 Trigger 是否存在联动、Trigger 是否多选待产品确认，本集按两者独立选择设计。
  - 提示文案以产品最终文案为准，本集暂用「Endpoint URL is required」与「Wrong URL format!」。

TC_WEBHOOK_ADD_001: Webhook 创建 - Version、Trigger、Endpoint URL 填有效值后 Add endpoint 新增一条记录
优先级：P0
类型：functional
需求追溯：TP-01
来源：ai-generated
人工审核状态：not-reviewed
前置条件：
  已登录为可创建 Webhook 的用户
  已打开创建 Webhook 页面
  Webhook 列表记录数为 0
测试步骤：
  1. 在 Version 下拉框选择 Version 5.0
  2. 在 Trigger 选择框选择 push
  3. 在 Endpoint URL 输入框输入 https://example.com/hooks/orders
  4. 点击 Add endpoint 按钮
  5. 刷新 Webhook 列表
关键检查点：
  步骤 4 后：创建页面关闭
  步骤 5 后：新建记录仍在列表中
业务结果：
  列表记录数由 0 变为 1
  新记录 Version 为 Version 5.0
  新记录 Trigger 为 push
  新记录 Endpoint URL 为 https://example.com/hooks/orders
后置条件：
  删除本次创建的 Webhook
标签：webhooks, creation, happy-path
