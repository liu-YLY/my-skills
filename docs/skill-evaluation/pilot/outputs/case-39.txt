阶段 1：理解需求

模式：默认模式（Webhook 创建，常规单功能）。
功能概述：在 Webhook 创建页通过 Version、Trigger、Endpoint URL 与 Add endpoint 完成创建。
复杂度与预算：常规单功能（单页表单、单角色主流程），用例集预算 ≤15 条；本集按风险裁剪为 9 条。

需求条目（分母，来源：对话轮次#1 用户请求）：
- R1 Version 下拉框可选版本
- R2 Trigger 选择框选择触发事件
- R3 Endpoint URL 输入框填写地址
- R4 Add endpoint 按钮提交创建
- R5 创建结果在列表与详情可查

业务规则：Version、Trigger、Endpoint URL 为必填；Endpoint URL 接受 http / https 地址；三项必填均完成后 Add endpoint 才可点击（必填规则与候选项需求未给出，见待确认项）。
风险分析：R4 创建主链路与 R3 地址校验为 P0 / P1；重复提交与脚本注入为防御性 P1；低风险维度按风险裁剪（见阶段 2）。
待确认项 / 原文问题清单：
- 对话轮次#1｜缺失｜Version / Trigger 的候选项、初始选中项与必填规则未给出；用例以 v2、push 为具体值，按钮可用性按「三项必填均完成才可点击」理解，待 UI 确认。
- 对话轮次#1｜缺失｜URL 格式提示文案与格式错误时按钮是否可点击未给出；用例中「Wrong URL format!」为占位，按输入后即提示理解，待 UI 确认，判定以按钮状态与未创建为准。
- 对话轮次#1｜缺失｜Webhook 名称字段未在控件清单中给出；创建记录以 Endpoint URL 与 Trigger 定位，不编造名称字段。
信息来源：对话轮次#1 用户请求原文；未找到对应产品知识文件，按通用流程执行。
