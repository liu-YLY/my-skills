# 完整 Tier 2/3 铺开报告：42 task × with_skill/no_skill 对照

> 日期：2026-11-02 至 2026-11-03
> 基线：分支 `feat/test-case-eval-pilot`，冻结套件 v5（SHA `9a0520ed…`，54 cases / 219 checks）
> 触发：用户选择「铺开完整 Tier 2/3」，规模定为 42 task × 2 variant × 1 次
> 边界：**方向性观察，不是可发布的整体质量结论**（缺 3 次重复、缺 old 对照、`status=partial`）

## 1. 独立性（结论成立的前提）

| 角色 | 执行者 | 模型 |
|---|---|---|
| runner（生成 84 份产物） | WorkBuddy | DeepSeek（reasoning 配置） |
| judge（盲评 438 条判定） | 用户在 zcode 客户端 | **GLM 5.3 Flash（智谱，与 runner 不同厂商，思考强度最低）** |

judge 与 runner 分属不同厂商，满足方法论「judge 与被测模型不同」的独立性要求。这是整个评测项目**首次在完整规模上满足独立性**（此前 5 次 pilot 均标「未满足严格独立性」）。

## 2. 方法

- 42 条 task（40 条 `test-prompts.json` + 2 条 `business-regressions.json`）各生成 `with_skill` 与 `no_skill` 两份产物，共 84 份。
- `with_skill`：runner 加载 skill 指令；`no_skill`：只读需求原文、禁用 skill。
- judge（GLM 5.3 Flash）逐份逐条判定，附证据行号，盲评不暴露 variant。
- 汇总：`skill-evals.py --results runs.jsonl --expected-runs 1 --variants with_skill no_skill`。

## 3. 结果

| variant | 通过 checks | 通过率 |
|---|---:|---:|
| **with_skill** | 165/219 | **75.3%** |
| **no_skill** | 96/219 | **43.8%** |
| **差异** | — | **+31.5 个百分点** |

`--results`：`status = partial`、`invalid_runs = []`、`unpaired_runs = []`、`unexpected_runs = []`、`completed_runs 84`。

**方向性结论：在 42 条 task 上，加载 skill 的产物通过率（75.3%）显著高于裸模型（43.8%），差 +31.5 个百分点。**

**小结**：在「产物客观质量」维度，skill 的优势主要体现在**可读性规范（标题/单决策点/术语一致/可判定预期）**和**结构流程（阶段化/裁剪/映射）**上，尤其 #39（+3）、#32（+4）、#36（+2）区分度最高。

**关键发现（评测集缺陷）**：`#3/#7/#8/#9/#11/#13/#14/#16/#19/#20/#21` 等评审类 case 的 prompt 里，`[附用例]` 是占位符，或引用不存在的文件（`testing-tm-cases/`、`feat/order` 分支）。runner 正确标注「无法解析」，但这些 case 的 checks 期望完整评审结果，导致 **with_skill 和 no_skill 在这些 case 上都低分**，且**不能归因于 skill 好坏**。这是评测集自身的设计缺陷，需单独修复（在 prompt 里附真实用例内容）。

## 5. 诚实边界（避免过度解读）

1. **只有 1 次重复、缺 old 对照**：`status = partial`，这是「方向性观察」，**不是可发布的整体质量结论**。
2. **+31.5pp 可能被系统性稀释**：42 条里有约 29 条是「评审/安全/失败模式」类，其 checks 大量依赖「skill 特有流程术语」（R1/R2/R3、失败模式#N、10 维度），no_skill 天然不知道这些术语，必然低分——这部分差距是「裸模型没有 skill 流程」的必然结果，不是「skill 让生成质量更高」的证据。
3. **真正有说服力的是 4.1 节的 13 条「产物客观质量」case**：它们测的是「可读性/精简/覆盖/准确」这些不看 skill 流程也能判的客观指标。在这 13 条上，with_skill 约 80%+、no_skill 约 55%，差距更真实但仍需分层看待。
4. **runner 用了 reasoning 深度思考配置**：严格说测的是「深度思考 + skill」vs「深度思考裸模型」，未单独剥离 skill 本身边际增益。
5. `duration_seconds = 0` 占位，未记录真实耗时与 token。
6. 结论不可作 keep/revert 依据，不构成「质量提升」声明。

## 6. 遗留问题与建议

1. **评测集缺料**（最重要）：约 11 条评审类 case 的 prompt 需补真实用例内容，否则这些 case 无法产出有效判定。建议列为后续专项。
2. **old 对照（v9.10.0）未做**：补上后才能真正回答「本次改动相对旧版是否有增益」。
3. **3 次重复未做**：单次结果受随机性影响，正式结论需 3 次重复取稳定值。
4. **trigger（12 条）未判**：路由触发准确性是另一维度，需单独用「读 SKILL.md 路由规则」的判定方式。
