## 2. 冲突候选

### 2.1 #13 评级阈值未包含「已确认 P0 → D」

| 项 | 内容 |
|---|---|
| check 原文 | 「整体评级按 A:≥95%且密度<0.5 / B:≥80% / C:≥60% / D:<60% 判定」 |
| skill 规则 | `knowledge/review-mode.md:84`：「已确认 P0：整体评级 D，包含集合级问题；以下分级仅适用于无已确认 P0 的情况」；同文件 L85-88 为 A/B/C/D 阈值 |
| 冲突 | check 只写阈值，未写 P0 优先；runner 按 P0→D，judge 按字面阈值，可能判 false |
| 建议 | 把 check 改为两句：「若存在已确认 P0，整体评级为 D；否则按 A:≥95%且密度<0.5 / B:≥80% / C:≥60% / D:<60% 判定」 |
| 处理阶段 | 阶段 2 或阶段 4 的 INV 提案；本阶段不改 |
| 影响 | 仅 #13；#21 的「评级 C」在无 P0 前提下与 skill 一致 |

### 2.2 #7 对 120 条用例要求「抽样评审」

| 项 | 内容 |
|---|---|
| check 原文 | 「兜底：抽样评审（每模块抽20%）」「标注「抽样评审」」 |
| skill 规则 | `knowledge/large-scale-review.md:47`：S2（50 < N ≤ 300，且无时间约束）→ 全量分批，每批 ≤50 条；S3（N > 300 或存在时间/人力约束）→ 分层抽样 |
| 冲突 | 120 条且未声明时间/人力约束时，skill 走 S2 全量分批，不实际抽样；check 强制要求抽样与「抽样评审」标注 |
| 建议 | 把 check 改为：「报告给出 S2 全量分批或 S3 分层抽样的策略及依据；若选 S3，标注抽样范围与样本清单；若选 S2，不要求出现「抽样评审」」 |
| 处理阶段 | 阶段 2 或阶段 4 的 INV 提案；本阶段不改 |
| 影响 | #7；#19 同型（见 2.3） |

### 2.3 #19 对 >100 条用例强制「触发分层抽样」

| 项 | 内容 |
|---|---|
| check 原文 | 「用例>100条触发分层抽样」「按优先级×模块交叉分层，每层抽20%最少1条」「标注「抽样评审」」 |
| skill 规则 | 同上：>100 不等于必须抽样；S2 覆盖 50 < N ≤ 300 且无时间约束 |
| 冲突 | 把「>100」直接等同于抽样，与 S2 全量分批冲突 |
| 建议 | 改为：「报告先按 S1–S5 选择策略并写明依据；只有选 S3/S5 时才要求分层抽样、sample_seed 与三份清单」 |
| 处理阶段 | 阶段 2 或阶段 4 的 INV 提案；本阶段不改 |
| 影响 | #19；与 #7 一并修复 |
