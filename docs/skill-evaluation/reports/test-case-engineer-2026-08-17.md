## 改动内容摘要（评测对象）

本次优化吸收外部「测试用例编写规范」的**语言风格规则**，输出格式（Markdown 表格 + bullet）保持不变：

1. **新增「禁用的模糊表达」节**：15 个禁用词清单 + 5 行"不可执行表达→改为"替换表
2. **新增「Tag 规范」节**：小写 kebab-case、首位业务域、1–5 个、由宽到窄排列
3. **title 规范强化**：允许 `[]` 类别标记与 `→` 迁移符号；长标题例外判定条件明确化（信息删除会造成场景重复或无法识别环境/版本时可保留，禁止截断/`...`/「等」）
4. **steps 规范强化**：新增 API 步骤（方法/路径/参数/认证）、数据步骤（查询对象/字段）写法；禁止 `if/else` 分支；拆分维度细化
5. **expected_results 规范强化**：5 类可观察证据分类框架（UI / API / 数据 / 业务状态 / 可观测性）+ 紧密断言合并例外
6. **业务背景规范**：以「验证」开头描述条件、对象、动作和结果方向，不复述步骤
7. **前置条件负面清单**：禁止「环境正常」「已准备相关数据」等模糊表述
8. **writing-examples.md 扩充**：新增 API 调用 / 数据查询 steps 示例、HTTP 403/200 预期示例、需求追溯/业务背景对照、完整好/坏用例 + 9 条"坏在哪里"清单
9. **core.md 对齐**：阶段 3 CHECKPOINT 显式列出 15 个禁用词，标题超长 Fallback 更新

> 注：本轮曾引入 YAML 输出格式后按用户要求回退，最终仅保留风格规则。YAML 残留扫描 = 0 ✓

## within-judge paired 对比（delta 决策）

**协议**：同一 judge 同一次评审内通读改前（d2f2b1e）/ 改后（891530f）完整 diff，投票 + margin + 退化场景。

**投票：better，margin: clear**

改进证据（可验证）：
- 禁用词表从 6 个（散落在 expected_results 规范）扩展为 15 词 + 替换表的独立成节黑名单，且 full_test 输出验证了模型确实执行了该清单自检
- Tag 从"场景标签，用于分类和筛选"一句说明升级为完整规范，full_test 输出的 11 条用例标签 100% 符合 kebab-case + 首位业务域
- 业务背景从"补充说明测试场景的业务背景"升级为"以「验证」开头 + 不复述步骤"，full_test 输出 11/11 条符合
- 5 类可观察证据分类给了 expected_results 一个可判定的分类框架（改前是平铺列举）
- writing-examples 的"坏在哪里"9 条清单使反例从对照表升级为可教学案例

**改后版潜在退化场景**（两要素齐全）：
1. **规则体积增加 → 阶段 3 读取成本上升**：场景=快速模式下模型加载 writing-rules.md 的 token 增加约 20%（+47 行）；为何可能更差=上下文紧张时更长规则可能被截断或稀释注意力（缓解：writing-examples 仍为按需加载，核心增量集中在单文件）
2. **禁用词清单跨文件冗余 → 判定冲突风险**：场景=阶段 3 读 writing-rules 的 15 词表、阶段 4 读 test-standards 的约 50 词表时同一禁令出现两处；为何可能更差=两份清单不一致时（15 vs 50）执行者可能困惑以哪份为准，需明确从属关系
3. **业务背景强制句式的表达限制**：场景=金融/合规类用例的业务背景需说明法规依据而非验证意图；为何可能更差=强制「验证」开头使这类背景信息被迫改写为验证句式，损失上下文信息

（≥1 个合格退化场景已列出，本票不触发 §7 降权）

## 测评结论

本次语言风格优化（+158/-40，3 文件）是一次**有效的实质改进**：

- **delta 结论**：better（clear）——三项新规则（Tag kebab-case、业务背景「验证」句式、15 词禁用表）在 full_test 输出中获得 100% 落实证据，非纸面改进
- **总分 96/100（A）**，与上轮 97 分不可直接比较（v1.3→v1.4 换尺）；同尺推演净变化约 ±1 分
- **效果分 31/33（E-A）**，B3.6 首次以 full_test（非 dry_run）验证显著增益
- **无效改进检测**：六规则通过（规则 2 触发但豁免成立），判定 keep
- **遗留债**：对抗测试缺失（P0，连续两轮）、版本号未升（P1，本次新增）

**核心价值证明**：skill 相对 baseline 的增益从"结构规范"扩展到"风险识别"（并发防超发/重复核销、状态机非法流转）——这是裸模型在同等 prompt 下完全缺失的能力。
