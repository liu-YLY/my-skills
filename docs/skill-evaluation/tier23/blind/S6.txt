# 测试用例集：Webhook 创建

## 阶段 1：需求理解

**功能概述**：用户在创建 Webhook 弹窗中配置 Version、Trigger、Endpoint URL 后，点击 Add endpoint 完成 Webhook 创建。

**需求追溯**：
| 条目 | 需求ID/PRD章节/Story | 备注 |
|------|----------------------|------|
| Webhook 创建 | 需求#39 | 无正式 ID，填「待补充」 |

**用户角色**：拥有创建 Webhook 权限的登录用户。

**业务规则**：
1. 创建 Webhook 需配置 Version（下拉框）、Trigger（选择框）、Endpoint URL（输入框）。
2. 点击 Add endpoint 提交创建，创建成功后 Webhook 生效。
3. Endpoint URL 需符合 URL 格式，且为必填项。

**状态规则**：
- 初始状态：Add webhook 弹窗打开，各控件处于默认值。
- 状态切换：必填项未填写完整时 Add endpoint 按钮不可用；填写完整后按钮可点击。
- 状态保存：提交成功后新增一条 Webhook 记录。
- 状态互斥：无。
- 非法状态：必填项缺失或格式非法时不允许提交。

**配置联动规则**：
- 上游配置：Version 与 Trigger 的可选值来自系统配置。
- 下游行为：创建后的 Webhook 用于接收对应 Trigger 触发的事件回调。
- 配置优先级：无。
- 配置冲突：无。

**默认值规则**：
- Version 下拉框默认未选择或为最新版本（需求未明确，待产品确认）。
- Trigger 选择框默认未选择（待产品确认）。

**异常规则**：
- 网络异常：提交请求失败时给出失败反馈，不创建记录。
- 重复提交：快速多次点击 Add endpoint 不应重复创建。

**数据规则**：
- Endpoint URL：必填，需符合 URL 格式（http/https，待产品确认具体格式规则）。
- Version：必填，从下拉框选择。
- Trigger：必填，从选择框选择（单选/多选待产品确认）。

**风险分析**：
- 高风险模块：Endpoint URL 字段（注入风险、格式校验）。
- 高回归风险：Webhook 列表与事件回调链路。
- 必须重点测试范围：Endpoint URL 校验、必填项校验、重复提交防护。

**待确认项**：
- Version 下拉框可选项与默认值需求未明确（待产品确认），本用例按 v3/v4 假设设计。
- Trigger 选择框可选项需求未明确（待产品确认），本用例按「订单创建」「订单支付」假设设计。
- Trigger 为单选还是多选需求未明确（待产品确认），本用例按单选假设设计。
- Endpoint URL 格式规则（是否限定 http/https）需求未明确（待产品确认），本用例按 http/https 假设设计。
- Version 与 Trigger 是否存在联动关系需求未明确（待产品确认），本用例不落联动用例。
