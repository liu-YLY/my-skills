用例评审（10 条全部标 P0）

【批次概况】
本批共 10 条用例，全部标注为 P0 优先级，其中包含明显合格的用例与明显不合格的用例。

【核心评审结论】
1. "10 条全部标 P0"本身即属优先级标注缺陷：P0 应为必须优先执行的高危/核心用例，占比通常应控制在 5%~10%。全量 P0 等于没有优先级，失去排期与风险区分的意义。
2. 优先级需结合"功能重要度 + 缺陷影响面 + 发生概率"综合评定，而非一概而论。
3. 合格用例与不合格用例混在同一优先级下，说明评审标准不统一，需逐条复核。

【合格用例应具备的特征】
1. 结构完整：包含用例编号、模块、标题、前置条件、测试数据、操作步骤、预期结果、优先级等字段。
2. 步骤可复现：一步一动作，输入明确，无歧义。
3. 预期可验证：有可观测的判定依据（提示文案、跳转、数据变化）。
4. 优先级有依据：仅核心主流程、涉及资金/安全/数据丢失的用例可标 P0。

【不合格用例常见问题】
1. 标题模糊，无法识别被测对象与场景。
2. 缺少前置条件或测试数据，无法复现。
3. 预期结果为空、仅"成功/失败"或无判定依据。
4. 步骤跳跃、一步多动作，或与预期结果不对应。
5. 优先级误标：次要功能、低频异常也被标为 P0。

【优先级整改建议】
1. 仅保留真正核心的用例为 P0（建议本批不超过 1~2 条），如登录/支付主流程、涉及资金安全或数据安全的用例。
2. 将重要但非阻断的用例降为 P1。
3. 一般功能校验、次要异常场景降为 P2/P3。
4. 补充优先级评定标准，并逐条复核、标注依据。

【评审执行建议】
因用例明细未随需求附传，无法逐条给出"合格/不合格"判定。请按上述标准逐条复核，重点检查三项：字段完整性、预期结果可验证性、优先级依据，并输出逐条评审结论（合格/需修改/不通过）及对应理由。
