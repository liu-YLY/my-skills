10 条登录用例评审报告（优先级复核）

一、评审范围
用例总数：10 条（TC_001~TC_010），当前全部标注 P0。

二、逐条评审

TC_001 登录-手机号正确密码跳转首页（P0）
评价：核心主流程，保留 P0 合理。预期"跳转首页"可接受，建议补充具体页面与登录态。

TC_002 登录-手机号格式错误提示（P0）
评价：常规字段校验，非核心主流程，不影响登录主链路，建议降级。

TC_003 登录-密码错误提示（P0）
评价：高频失败分支，保留 P0 或降 P1 均可；建议 P1（错误分支通常低于主成功路径优先级）。

TC_004 登录-密码为空提示（P0）
评价：常规必填校验，建议降级。

TC_005 登录-验证码错误提示（P0）
评价：验证码失败分支，属常规校验，建议降级。

TC_006 登录-网络异常提示（P0）
评价：异常场景，影响可用性体验但不阻塞主流程，建议降级。

TC_007 登录-输入框 XSS 注入（P0）
评价：安全类用例，需结合威胁模型判断；若输入会回显且无过滤，安全风险高，建议保留 P0 或 P1，不建议低于 P1。

TC_008 登录-连续错误锁定（P0）
评价：账号安全类，防暴力破解，建议保留 P0 或 P1，不宜降至 P2。

TC_009 登录-记住登录 7 天（P0）
评价：体验增强类，非核心，建议降为 P1 或 P2。

TC_010 登录-退出登录（P0）
评价：会话管理类，建议 P1。

三、优先级复核建议（针对提问的 TC_002/004/005/006/007）

TC_002 手机号格式错误：P0 → P2（常规字段校验，低频影响，不阻塞主流程）
TC_004 密码为空：P0 → P1（必填校验，属基础校验，建议 P1）
TC_005 验证码错误：P0 → P1（验证码失败分支，建议 P1）
TC_006 网络异常：P0 → P2（异常场景，非核心，建议 P2）
TC_007 XSS 注入：P0 → 保留 P0 或 P1（安全类，建议不低于 P1；若存在明显注入风险保留 P0）

四、调整后优先级汇总
TC_001 登录成功：P0
TC_002 格式错误：P2
TC_003 密码错误：P1
TC_004 密码为空：P1
TC_005 验证码错误：P1
TC_006 网络异常：P2
TC_007 XSS 注入：P0（或 P1，视安全评审）
TC_008 连续错误锁定：P0（或 P1）
TC_009 记住登录：P2
TC_010 退出登录：P1

五、结论
将全部用例标 P0 会导致优先级失去区分度，掩盖真正核心与安全用例。建议按上述方案区分 P0/P1/P2：P0 保留主流程与高安全风险用例，常规校验降 P1/P2，异常场景降 P2。
