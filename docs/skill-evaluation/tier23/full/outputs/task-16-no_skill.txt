登录用例评审报告（字段缺失与冗余问题）

一、评审范围
用例总数：4 条（TC_001~TC_004）。

二、逐条评审

TC_001 登录-手机号正确密码
问题：
1. 缺优先级字段。
2. 缺用例类型字段（功能/接口/UI）。
3. 预期"登录成功"模糊，未指定跳转页面与会话状态。
4. 步骤未给出具体输入值（密码值缺失）。
建议：补齐优先级（P0）、类型（功能测试），补充具体密码值，细化预期。

TC_002 登录-手机号错误密码
问题：
1. 与 TC_001 步骤完全重复，仅预期由"登录成功"改为"提示错误"，属冗余，可合并或参数化。
2. "错误密码"未给出具体错误值。
3. 预期"提示错误"模糊，未指定具体提示文案。
建议：与 TC_001 合并为参数化用例（正确/错误密码两条数据），或保留但明确差异点并补充错误密码具体值。

TC_003 登录-邮箱正确密码
问题：
1. 预期结果为空，用例不可执行（严重）。
2. 缺优先级、类型字段。
3. 步骤未给出具体邮箱与密码值。
建议：补充预期（如"登录成功，跳转首页"），补齐字段与输入值。

TC_004 登录-密码为空
问题：
1. 缺需求追溯字段。
2. 缺优先级、类型字段。
3. 预期"提示错误"模糊。
建议：补齐需求追溯（关联需求 ID）、优先级（P1）、类型，细化提示文案。

三、问题汇总
- 字段缺失：优先级缺失（TC_001/002/003/004）、类型缺失（TC_001/002/003/004）、需求追溯缺失（TC_004）。
- 冗余：TC_002 与 TC_001 步骤完全重复，仅预期不同。
- 预期缺失：TC_003 预期结果为空。
- 预期模糊：TC_001/002/004 预期均为模糊断言。
- 输入值缺失：TC_001/002/003 未给出具体输入值。

四、结论
整体质量偏低，主要问题为字段缺失、用例冗余、预期缺失/模糊。建议统一补齐标准字段（优先级、类型、需求追溯、前置条件、具体输入值），合并冗余用例，细化所有预期结果后重新评审。
