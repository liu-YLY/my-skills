二、缺陷类型一：步骤耦合
════════════════════════════════════════════
定义：一个测试步骤承载多个动作，或多个步骤只对应一条预期结果，
      导致定位失败原因困难、无法判断是哪一步出错。

识别规则：
  R1 单步骤含多个动词或"并且/同时/然后"连接的多个动作 → 拆分为多步。
  R2 多个步骤（≥2）却只有一条预期结果 → 每步应给出对应中间预期。
  R3 一个步骤既包含操作又包含结果校验 → 操作与断言分离。

示例 1（多动作耦合，错误）：
  步骤：点击"提交"按钮并检查页面跳转并验证订单号生成。
  修正：
    步骤1 点击"提交"按钮。
    步骤2 验证页面跳转至"下单成功"页。
    步骤3 验证生成唯一订单号且非空。

示例 2（多步骤单预期，错误）：
  步骤1 输入用户名；步骤2 输入密码；步骤3 点击登录。
  预期结果：登录成功。（3 步仅 1 条预期，无法定位失败环节）
  修正：
    步骤1 输入合法用户名 → 预期1 用户名框正常回显输入值。
    步骤2 输入正确密码 → 预期2 密码以掩码显示。
    步骤3 点击登录 → 预期3 跳转首页并显示登录用户昵称。

三、缺陷类型二：模糊断言
════════════════════════════════════════════
定义：预期结果使用无法客观判定通过/失败的模糊表述。

模糊词清单（需替换）：
  "正常""正确""成功""合理""适当""较快""友好""稳定""大概""基本""应该"

识别规则：
  R4 预期结果含模糊词且无量化指标 → 判定为模糊断言。
  R5 预期结果无法给出可观测的判定标准 → 需补充具体现象/数值/文案。

示例 3（模糊，错误）：
  预期结果：系统正常返回结果。
  修正：接口返回 HTTP 200，响应体 code=0，且 data 字段包含订单号。

示例 4（模糊，错误）：
  预期结果：页面加载较快。
  修正：页面首屏渲染完成时间 ≤ 3 秒（或以性能基线下限为准）。
