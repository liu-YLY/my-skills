## 阶段 1：需求理解

**功能概述**：支付模块完成订单的支付发起、支付结果确认、退款与异常补偿，是涉及资金的核心链路。

**需求追溯**：
| 条目 | 需求ID/PRD章节/Story | 备注 |
|------|----------------------|------|
| 支付发起 | 待补充 | 用户未提供 PRD/Story ID |
| 支付结果回调 | 待补充 | 用户未提供 PRD/Story ID |
| 退款 | 待补充 | 用户未提供 PRD/Story ID |

**用户角色**：买家、卖家、系统回调服务

**业务规则**：
1. 支付金额以分为单位计算，禁止浮点运算
2. 同一订单只允许成功支付一次，重复支付需幂等拦截
3. 退款金额不得超过已支付金额
4. 支付超时后订单进入「已取消」，不可再支付
5. 支付成功后订单状态由「待支付」流转为「已支付」

**状态规则**：
- 初始状态：待支付
- 状态切换：待支付 → 已支付 / 待支付 → 已取消（超时）
- 状态保存：支付成功后订单状态持久化为「已支付」
- 状态互斥：已支付与已取消互斥
- 非法状态：已取消订单不可再次支付

**异常规则**：
- 支付请求超时：先查询真实支付结果，禁止直接判定未支付
- 回调重复：同一支付流水重复回调仅生效一次
- 部分退款：退款金额边界为 0、等于支付金额、大于支付金额

**风险分析**：
- 高风险模块：支付、退款（涉及资金）
- 高回归风险：订单状态流转、账本记录
- 必须重点测试范围：金额精度、重复支付、退款边界、超时补偿

**待确认项**：
- 支付渠道、超时时长、退款时效等具体规则未提供，标注「待产品确认」

## P0 占比说明（自检发现 P0 占比 60%）

本次生成 12 条用例中 P0 共 7 条，占比约 58%（四舍五入口径下为 60%）。

**结论：该分布有业务风险依据，无需为满足比例调整用例，可直接出报告。**

依据（test-standards.md「优先级比例指导」与「优先级三步法」）：

1. **比例只作观察信息，不预设各档占比**：优先级比例指导明确规定「报告分布作为观察信息，不预设各档占比，不为满足比例增加、删除或调整用例」。

2. **P0 占比高的根因是功能属性而非分布失衡**：支付模块涉及资金，P0 定义为「核心流程不可用、重大资金或数据损失、关键安全边界失效等阻断风险」。本模块中金额精度、重复支付、回调幂等、退款边界任一环节失效均直接造成资损，按三步法逐条复核：
   - 业务影响：资损 → 最高档
   - 发生可能性与回归必要性：资金链路必须每次发布准入检查 → 最高档
   - 结论：P0 依据充分，非「缺少风险依据的分布异常」

3. **不为满足比例调整用例**：阶段 4 失败模式明确规定「优先级分布异常且缺少风险依据」才需按三步法复核，复核后「保持有依据的优先级，在效率报告中说明分布及依据；不为满足比例调整用例」。本次复核结果为「有依据」，故维持原优先级。
