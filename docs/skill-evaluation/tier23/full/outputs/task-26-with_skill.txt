## 阶段 1：需求理解

**功能概述**：登录功能完成用户身份认证，支持账号密码登录，是系统访问控制的第一道关口。

**需求追溯**：
| 条目 | 需求ID/PRD章节/Story | 备注 |
|------|----------------------|------|
| 账号密码登录 | 待补充 | 用户未提供 PRD/Story ID |
| 登录锁定与安全 | 待补充 | 用户未提供 PRD/Story ID |

**用户角色**：普通用户、未登录访客

**业务规则**：
1. 账号为手机号，密码 8-20 位
2. 连续输错 5 次后锁定 30 分钟
3. 登录成功后跳转首页并建立会话
4. 密码以掩码展示，不明文回显

**异常规则**：
- 账号不存在或密码错误时提示「用户名或密码错误」，不区分具体原因
- 未登录访问受保护页面时跳转登录页
- Token 过期后需重新登录

**风险分析**：
- 高风险模块：认证、会话管理
- 必须重点测试范围：密码校验、锁定机制、会话安全、暴力破解防护

**待确认项**：
- 是否支持验证码/短信登录、锁定是否含解锁策略，标注「待产品确认」

**信息来源**：
- plugins/testing/skills/test-case-engineer/SKILL.md 及 core.md
- knowledge/ 下 writing-rules.md / test-standards.md / test-levels.md / bug-patterns.md / case-arrangement.md / anti-patterns.md / failure-semantics.md
- 未找到产品知识文件（knowledge/products/ 无登录对应产品）；未发现项目内登录模块代码或 PRD

- **优先级**: P0
- **类型**: functional
- **需求追溯**: 待补充 / TP-01
- **来源**: ai-generated
- **业务背景**: 验证输入正确手机号与密码时登录成功并跳转首页

**前置条件**:

1. 打开登录页
2. 在「手机号」输入框输入 13800138000

- 会话建立，接口返回登录态 token

**标签**: login, happy-path

### TC_LOGIN_BRUTE_011: 安全 - 高频登录尝试触发频率限制

- **优先级**: P1
- **类型**: security
- **需求追溯**: TP-09
- **来源**: ai-generated

- 已注册账号 13800138000

**标签**: login, security, brute-force
