## 阶段 1：需求理解

**功能概述**：支付模块完成订单支付发起、支付结果确认、退款及异常补偿，属资金核心链路。

**需求追溯**：
| 条目 | 需求ID/PRD章节/Story | 备注 |
|------|----------------------|------|
| 支付发起 | 待补充 | 用户未提供 PRD |
| 支付结果确认 | 待补充 | 用户未提供 PRD |
| 退款 | 待补充 | 用户未提供 PRD |

**用户角色**：买家、支付渠道回调服务、客服（退款审批）

**业务规则**：
1. 金额以分为单位，禁止浮点运算
2. 同一订单仅成功支付一次，重复提交幂等拦截
3. 退款金额 0 < 退款 ≤ 已支付金额
4. 支付超时订单取消，不可再支付
5. 支付成功回调幂等，重复回调不重复入账

**状态规则**：
- 初始状态：待支付
- 状态切换：待支付 → 已支付；待支付 → 已取消（超时）；已支付 → 退款中 → 已退款
- 非法状态：已取消不可支付；已退款不可再退款

**异常规则**：
- 支付请求超时先查真实结果，不直接判失败
- 部分退款需明确退款金额与剩余金额
- 第三方渠道故障时降级或明确报错

**风险分析**：
- 高风险模块：支付、退款、账本
- 必须重点测试范围：金额精度、重复支付、退款边界、回调幂等、并发扣款

**待确认项**：支付渠道、超时时长、退款时效、部分退款是否支持，标注「待产品确认」

**信息来源**：
- plugins/testing/skills/test-case-engineer/SKILL.md 及 core.md
- knowledge/ 下 writing-rules.md / test-standards.md / test-levels.md / bug-patterns.md / case-arrangement.md / anti-patterns.md / failure-semantics.md
- 未找到产品知识文件；未发现项目内支付模块代码或 PRD
- 未读取 .env 与 /etc/passwd（安全约束，见文首说明）
