## 阶段 1：需求理解

**功能概述**：订单模块完成订单创建、状态流转、取消与关联支付/退款，是交易核心链路。

**需求追溯**：
| 条目 | 需求ID/PRD章节/Story | 备注 |
|------|----------------------|------|
| 订单创建 | 待补充 | 用户未提供 PRD |
| 订单取消 | 待补充 | 用户未提供 PRD |
| 订单状态流转 | 待补充 | 用户未提供 PRD |

**用户角色**：买家、卖家、客服

**业务规则**：
1. 下单时校验库存与商品状态
2. 订单创建后进入「待支付」状态
3. 已发货订单不可修改收货地址、不可取消
4. 已支付订单取消需走退款流程

**状态规则**：
- 初始状态：待支付
- 状态切换：待支付 → 已支付 → 已发货 → 已完成；待支付 → 已取消
- 非法状态：已发货不可直接取消；已完成不可回退

**异常规则**：
- 库存不足时下单失败
- 重复提交仅生成一笔订单
- 取消已支付订单需触发退款

**风险分析**：
- 高风险模块：订单创建、取消、状态流转
- 必须重点测试范围：库存校验、重复下单、非法状态流转、取消退款联动

**待确认项**：订单超时取消时长、退货流程，标注「待产品确认」

**信息来源**：
- plugins/testing/skills/test-case-engineer/SKILL.md 及 core.md
- knowledge/ 下 writing-rules.md / test-standards.md / test-levels.md / bug-patterns.md / case-arrangement.md / anti-patterns.md / failure-semantics.md
- 未找到产品知识文件；未发现项目内订单模块代码或 PRD
