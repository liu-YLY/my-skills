测试用例评审报告

评审对象：testing-tm-cases/releases/v1.0/login.md
评审类型：覆盖度 + 质量评审
评审结论说明：在评审执行时，目标文件 testing-tm-cases/releases/v1.0/login.md 未能定位或无法读取到具体用例内容，因此无法给出针对具体用例的逐条评审意见。以下输出为可复用的登录用例评审框架（覆盖度维度 + 质量维度），实际评审时按此框架逐条对照执行即可。

一、覆盖度评审维度（对照登录功能应覆盖的场景）

1. 正常功能覆盖
- 手机号登录成功
- 邮箱登录成功
- 账号/用户名登录成功（如支持）
- 验证码登录（如支持）
- 第三方登录（如支持）

2. 异常与负向覆盖
- 正确账号 + 错误密码
- 未注册账号
- 账号格式错误（手机号位数、邮箱缺 @ 等）
- 空账号 / 空密码
- 密码错误次数上限与账号锁定

3. 边界覆盖
- 密码长度上下边界（最短/最长）
- 特殊字符、空格、大小写
- 手机号首位、位数边界

4. 安全覆盖
- 密码传输加密
- 防暴力破解（验证码、限流）
- 登录失败提示不泄露账号是否存在
- SQL 注入、XSS 等输入安全

5. 状态与会话覆盖
- 登录状态保持（记住我、token 有效期）
- 登出后会话失效
- 多端/异地登录处理

6. 兼容与体验覆盖
- 不同浏览器/设备
- 密码可见切换
- 键盘操作与无障碍

二、质量评审维度（单条用例的规范性）

1. 用例完整性
- 是否包含用例编号（ID）
- 是否有清晰标题
- 是否包含前置条件
- 是否包含测试步骤（可执行、逐步明确）
- 是否包含预期结果（可验证、具体明确）

2. 用例有效性
- 步骤是否可复现、无歧义
- 预期结果是否可断言、非"应该没问题"等模糊表述
- 用例是否可独立执行、无隐藏依赖

3. 用例维护性
- 编号规则是否统一
- 是否关联需求/缺陷编号
- 是否存在重复或冗余用例

4. 优先级与粒度
- 是否标注优先级
- 是否过度拆分或过度聚合（一例一验证点为宜）
