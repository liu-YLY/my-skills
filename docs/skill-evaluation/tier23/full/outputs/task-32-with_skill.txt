可读性约定（贯穿全文）：
- 标题一眼定位测试点：`被测对象 - 条件/行为/结果`，不写「验证」「测试」开头
- 步骤只保留改变状态或提供输入的操作，动词统一用「输入 / 点击 / 选择 / 打开 / 刷新」
- 预期写成「在哪里 + 看到什么 + 什么值/状态」，不用「成功」「正常」等评价词
- 术语全文一致：对象统称「登录页」「手机号输入框」「密码输入框」「登录按钮」；提示统一写「页面显示『…』」；跳转统一写「页面跳转到 /…」

编排策略：按用户旅程编排

## 阶段 1：需求理解

**功能概述**：登录功能完成账号密码身份认证，支持登录成功、错误提示、账号锁定与会话建立。

**需求追溯**：需求 ID 待补充（用户未提供 PRD）。

**用户角色**：普通用户、未登录访客

**业务规则**：
1. 账号为手机号，密码 8-20 位
2. 连续输错 5 次锁定 30 分钟
3. 登录成功跳转首页并建立会话
4. 密码以掩码展示

**异常规则**：账号或密码错误统一提示「用户名或密码错误」；未登录访问受保护页跳转登录页。

**待确认项**：是否支持验证码登录、锁定解锁策略，标注「待产品确认」。

**信息来源**：SKILL.md、core.md、knowledge/ 下 writing-rules.md / test-standards.md / test-levels.md / bug-patterns.md / case-arrangement.md / readability.md / anti-patterns.md；未找到产品知识文件与登录模块 PRD。
