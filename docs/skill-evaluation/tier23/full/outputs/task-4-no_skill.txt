一、逐条评审意见

用例：TC_001 登录-手机号正确密码
问题：
1. 仅给出一行标题，缺少用例编号规范外的完整要素：前置条件、测试步骤、预期结果均缺失。
2. "正确密码"依赖账号与密码的对应关系，缺少前置条件说明（账号已注册、状态正常），无法独立执行。
3. 缺少预期结果描述，无法判定"登录成功"的具体表现（跳转页面、提示、会话建立）。
4. 未标注优先级。
改进建议：
- 补充前置条件：已存在已注册且状态正常的手机号账号。
- 补充测试步骤：进入登录页 → 输入手机号 → 输入密码 → 点击登录。
- 补充预期结果：登录成功，跳转首页/用户中心，顶部显示用户信息。
- 补充优先级（建议 P0）。

用例：TC_002 登录-手机号错误密码
问题：
1. 同样缺少前置条件、测试步骤、预期结果，仅标题可读。
2. 未明确"错误密码"的定义（与正确密码完全不同？大小写错误？）。
3. 缺少失败后的具体预期（提示文案、是否锁定计数、密码框是否清空）。
4. 未标注优先级。
改进建议：
- 补充前置条件：已存在已注册手机号账号。
- 补充步骤与预期：登录失败，提示"手机号或密码错误"，不进入系统。
- 建议补充连续多次错误密码触发的锁定用例，形成完整负向链路。

用例：TC_003 登录-邮箱正确密码
问题：
1. 同样三要素（前置条件、步骤、预期结果）缺失。
2. 与 TC_001 结构一致，但仅覆盖了"正确密码"正向场景，未覆盖邮箱登录的错误密码等负向场景。
3. 未标注优先级。
