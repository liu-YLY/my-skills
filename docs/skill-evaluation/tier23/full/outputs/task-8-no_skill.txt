一、评审+改写工作流

1. 评审阶段
- 逐条读取用例，按统一检查表核对（见下）
- 识别问题：缺编号/缺步骤/缺预期/标题不清晰/粒度不当/重复等
- 对问题分级：阻断 / 严重 / 一般 / 建议

2. 改写阶段
- 对每条存在问题的用例直接产出修正稿
- 保留原始用例语义，仅补齐或修正缺失/错误要素
- 不改变原有用例编号（如已有），缺失编号则按统一规则补编
- 对粒度不当的用例做拆分，对重复用例做合并去重

3. 产出阶段
- 逐条输出：原用例 → 问题 → 修正后用例
- 附带问题汇总与改后通过率

二、统一检查表

1. 是否含唯一用例编号
2. 标题是否含"动作 + 对象 + 结果"
3. 是否有前置条件
4. 步骤是否可执行、逐步明确
5. 预期结果是否可断言
6. 是否标注优先级
7. 一例一验证点
8. 是否有重复/冗余
