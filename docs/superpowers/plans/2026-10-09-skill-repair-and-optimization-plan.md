# 2026年10月9日 Skill 修复与优化实施计划

## 目标与范围

修复当前 8 个 Skill 的确定性缺陷和相互冲突的推理规则，再增加适用性判定、失败语义、流程属性验证、证据追溯及分层覆盖报告。每项修复必须有可执行反例或可判定的行为验收，优化收益以实际输出和运行证据判断。

本计划覆盖 testing 与 wechat-formatter 两个插件。沿用现有入口、core、knowledge、脚本和 MCP 服务；新增能力优先扩展已有契约，不新增独立 Skill，不批量重写入口，不格式化无关内容。

用户已批准按本计划实施；修复和优化按批推进，本地提交记录可验收成果，远程发布仍需单独授权。历史结果保留在 [2026年9月21日迭代计划](2026-09-21-skill-iteration-plan.md)，本轮不覆盖旧记录。

## 阶段一 冻结契约与修复确定性工具错误

### B01 校准验收依据与评测期望

- 核对入口、知识、Schema、示例和评测期望，将每个问题的正确行为写入对应现有测试或 `test-prompts.json`。
- 先修正 strategy id5 的旧期望：缺历史缺陷或变更频率时标待补，不能代理填正式分数；代理信息可以单列，但不能混入正式总分。
- 仅当业务契约明确时冻结断言；没有明确依据的目标、时限和补偿行为保留待确认。
- 每个代码缺陷在所属批次先复现失败，再修复通过；不创建一个长期失败的测试提交。
- 验收：评测样本输入检查通过；已确认反例与断言一一对应；旧评分规则不能继续奖励错误答案。

### B02 禁止 diff 采集执行外部转换

- 在全部 Git diff 模式加入 `--no-ext-diff --no-textconv`，覆盖工作区、暂存区、分支、单提交和 revision range。
- 同步决策树、示例和原有测试；保留干净 feature 分支的三点 diff 规则及用户指定范围。
- 临时仓库配置一个只写标记文件的 textconv，验证各模式不会执行；正常文本 diff 内容与范围仍正确。
- 验收：全部模式无标记文件；暂存与未暂存范围不混淆；已有覆盖分析行为不退化。

### B03 修复依赖环漏报

- 修改 review-checker 图遍历，至少准确识别所有参与循环依赖的用例；不要求枚举指数数量的所有简单环。
- 优先采用无新依赖的强连通分量或完整遍历；报告给出具体循环证据，保留 confirmed 与 candidate 的区分。
- 覆盖 `A:[B,C], B:[B], C:[A]`、共享节点多环、自环、无环、孤立节点及不在集合中的依赖。
- 验收：B、A、C 都进入确定问题范围；无环不误报；大型依赖链不产生递归栈错误；101项基线测试保持通过。

### B04 保留 Word 内容顺序

- 按文档原始块顺序遍历段落和表格，保留现有标题、表格转义及列表转换方式。
- 使用临时 DOCX 验证“支付标题→退款表格→注册标题→注册正文”的输出顺序；补充连续表格、空段落和表格内多行内容。
- 文件生成只作用于测试临时目录；不使用用户真实文档作为可覆盖的测试素材。
- 验收：表格保持所属章节；单表格、纯正文及其他现有格式转换不退化。

### B05 保留代码块里的模块示例

- 模块解析跳过反引号围栏、波浪号围栏、缩进代码以及代码中的模块结束符；使用解析器或受控状态扫描，不继续全文盲替换。
- 同时验证正文模块仍会渲染，围栏中的 `:::hero`、字段和空白保持原样。
- 验收：代码展示内容与输入一致，正文模块可用，净化链未绕过。

### B06 完成高级模块导出

- 从 `layout/layout-modules.md` 建立实际模块清单，逐项对应正文格式、允许属性、DOM、CSS和公众号替代样式。
- 按完整模块族分批实现；每批包含解析、渲染、净化、样式和业务断言。图片类、字段类、行列类分别形成可独立验收的小PR。
- DOM 与 `modules-base.css` 对齐；解析 image-steps 图片、metrics行列、标题和声明的参数，避免显示内部字段名。
- 对不支持的输入给出明确错误或契约规定的带警告降级；不能静默套用通用字段渲染并宣称完整支持。
- 验收：全部声明模块有覆盖；图片生成安全的 img、有效字段不外露、布局属性产生可判定结构；危险 URL、事件属性和 CSS 仍被移除。
- 视觉验收：选择开场、指标、图片步骤和长内容模块，在实际浏览器检查桌面及390px移动视口；预览不外推公众号发布结果。

阶段一退出条件：D03至D07反例全部通过，D11期望已校准；涉及包的旧测试通过，未解决模块明确列入剩余工作，不用部分完成替代整阶段完成。

## 阶段二 统一状态机场景契约

### B07 修正守卫失败的目标语义

- 将“一个 guard 不满足”解释为“对应转换不执行”，不能直接推导整个事件被拒绝或状态不变。
- 同源同事件存在其他分支时，只有输入条件足以唯一确定分支才填写目标；通用字符串 guards 无法可靠求解时标待确认并给原因。
- guard场景明确一个违反条件、其余条件与输入关系；不把所有 guards 同时置为失败。
- 同步场景知识规则和审批示例，保留合法转换的 transition_id 和完整 guard_conditions。
- 验收：互补审批分支不再生成冲突验收；独立支付守卫、多个条件、未知条件及无匹配分支都有反例。

### B08 恢复单一场景契约与正确去重

- 在 `knowledge/state-modeling.md` 和 `knowledge/scenario-types.md` 分别维护模型与场景规范，core、入口及下游引用对应规范，消除循环指向。
- legal场景规范包含转换引用和守卫；illegal包含禁止引用和具体尝试目标；待确认目标统一使用规范值并提供原因。
- 去重依据转换、目标、完整前置条件及具体违反守卫；只合并验证输入和断言等价的场景。
- 将知识示例解析为真实 Schema，并送入覆盖匹配校验；引用ID不能绕过结构匹配。
- 验收：同事件不同合法分支及不同guard失败独立保留；示例可校验，错误目标、缺守卫、错误引用和非法目标不能计为已覆盖。

### B09 增加适用性判定

- 为十类场景输出 `applicable / not_applicable / unknown`、依据和所缺信息；无回调、异步、权限或副作用时不强行凑场景。
- 将退出条件改为“全部适用类型已处理，未知项有待确认说明”；去掉至少十条、每类至少一条的固定门槛。
- MCP新增适用性信息采用兼容字段或可选参数；缺信息时报告未评估，不靠事件关键词证明业务能力。
- 覆盖报告区分“适用但缺场景”“不适用”“适用性未知”，保留旧类型计数但不能单独判定完整。
- 验收：同步开关模型不生成消息乱序；异步支付模型不漏幂等；未说明权限不能直接判不适用；独立和增强模式口径一致。

### B10 改为宿主能力探测

- 优先检查当前宿主已暴露的 MCP 工具；用户显式禁用优先于自动探测，不把 Trae环境变量和文件设为跨宿主硬前置。
- 健康检查使用工具列表或明确的最小合法模型；区分业务校验不通过、参数错误、连接失败和工具不可用。
- 统一超时、重试和降级口径，防止正常服务因空载参数错误被判为离线；MCP仍是复核器。
- 验收：非Trae宿主已有工具可增强；未安装可独立运行；参数错误不冒充连接失败；真实 stdio 与 HTTP 调用通过。

阶段二退出条件：D01、D02、D08至D10闭环，场景示例、生成器、覆盖校验和下游消费共享契约；旧模型与既有调用仍可使用。

## 阶段三 修复诊断和风险决策逻辑

### B11 修复根因证据推理

- 撤销修复后不复现，先核对数据、配置、缓存、时序和复现概率；结论为验证不充分，不能自动标多根因。
- “修复后仍有问题”也不自动证明原假设错误：区分补丁未生效、修复不完整、观测错误及假设被证伪。
- 统一5 Whys规则为证据驱动停止；不强制凑五层，不把流程原因当唯一技术根因。
- 更新入口、根因方法、报告示例和期望，使用有反证的日志样本验证候选结论。
- 验收：偶发不复现不推出多根因；未验证结论不变成已确认；纯诊断任务仍能交付下一项最小验证。

### B12 修复性能判断和采样口径

- 区分异常观测点、业务SLA边界和特定环境下的容量边界；单个错误或RT陡增只能触发排查。
- 将负载机、测试数据、限流、网络和依赖容量纳入反证清单；根因要求时间窗一致的交叉证据。
- 区分连续原始采集和每30分钟趋势汇总；采样频率按待观测事件尺度与采集开销确定，不能把30分钟快照当持续监控。
- 统一入口与知识中的建议阈值，注明业务目标、历史基线、工具示例或待确认来源。
- 验收：参数错误造成4xx不被判容量上限；压测机饱和不归因服务端；短时连接耗尽可被发现；缺数据不外推生产TPS。

### B13 修复风险评分和资源安排

- 缺失维度允许未评估，不填代理分、不算正式总分；有依据的关键业务风险仍能形成临时优先级。
- 将发布阻断条件与风险分数分开：未授权资金操作、重复扣款等按已确认业务影响处理，不让低总分抵消阻断风险。
- 取消固定高/中/低工时比例和低风险禁止探索；按风险、覆盖缺口、验证成本和资源约束安排工作，全部高风险也合法。
- 区分历史缺陷与当前未解决缺陷，避免“有过P0”自动等于当前不可发布。
- 同步知识矩阵、策略模板、反例及B01校准的期望。
- 验收：新项目不造分；风险不为工时配额降级；资金风险优先于颜色；工时方案可解释且总额不超预算。

阶段三退出条件：D15、D17至D19闭环；三个Skill的入口、方法、示例和期望一致，正常诊断与资料不足场景均有行为证据。

- 验收：根因加用例请求连续完成；仅场景请求不扩范围；未经人工审核不声称已审核；跨Skill转交保留原始请求与待确认项。

## 阶段五 增加可验证的业务建模能力

本阶段依赖前四阶段的稳定契约。所有新增业务值必须来自需求或可核对资料；不为构造完整模型自动补业务规则。

### B16 增加失败语义与不确定结果

- 在状态机场景和用例规则增加失败阶段：执行前拒绝、提交前失败、提交成功但响应丢失、部分成功待补偿、结果未知。
- 为每类记录允许状态、禁止副作用、关键观测证据和恢复条件；状态为集合时保留条件，无法唯一确定时标待确认。
- 请求超时先核实业务结果，再决定重试；幂等键、重试时限、补偿动作均引用真实需求。
- 验收：支付响应丢失不直接认定未支付；重复回调验证一次有效业务结果；未知结果不生成无条件重试用例。

### B17 增加安全属性与进展属性

- 安全属性覆盖不重复资金操作、不越权、不进入非法状态；逐条记录适用对象、依据和验证方式。
- 进展属性仅针对要求结束的有限流程：最终完成、进入明确失败态或触发已定义恢复路径。
- MCP可新增可选的终止要求或目标集合，并检查无法到达允许终态的闭合状态集合；只称为结构检查，不证明时限内必达。
- guards和环境可能使路径不可执行，无法证明时报告待核实；会员续订等允许循环的对象不一刀切判错。
- 验收：有限审批 `A→B→A` 被报告无法结构性结束；存在退出路径不误报；周期会员模型按适用性排除；事件幂等与终态状态变化分开验证。

### B18 增加证据追溯和变更失效传播

- 在现有产物增加可选的需求引用ID、来源位置/版本、风险ID及上下游产物引用，保留原 `source/evidence_type` 字段。
- 需求→风险→模型/场景→用例→执行证据形成可查询关系；业务结果未知与来源不可达分别记录。
- 来源或需求变化后仅标记受影响结论需复核，不静默覆盖旧证据，不重跑无关完整流程。
- 优先支持结构化输入的确定性映射；自然语言关系无法确认时保留候选关联。
- 验收：优惠上限变化定位到对应边界用例；无关登录用例不失效；来源缺失不被冒充已确认；独立Skill使用不依赖完整追溯链。

### B19 分层报告覆盖情况

- 分别报告需求条目覆盖、模型转换覆盖、适用场景设计覆盖和实际执行覆盖；每项带分母来源、版本和未评估项。

- 新追溯/执行输入采用可选契约；空集合、无适用项和输入缺失分别表达，不能全部返回0%或100%。
- 验收：模型覆盖100%但需求基线缺失时，需求覆盖显示未评估；全量设计但未执行时不显示测试通过；重复证据不重复计数。
