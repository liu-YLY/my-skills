# 防御性测试点反推方法

> **何时阅读**：步骤 5 完成报告后，反推防御性测试点时加载本文件。
> **覆盖范围**：反推流程 / 5 类测试点检查清单 / 优先级 / 与 test-case-engineer 的转交规则。

## 1. 反推流程

```
根因 → 风险点 → 防御性测试点 → 优先级标注 → 清单输出
```

### 1.1 根因 → 风险点

对每个根因回答：「若此根因再次出现（或以变体形式出现），哪些场景会出问题？」

- 列出根因涉及的缺陷模式（见 [bug-patterns-index.md](bug-patterns-index.md)）。
- 对每个模式识别可能触发的同类场景，输出风险点清单，每条标注关联根因。
- 示例：根因「订单服务缺少幂等校验」→ 风险点：支付回调重复处理、库存重复扣减、消息重复消费。

### 1.2 风险点 → 防御性测试点

对每个风险点按第 2 节 5 类逐一设计。不要求每类都生成；只保留有根因依据、可执行的测试点。

### 1.3 优先级标注

| 优先级 | 判定标准 | 处理时效 |
|--------|---------|---------|
| P0 | 直接关联根因，且影响核心功能/数据安全 | 发布前必须通过 |
| P1 | 关联根因的同类风险点，影响重要功能 | 本迭代内完成 |
| P2 | 间接关联根因，影响边缘场景 | 排入 backlog |

### 1.4 清单输出格式

```markdown
## 防御性测试点清单

| 编号 | 测试点 | 关联根因 | 优先级 | 来源 |
|------|--------|----------|--------|------|
| DT-01 | [可执行的测试点描述] | [关联根因] | P0/P1/P2 | 根因反推 |

> 完整用例生成请转交 test-case-engineer skill。
```

## 2. 5 类防御性测试点

### 2.1 边界值测试点

**适用根因**：数值计算错误、字符串长度/数组越界、时间窗口/过期判断、分页/批次边界。

- 最小值（0、空、负数）与最大值（Int 上限、字段长度上限）是否被正确处理。
- 边界值 ±1（如 age=17/18/19、amount=0.00/0.01）是否被正确处理。
- 临界条件切换（刚好达到/刚好超过阈值）是否符合预期。
- 时间边界（00:00:00、23:59:59、跨天/月/年）是否被正确处理。

### 2.2 异常输入测试点

**适用根因**：输入校验缺失、类型转换错误、空值处理、格式校验缺失。

- Null / 空字符串 / 空数组是否被正确处理。
- 类型错误与格式错误是否被拒绝。
- 特殊字符（SQL 注入、XSS、Unicode 控制字符）是否被过滤。
- 超大输入是否被截断或拒绝；第三方返回异常数据是否有兜底。

### 2.3 并发测试点

**适用根因**：竞态条件、幂等缺失、锁失效/死锁、缓存击穿/雪崩。

- 相同请求并发 N 次（N=10/100/1000）是否保持幂等。
- 同一资源并发读改写是否有锁保护；不同请求操作同一账户/订单是否有序。
- 缓存失效瞬间大量请求穿透到 DB 是否有保护。
- 分布式锁失效/超时是否降级；死锁是否被检测。

### 2.4 资源测试点

**适用根因**：内存泄漏、连接泄漏（DB/HTTP）、文件句柄泄漏、磁盘/内存耗尽、资源未及时释放。

- 长时间运行（如 24h）后内存占用是否稳定。
- 异常路径下资源是否被释放（try-finally / try-with-resources）。
- 高并发下连接池是否被耗尽。
- 大文件/大数据量是否 OOM；磁盘满或配额上限时是否优雅降级/拒绝。

### 2.5 状态测试点

**适用根因**：状态机转换错误、流程顺序错误、状态回滚缺失、事务边界错误、中间状态可见性。

- 非法状态转换（如「已取消」→「已支付」）是否被拒绝。
- 重复操作（如重复支付）是否被正确处理。
- 部分失败时事务是否回滚；中间状态对外可见性是否符合预期。
- 状态机并发转换（同一订单同时取消和支付）是否有锁保护；长时间停留中间状态是否有超时处理。

## 3. 与 test-case-engineer 的转交规则

**触发条件**：用户明确要求完整用例或步骤级落地；测试点清单已生成，且每点标注「关联根因」与 P0-P2 优先级。已有授权内连续转交；范围变化、缺关键资料或未授权写操作时暂停。

**转交内容**：防御性测试点清单 + 根因分析报告 + 修复方案摘要（用于设计反向验证）。

**转交话术**：

```
bug-analyzer 已完成防御性测试点反推，输出清单如下（编号/测试点/关联根因/优先级）。
请 test-case-engineer：①将每个 DT 展开为完整用例；②优先展开 P0；
③为修复方案设计反向验证用例；④设计回归用例覆盖关联功能。
```

**反模式（不要做）**：

- 直接展开为完整用例：本 skill 只输出测试点清单。
- 测试点无关联根因或无优先级：必须可追溯并标 P0/P1/P2。
- 描述模糊（如「测试并发」）：必须可执行，如「同一业务幂等键并发 100 次，仅一次有效副作用；响应按契约核对」。

**边界与降级**：test-case-engineer 未安装时声明「完整用例生成能力不可用」；用户仅要根因时只输出测试点不转交；P0 测试点超过 10 个时提示聚焦核心风险。
