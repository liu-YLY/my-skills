# Bug 根因分析报告模板

> **何时阅读**：步骤 5 生成报告时加载本文件，按字段定义逐项填写。
> **覆盖范围**：报告字段定义 / 填写规范 / 转交规则。完整报告示例见 [report-examples.md](report-examples.md)。

## 1. 报告字段定义

| 字段 | 是否必填 | 内容说明 | 来源步骤 |
|------|---------|---------|---------|
| Bug ID / 标题 | 必填 | 缺陷跟踪系统 ID 或一句话简短描述 | 用户输入 |
| 现象 | 必填 | 一句话描述 Bug 表现，禁止模糊词（如"功能不正常"） | 步骤 1 |
| 环境 | 必填 | dev/test/staging/prod + 版本号 + 构建号 | 步骤 1 |
| 复现率 | 必填 | 100% / 偶发 X% / 无法复现 | 步骤 1 |
| 附件/日志 | 选填 | trace id / 日志片段 / 截图链接 | 步骤 1 |
| 复现步骤 | 必填 | 编号步骤，含操作 + 期望 + 实际 | 步骤 1 |
| 隔离结论 | 必填 | 异常首次出现位置 + 调用链证据 + 对照缺陷模式 | 步骤 2 |
| 根因 | 必填 | 已确认根因／候选原因／证据不足，附依据与未验证事项 | 步骤 3 |
| 验证结论 | 必填 | 实际执行结果、未执行部分及原因，不编造修复验证 | 步骤 4 |
| 修复建议 | 必填 | 紧急修复 + 长期改进 + 预防措施（三档） | 步骤 5 |
| 影响范围 | 必填 | 受影响功能 / 数据 / 用户 | 步骤 5 |
| 回归测试 | 必填 | 必测场景 + 关联功能清单 | 步骤 5 |

## 2. 字段填写规范

- **现象**：一句话含「什么操作 + 触发什么异常 + 什么条件」；禁止"功能不正常/有 bug/出错了"。示例：「提交同一订单后，账本出现两笔扣款；是否与重试有关待验证」。
- **复现率**：100% 必现；偶发 X% 需至少 10 次试验并附触发条件（如并发 >50）；无法复现需注明已尝试与未覆盖场景。
- **复现步骤**：编号列出，每条一个操作，必须含「期望结果 vs 实际结果」；偶发 Bug 标注重复次数或前置条件。
- **隔离结论**：异常首次出现位置（组件/服务/模块/方法）、每个边界的输入输出（脱敏）、对照 [bug-patterns-index.md](bug-patterns-index.md) 说明模式类别。
- **根因**：直接原因（精确到文件/行号/配置项）+ 深层原因（流程/规范/架构）；保留关键追问链或维度证据；无深层原因证据时标未确认，不推断流程或人员责任。
- **验证结论**：记录验证用例、修复方案和实际完成的复现/假设验证/修复复测/回归；未执行项目写明原因，仍可交付诊断报告。验证环境约束三态：
  - 同一数据、配置、缓存、时序、负载下完成可恢复对照且结果支持假设 → 「实验复现确认」。
  - 补丁命中范围或实验条件不明、阴性样本不足 → 「因果验证不充分」，不据此证伪或宣布多根因。
  - 生产用影子流量/A-B 桶/观察性验证 → 「因果链由观察数据佐证而非实验复现」。
- **修复建议（三档必填）**：
  - 紧急修复：24h 内止血，可立即执行，如「回滚至 v1.2.3」「关闭特性开关 X」。
  - 长期改进：涉及模块 + 预估人天，如「订单服务增加幂等校验，2 人天」。
  - 预防措施：落到 CI/监控/lint/测试用例编号，如「新增 lint 规则 R-001」「告警阈值：错误率 >1%」。
- **影响范围**：受影响功能（基于调用链与数据流）、受影响数据（表/记录数/修复脚本编号）、受影响用户（全量/灰度桶/角色与比例）。
- **回归测试**：修复后必测场景 + 可能受影响的关联功能清单（基于依赖关系）。

## 4. 与 test-case-engineer 的转交规则

完成报告输出后，仅在用户要求完整用例或步骤级落地时转交；仅要求根因或测试点时交付已有成果。

- **触发条件**：步骤 4 已记录验证状态与缺口；报告已披露且现有授权覆盖完整用例生成；防御性测试点清单已生成（见 [defensive-test-points.md](defensive-test-points.md)）。
- **转交内容**：根因分析报告 + 防御性测试点清单（编号/测试点/关联根因/优先级）+ 修复方案摘要。
- **转交话术**：

```
bug-analyzer 已完成根因分析，输出：报告全文、DT-01..DT-N 测试点清单、紧急/长期/预防三档修复方案。
请 test-case-engineer：①将每个测试点展开为完整用例；②在已授权隔离环境设计条件一致的反向验证，
未稳定复现时输出证据缺口和下一项最小验证；③设计回归用例覆盖关联功能。
```

- **边界与降级**：用户未明确要求完整用例时仅输出测试点清单；test-case-engineer 未安装时声明「完整用例生成能力不可用」。
