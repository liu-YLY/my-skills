# 前端测试准备

按“轻量导航索引 → 单需求映射 → 运行页面核实”补齐测试上下文。日常需求默认按任务刷新相关条目；首次接项目建立轻量目录，用户明确要求全量维护时才遍历全部受影响模块。代码分析成果可独立交付；运行条件不足只阻塞运行核实。

## 输入、证据与授权

先读仓库适用的 AGENTS.md、项目说明和已有索引，确认仓库、需求范围及来源版本。设计稿记录页面或节点及版本。已提供的信息不重复询问，能从材料和代码查到的先查；缺失规则提出具体问题，不编造预期。

每项关键结论区分以下证据状态：

- **代码推断**：注明提交、文件位置及符号，以及依赖运行配置或服务端的条件。
- **运行已验证**：注明亲自观察的事实、环境、角色、部署版本状态、核实时间及脱敏证据，只覆盖实际观察范围。
- **待确认**：说明缺失信息、冲突或未执行原因，以及核实办法。

正确预期与当前实现分列。关键断言引用需求条款、设计节点或用户确认；代码、已有测试、录制步骤和当前行为仅说明现状，不能自动成为验收标准。设计稿未描述的权限和业务规则不自行补出。发现冲突时保留双方证据，询问具体规则，不弱化断言、隐藏失败或把跳过、阻塞、未执行记为通过。

本 Skill 不授予业务写入、数据创建清理、账号变更、Jira、生产操作或安装依赖权限。运行核实和其他动作均遵循当次授权，测试环境也不意味着可修改数据。全局 Skill 只保存通用方法和模板；项目索引、账号标识、凭据、令牌及客户数据不写入全局 Skill，项目产物与附件只保存必要的脱敏信息。

## 一、分层索引与按需读取

主索引默认位于 `<仓库根目录>/docs/testing/frontend-navigation.md`。用户或仓库另有约定时遵循该约定并报告实际位置。同名文件先读后改，保留用户补充，不覆盖无关资产。仓库不可写时在任务工作目录保留相同相对结构并说明原因；没有可写位置时在答复交付。

大项目默认分层，按实际模块命名，仅创建本次有内容的文件：

```text
docs/testing/
├── frontend-navigation.md       # 模块目录、链接、覆盖范围和导航发现版本
└── frontend-index/
    └── 模块标识.md              # 该模块的页面条目、依赖与增量基线
```

- **主索引**只保存模块标识、检索关键词、源码范围、模块文件相对链接、覆盖状态及导航发现的提交/时间，不堆全部页面、依赖或用例。小项目内容少时可暂用单文件，后续拆分仍保留此入口。
- **模块索引**默认位于 `<仓库根目录>/docs/testing/frontend-index/模块标识.md`，保存模块扫描范围、已检查提交基线、相关未提交文件的内容指纹，以及每个页面的路由/参数、菜单或其他入口、组件、前端守卫/开关、接口、相关测试、已追踪的共享依赖和证据状态。页面使用模块内稳定唯一标识，显示名称或路由改变时保留标识和旧别名；另记代码有效性检查提交与最后深入读取提交。前者表示已处理该页及已追踪依赖的相关差异，后者表示实际深入读取，未深入条目如实标注。重复的共享守卫/接口说明集中记录，页面保留依赖路径及引用，不复制长说明；跨模块重复明显时才增加共享索引并在主入口登记。
- **需求准备记录**保存本次数据方案、步骤、检查点、正确预期及依据、证据和未决项；与可复用索引分开，按项目约定或任务目录保存。

首次通过目录、路由、菜单、权限守卫、接口封装和测试文件建立轻量地图，只深入本次需求相关页面，不为完整依赖图通读全仓。优先使用文件列表与文本搜索，排除依赖目录和生成产物。索引按实际技术结构组织，不固定框架；动态路由、微前端、跨仓库或服务端菜单记录连接点、未读取范围及待确认项。路由存在不证明可访问，搜索未命中不证明功能不存在。

读取时先查主索引，再搜索页面名、路由或变更文件，读取命中模块与必要段落。长模块文件可按实际子模块再拆，并更新入口链接；不一次加载所有模块。已有单文件索引按需迁移，保留有效内容、用户备注和来源版本，修正引用，不因拆分把旧结论标为新验证。

## 二、按变更增量维护

1. **取得完整差异范围**：先取文件名与状态清单，按检查基线分组比较到当前提交，合并暂存、未暂存和相关未跟踪源文件，不只看最近一次提交。选中页面优先使用其代码有效性检查提交，缺失时回退到模块基线；导航与待处理影响仍按各自范围的基线检查，避免因其他页待更新而反复刷新已处理页面。可用只读的 `git diff --name-status -M 基线提交 HEAD`、`git diff --name-status`、`git diff --cached --name-status`、`git ls-files --others --exclude-standard`。上次含未提交改动时，也比较已记录路径的当前内容指纹，捕捉变化或撤销。相同基线的差异清单只取一次；未选中更新范围时不读取全部 diff 正文。
2. **定位并扩展影响**：用变更路径搜索模块索引的关联文件，再沿实际引用追踪调用者。共享组件、状态、接口、权限或开关变化时扩展到关联页面；路由/菜单发现逻辑变化时复核相关导航目录，新增模块加入主索引。未深入或未索引部分不能据此排除影响；动态依赖或边界不明时扩大到有关模块并标注不确定性。
3. **按任务决定刷新范围**：日常需求只深入本次页面及判断其行为所需的共享依赖；其他受影响页面登记为待更新，不为了推进基线顺手深入。用户明确要求维护全部索引时，再逐模块处理剩余影响。相关源码和已追踪依赖没有变化、覆盖足以支持本次问题时复用代码上下文；缺少依赖信息则补查，不能只凭页面文件没变认定可复用。需求或设计稿改变仍重做预期映射。新增入口先补导航定位，重命名保留标识及别名，已确认删除的入口和失效链接清理后保留必要历史备注。
4. **诚实推进基线**：记录比较范围、受影响页面及原因、更新/复用条目和遗留影响。某页及已追踪依赖的相关差异处理完可推进该页有效性检查提交，不必等待其他页；深入读取版本仅在实际深入时更新。某模块覆盖范围内全部相关差异处理完才推进模块基线，否则保留旧基线和待处理清单。导航发现、模块检查、页面有效性与深入读取版本分开，更新主文件不等于所有页面已重查。
5. **缺失基线时回退**：提交不可访问、索引缺少依赖信息或大范围重构时，先重建有关模块的轻量索引；仍不能划定边界才扩大到全仓导航扫描，并说明原因。非 Git 项目可比较文件清单和内容指纹，无可靠基线时不宣称增量无遗漏。全仓导航扫描也不要求深入全部页面实现。

每次交付简短列出复用、更新、待更新的页面及原因，并记录实际读取范围；不反复附上未改变的模块全文，不声称未经测量的 token 节省比例。待更新清单只存当前未解决影响和来源版本，处理后移除，避免长期累积完整提交日志。

代码索引复用不等于运行结论可复用。历史运行证据保留原状态、环境和时间，另列“对本次任务的适用性”。部署、服务端菜单、权限、账号、数据或环境配置变化时，将本次适用性标为待确认并重新核实，不改写历史事实；即使没有变化，也不能把旧观察写成本次已执行。无代码差异不证明环境未变。

## 三、把单需求映射到执行上下文

从需求中的名称、文案、字段、操作及设计线索定位页面，沿“路由/菜单 → 页面及子组件 → 事件/状态/条件 → 接口”追踪。检查展示与禁用条件、权限、开关、状态转换、参数来源、请求/响应、空态和错误态；已有测试用于发现约束与缺口。

交付以下信息，引用代码位置并标注证据状态：

- **入口**：菜单、路由、参数与跳转来源，区分候选入口与实际核实结果。
- **前置条件**：角色、权限、开关与数据状态；前端权限键不能证明后端授权，隐藏按钮不能证明后端禁止操作。
- **数据方案**：最小字段、状态、关联对象、查找现有数据的办法，以及必要的创建/清理建议和授权状态。区分方案已列出与数据已就绪，不猜真实账号或服务端记录。
- **步骤**：从进入页面开始，写明目标、动作、定位线索和观察点，标出有业务副作用的动作。
- **检查点**：列前置状态、动作、正确预期及需求/设计/确认依据、当前实现证据。缺失规则列待确认，不用代码现状补出预期。

动态菜单、后端权限、真实身份、租户配置和服务端数据必须通过合适来源确认，不能仅靠前端代码。

## 四、运行页面核实

实际浏览器工具、测试环境、身份和当次允许操作明确后才进入此阶段。缺少条件时保留索引与需求准备记录，明确“运行未验证”、原因和后续步骤，不虚构调用、截图或执行结果。

1. 核实入口可达、当前身份/租户、菜单、权限、开关与数据状态，不绕过守卫或擅用他人身份。
2. 用可靠构建标识、部署元数据或确认的发布记录对应代码提交；未知时写“部署版本待确认”，页面外观相同不证明版本一致。记录实际核实时间，不能把提供方的旧时间当作本次核实时间。
3. 在授权范围内观察页面及接口结果；保存、提交、删除等写入动作先核对当次授权，无授权则只交付步骤与阻塞项。保留与需求不符的实际结果。
4. 索引、源码与部署不一致时停止沿用旧映射，能查到对应代码或发布说明则重新映射，否则询问目标版本。其他版本的运行观察不能证明本次源码验收通过。

实际检查结果使用“通过、失败、阻塞、未执行”，与三类证据状态分列；只有实际执行且有预期依据时判通过/失败。准备完成或页面可达不代表业务测试通过。

## 五、交接给 Codex 页面操作

使用 [索引与交接模板](references/handoff-template.md) 按范围生成产物，交付主索引实际路径、相关模块链接和需求准备记录。后续可直接使用 Codex 操作页面，无需执行 Skill：明确要求先读主索引及相关条目、核对版本、必要时调用本 Skill 增量更新，再按用例及需求预期执行。

后续任务须能访问仓库或索引文件。保存索引不会自动使所有新会话读取它；项目需要默认读取约定时可建议写入项目 AGENTS.md，但不擅自修改项目或全局指引。交接保留当次授权范围与待补条件，不因索引存在扩大操作权限。

## 调用示例

“用 $frontend-test-preparation 阅读当前前端仓库，为附件需求‘列表支持按状态筛选’准备测试。已有索引则增量更新，大项目按模块保存。先做代码分析；环境和账号尚未提供。”

输出主索引与相关模块、候选入口及代码位置、角色/开关条件、两种状态的数据方案、筛选步骤、依据需求的检查点和待确认项，并明确“运行未验证”。此处筛选仅为示例。
