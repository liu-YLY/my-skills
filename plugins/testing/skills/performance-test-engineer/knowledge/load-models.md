# 负载模型

> **何时阅读**：设计负载，或诊断到达率与预期不符时。

## 1. 负载形状与到达方式

阶梯、峰值和疲劳描述负载随时间如何变化；容量描述测试目标。另按业务选择到达方式：

- **封闭**：固定或逐步调整用户数，每个用户结束上一轮才开始下一轮。变慢会压低迭代发起率，适合模拟固定用户群。
- **开放**：按外部节奏安排新迭代，计划发起与上一轮何时完成无关。适合模拟外部到达量，实际发起仍受可用执行资源限制。未发起要记录，先核对发压资源、调度和服务变慢是否占满执行资源。

下文数字仅作设计示例，按业务周期、基线和停止条件确定。

| 模型 | 核心目标 | 典型时长 | 关键产出 |
|------|----------|----------|----------|
| 阶梯递增 | 找性能拐点 | 30-90 分钟 | 拐点并发数、拐点 TPS |
| 峰值 | 验证瞬时冲击承受力 | 5-15 分钟 | 崩溃阈值、恢复时长 |
| 疲劳 | 暴露泄漏与慢查询累积 | 8-24 小时 | 内存/连接增长曲线 |
| 容量 | 量化最大处理能力 | 1-4 小时 | 最大 TPS、最大并发用户 |

## 2. 阶梯递增（Ramp-up / Step Load）

**定义**：逐档提高用户数或计划到达率，观察性能变化。

| 项 | 内容 |
|----|------|
| 适用场景 | 找出系统性能拐点、容量规划、回归测试 |
| 不适用场景 | 验证峰值承受能力（用峰值模型）；长期稳定性（用疲劳模型） |
| 参数示例 | 起始 10 用户，每 2 分钟增加 20 用户，持续到 TPS 下降或 RT 超阈值 |
| 典型时长 | 30-90 分钟 |
| 风险点 | 阶梯步长过大可能跳过拐点 |

**执行要点**：
每档达到预定稳态后采数，临近拐点缩小步长。按已确认 SLA 与环境保护条件停止并记录。

## 3. 峰值（Spike）

**定义**：短时间内施加远超日常的瞬时负载，观察系统是否崩溃及恢复能力。

| 项 | 内容 |
|----|------|
| 适用场景 | 秒杀活动、突发流量、容灾验证 |
| 不适用场景 | 测容量上限（用容量模型）；长期稳定性（用疲劳模型） |
| 参数示例 | 日常 500 QPS，峰值 5000 QPS，持续 30 秒后回落到日常 |
| 典型时长 | 5-15 分钟（含恢复观察期） |
| 风险点 | 忽略恢复期观察，漏测雪崩 |

**执行要点**：
按业务峰值的幅度和持续时间施压，回落后观察延迟、错误率和资源恢复。

## 4. 疲劳（Soak / Endurance）

**定义**：在预期生产负载下长时间运行，检测内存泄漏、连接泄漏、慢查询累积。

| 项 | 内容 |
|----|------|
| 适用场景 | 上线前稳定性验证、内存泄漏检测、慢查询暴露 |
| 不适用场景 | 找拐点（用阶梯）；测峰值（用峰值） |
| 参数示例 | 日常 500 QPS，持续 8-24 小时 |
| 典型时长 | 8-24 小时 |
| 风险点 | 时长不足暴露不了泄漏；环境不一致导致结果失真 |

**执行要点**：
按业务持续周期、资源增长速率和重启/GC 周期选时长与负载。持续采集资源、慢查询和事件日志，按事件尺度选频率。内存增长需核对 GC 后存活量、数据量及稳定基线。

## 5. 容量（Capacity）

**定义**：持续施加负载找到系统最大处理能力（最大 TPS / 最大并发用户）。

| 项 | 内容 |
|----|------|
| 适用场景 | 容量规划、扩容决策、SLA 谈判 |
| 不适用场景 | 稳定性验证（用疲劳）；瞬时峰值（用峰值） |
| 参数示例 | 从 100 并发起，每 5 分钟增加 50，直到错误率 > 1% 或 RT 超阈值 |
| 典型时长 | 1-4 小时 |
| 风险点 | 单接口容量不等于系统容量；忽略依赖方瓶颈 |

**执行要点**：
按预定稳态、目标和保护条件找最大通过档与首个失败档，记录原因和依赖瓶颈。只有目标涉及整体容量时才用有依据的混合流量，单接口结果限定在该入口。
