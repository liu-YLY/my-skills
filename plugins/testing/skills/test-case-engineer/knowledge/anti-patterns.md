# 反例黑名单（不要做什么）

> SkillLens 论文实证：只写「应该做 X」没有「不要做 Y」会降低 LLM judge 准确率。对照 [writing-rules.md](writing-rules.md) 执行。

## 工作流与输出

| # | 反模式 | 替代做法 |
|---|--------|----------|
| 1 | 跳过阶段 1 直接写用例 | 至少压缩输出需求理解，快速模式也不例外 |
| 2 | 跳过阶段 2 直接写用例 | 必须输出测试点清单，阶段 3 基于清单生成 |
| 3 | 把 AI 来源标签当作人工审核证明 | 来源标 ai-generated，人工审核状态单列 not-reviewed |
| 4 | 用例中使用模糊词 | 替换为具体数值或明确描述 |
| 5 | 业务结果缺失或关键节点不可定位 | 补业务结果及必要检查点 |
| 6 | 单条用例覆盖多个测试逻辑 | 拆成独立用例，每条只验证一个逻辑 |
| 7 | 用位置描述代替元素名称 | 用具体按钮名、输入框名 |
| 8 | expected_results 仅写「正确」「正常」 | 引用实际 UI 文案或具体数值 |
| 9 | 缺少必填字段 | 补齐 ID/标题/优先级/类型/步骤/预期 |
| 10 | title 过长且未记录例外 | 精简为「对象 - 行为」；信息不可删时保留并记录原因 |
| 11 | 因步骤数量机械拆分 | 按业务目标、分支和失败隔离定粒度 |
| 12 | ID 重复或格式不规范 | 用 `TC_{模块}_{功能}_{三位序号}` |
| 13 | steps 使用占位话术 | 写具体操作：输入 xxx、点击 xxx、查看 xxx |
| 14 | 测试点缺少操作路径 | 测试点必须含 [验证对象] + [操作/场景] + [预期结果方向] |
| 15 | 用一张表罗列全部用例 | 每条用例用 `### TC_模块_功能_序号: 标题` 块承载；表格只在块内展开同构数据行 |

## 可读性与信息密度

| # | 反模式 | 替代做法 |
|---|--------|----------|
| 1 | 步骤复述前置条件、无信息量导航、解释性文字混入 | 删除；导航只保留被测行为，原因移到业务背景 |
| 2 | 操作与验证混写 | 操作写步骤，结果写预期 |
| 3 | 预期写评价或愿望 | 写「在哪里 + 看到什么 + 什么值/状态」 |
| 4 | 标题用抽象名词或「验证」开头 | 用「对象 - 条件 - 预期行为」 |
| 5 | 整段文字替代编号步骤 | 拆成编号步骤，一步一个动作 |
| 6 | 一步堆叠多个决策点 | 按决策点拆步 |
| 7 | 编号或括号多层嵌套 | 编号不超过 3 层，括号不套括号 |
| 8 | 正文写测试黑话或底表列名裸奔 | 换成业务动作与概念（「输入 21 字」而非「验证边界值」；「年付总额度 100」而非 `ssdays=365, up_to=100`） |
| 9 | 套话、防作弊免责说教与取证动作占篇幅 | 删除 `无其他阻断`/`已记录快照`/`不用…代替`/`另验`/`不计入` 及业务结果 `步骤 1：` 前缀 |
| 10 | 外置 `test-data` 暗号表跨文件拼图 | 具体输入值与初始状态直接内联在单条用例内，禁止写 `使用夹具 M4`/`见数据表 S1` |

## 范围、测试点与拆分合并

| 类别 | 反模式 | 替代做法 |
|------|--------|----------|
| 范围 | 把基础设施故障当业务异常，或虚构未交付夹具 | 需求要求容错且环境已交付才写；禁编服务宕机/断网及「隔离 Stub/可控服务端时钟」 |
| 范围 | 同一兜底逻辑按底层状态码机械裂变 | 下游 400/429/503 走同一失败处理分支时只留 1 条代表性用例 |
| 范围 | 不可达脏数据或把查配置/问口径写成用例 | 禁假设手工改库造矛盾状态；查配置/确认口径归入准备或「原文问题清单」 |
| 范围 | 每个字段都展开全套边界值，或同一阈值正反各写一条 | 只对「需求给阈值 + 本次改校验」的字段取一组三点，写清临界内/临界/临界外 |
| 范围 | 非重点内容写全流程用例 | 回归项最多 1 条冒烟，不写检查点 |
| 范围 | 顺带发现的问题写成用例 | 记入「原文问题清单」或缺陷 |
| 范围 | 用例数多当作覆盖全 | 先过范围闸门，再核对测试点覆盖 |
| 测试点 | 验证 XXX 可以点击/正常/可以关闭 | 写明操作行为、具体表现、关闭后的状态与业务影响 |
| 测试点 | 堆叠多个验证目标 | 每条测试点只验证一个核心目标 |
| 拆分 | 过度原子化 | 同一操作的多结果用软断言合并为一条 |
| 拆分 | 合并独立业务目标或为减少数量合并无关目标 | 同一目标可跨层取证，独立目标按业务拆分 |
| 拆分 | 无条件分支合并（if/else） | 按分支拆成独立用例 |
| 拆分 | 忽视失败依赖 | 停止依赖路径，独立结果继续汇总 |
| 拆分 | 合并昂贵前置准备不注释原因 | 在用例注释说明合并原因（如「前置数据需 30 分钟批处理」） |

## 触发检查时机

阶段 1 查工作流 1–2；阶段 2 查范围（越界项在此剔除）；阶段 3 输出前查格式、可读性与测试点；阶段 4 全查。

> Bug 根因分析与缺陷定位已迁移至 bug-analyzer skill。
