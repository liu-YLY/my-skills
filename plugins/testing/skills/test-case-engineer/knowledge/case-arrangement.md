# 用例编排与排序规范

> **何时阅读**：阶段 3 输出完整用例集前必读；只编写单条用例时无需阅读。
> **覆盖范围**：编排策略决策、用户旅程编排、模块化分组编排、通用排序规则。
> **与 writing-rules.md 的关系**：编排规则从写作规则中拆出，编写铁律仍在 [writing-rules.md](writing-rules.md)。

## 用例编排与排序规范

用例输出必须遵循统一的编排顺序，禁止随机罗列。编排策略二选一，**默认采用策略一**。

### 策略决策规则

| 条件 | 采用策略 |
|------|----------|
| 默认：单一功能 / 单页面 / 单模块，预计用例 ≤ 50 条（参考阈值） | 策略一：用户旅程编排 |
| 满足任一：可按关联性划出 ≥ 3 个功能模块 / 预计用例 > 50 条 / 涉及多角色、多页面或跨系统 | 策略二：模块化分组编排（组内仍按策略一） |

### 策略一：用户旅程编排（默认）

按真实用户使用被测功能的端到端操作时序（用户旅程，User Journey）排列用例，使执行顺序与功能生命周期（CRUD Lifecycle）一致：

| 顺序 | 旅程阶段 | 覆盖内容 |
|------|----------|----------|
| 1 | 入口与到达 | 进入页面 / 打开弹窗 / 导航到功能入口 |
| 2 | 初始状态与默认值 | 首次加载的页面展示、默认配置、空数据态 |
| 3 | 创建（Create） | 新增 / 提交 / 保存 |
| 4 | 查询与展示（Read） | 列表展示、详情查看、搜索筛选 |
| 5 | 编辑（Update） | 修改 / 更新 / 保存后生效 |
| 6 | 删除（Delete） | 删除 / 移除 / 停用 |
| 7 | 恢复（Restore） | 回收站还原 / 撤销 / 重新启用（仅当需求存在该能力） |
| 8 | 辅助操作 | 取消 / 返回 / 刷新等辅助行为 |

**规则**：
- 需求仅覆盖部分阶段时按实际裁剪，保持相对顺序不变
- 每个阶段内部：先正向（Happy Path）后反向（异常 / 边界 / 权限），同级按优先级 P0 → P3
- 用例 ID 的功能缩写与旅程阶段对应（如 `ADD` / `QUERY` / `EDIT` / `DEL` / `RESTORE`），同阶段内序号连续

### 策略二：模块化分组编排（需求庞大时）

按**功能内聚性（Functional Cohesion）**将需求划分为若干功能模块，模块间独立成组，组内再按策略一（用户旅程）编排。

**模块划分依据**（功能关联性判定，满足任一即归入同一模块）：
- 数据依赖：操作同一数据实体（同表 / 同对象 / 同配置项）
- 状态联动：存在状态流转的上下游（A 的状态变化触发 B 的行为）
- 交互流连续：处于同一条用户操作路径上的连续功能
- 角色与信息架构：同一角色使用或同一页面族内的功能

**模块间排序**：按依赖关系拓扑排序，被依赖的上游模块在前（如：配置模块 → 业务模块 → 报表模块）；无依赖关系的模块按主用户旅程的先后排列。

**输出结构**：模块以分组标题呈现，示例如下：

```markdown
## 模块 1：告警渠道配置
（组内按用户旅程：入口 → 创建 → 编辑 → 删除）

### TC_ALERT_CHANNEL_ADD_001: ...

## 模块 2：告警规则管理
（组内按用户旅程）

### TC_ALERT_RULE_ADD_001: ...
```

**规则**：
- 模块划分粒度以「组内用例共享前置数据、可连续执行」为宜，避免过碎
- 用例 ID 的模块缩写与分组一一对应（如 `ALERT_CHANNEL` / `ALERT_RULE`）
- 跨模块端到端流程用例置于其依赖的模块之后，独立成组（如「模块 3：端到端流程」）

### 通用排序规则（两策略均适用）

1. 功能用例在前；performance / security / compatibility 等非功能类型独立成组追加在末尾（见 [test-levels.md](test-levels.md)「默认输出功能测试用例」）
2. 编排顺序不因生成批次打乱：阶段 4 自检补充的用例按归属插入对应模块 / 旅程阶段，禁止整体追加在末尾
3. 输出用例集时在开头声明所用编排策略（一句话，如「本用例集按用户旅程编排」或「按模块分组 + 组内用户旅程编排」）

## 用例集预算与等价场景合并

用例数量按功能复杂度设软预算；超出时在用例集开头写明理由（风险、监管、多角色等），不把预算当硬性扣分或质量门槛。

| 复杂度 | 判定依据 | 用例数预算 |
|--------|----------|-----------|
| 单字段纯校验 | 单字段、无跨模块联动、无状态机、无资金属性 | ≤8 条 |
| 常规单功能 | 单功能、少量规则约束、单角色主流程 | ≤15 条 |
| 多功能多状态 | 多规则相互约束、状态机、资金/权限/并发、跨模块联动 >2 处 | ≤25 条 |

预算按「用例集」计，不按模块或批次分别计数；参数化/紧凑表格组内每行仍算 1 条用例。

**合并优先于新增**：同一业务目标与同一条件的等价场景合并为参数化组；同一操作触发的多个紧密结果用关键检查点汇总，不拆成多条用例。合并后若无法指出「哪一步、哪个字段」导致失败，才拆分。

**输出前去重**：三轮生成或阶段 4 补充用例后，逐对检查标题、前置条件与关键输入；等价的合并，仅条件或数据不同的改为参数化行，不因来源不同保留重复用例。

**与紧凑表格模式的关系**：`writing-rules.md` 的紧凑表格适用于同构 P2/P3 数据组；本节的预算与去重适用于所有优先级用例，两者不冲突。

**与阶段 2 裁剪的关系**：`core.md` 的「裁剪说明」列记录哪些维度/字段未落为用例及理由；本节预算约束最终用例总数。裁剪不等于删需求，未覆盖的测试点仍须在输出中单列并写明原因。
