# 失败语义、安全属性与进展属性

> **何时阅读**：输入提供 `failure_semantics` / `safety_properties` / `progress_requirement`，或需要设计超时、重试、重复回调、部分成功、结果未知类用例时。
> **覆盖范围**：失败阶段判定、恢复用例条件、安全属性与进展属性的验证边界。
> **可跳过条件**：普通功能用例且不涉及失败语义或状态型属性时无需阅读。

## 失败阶段与不确定结果

状态机场景提供 `failure_semantics` 时原样消费；该对象可选，不要求历史用例迁移。
记录 `phase / allowed_states / forbidden_side_effects / observations / recovery_conditions / source / evidence_type`，
允许状态和恢复动作只引用已确认需求；缺契约时保留待确认场景，不编造幂等键、时限或补偿。

| 失败阶段 | 必查证据与结果边界 | 恢复用例条件 |
|---|---|---|
| 执行前拒绝 | 核对校验/授权响应与实际业务记录；哪些副作用禁止以契约为准 | 已确认无业务执行且拒绝原因可修正时按需求设计重试 |
| 提交前失败 | 核对事务/持久化边界、回滚及外部调用；不能凭客户端报错推定全部回滚 | 提交确未发生、外部结果已核对且重试条件已定义 |
| 提交成功但响应丢失 | 核对支付/订单/账本与第三方记录，结果可能已成功 | 先查实际结果，按真实幂等契约复用结果；禁止再次产生资金副作用 |
| 部分成功待补偿 | 分列各子操作结果与禁止重复的副作用；未定义补偿不自动生成 | 只验证需求规定的补偿入口、条件、权限和目标 |
| 结果未知 | 用业务查询、事件、日志或对账补证；未知状态与来源不可达分别记录 | 查清结果或取得已定义的恢复策略后再决定，不生成无条件重试 |

- 请求超时先核实业务结果，不能直接把未响应等同未执行、未支付或保持原状态。
- 重复回调验证一次有效业务结果与禁止副作用；HTTP成功次数、状态不变和资金操作次数分别观察。
- `allowed_states` 为集合时保留每个状态的条件；条件不足以唯一判定则列待确认，不把互斥结果并列为通过条件。
- 每条恢复用例独立写前置状态、观测、操作和可判定结果；不使用步骤内if/else代替多个路径。

## 安全属性与进展属性

按输入中的可选 `safety_properties` 与 `progress_requirement` 设计用例，不因对象有状态就默认适用。
安全属性保留 `id / statement / applies_to / source / verification_method / evidence_type`；每项以业务事实和可观察证据验证。

- 不重复资金操作：核对一次业务结果与账本/第三方副作用，不以状态未变代替副作用验证。
- 不越权：覆盖已确认角色/租户/对象权限，核对被拒绝业务动作及受保护数据；不发明角色或错误码。
- 不进入非法状态：用既有禁止转换及业务不变量判定；缺状态规则时标待确认。
- `progress_requirement` 保留 `required / allowed_terminal_states / applies_from_states / source / evidence_type`；只对需求要求结束的有限流程验证完成、明确失败或已定义恢复路径。
- 会员续订等允许周期循环的对象按需求排除进展要求；不能把所有环判Bug。
- 闭合状态集合无法到达允许终态只能形成结构检查结论；存在退出边不保证守卫可满足、环境会调度或时限内结束。
- 运行进展用例仅在需求规定触发事件/终态/时间依据时可执行；缺时限则不造SLA，标明结构结论与运行验证缺口。
