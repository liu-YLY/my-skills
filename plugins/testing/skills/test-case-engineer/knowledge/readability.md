# 人类易读性细则

> **何时阅读**：阶段 3 编写用例时，拿不准句式、结构或术语写法时查阅。要点与阈值已写入 [writing-rules.md](writing-rules.md)「句式与结构（要点）」，本文件提供完整规则、对照表与示例。
> **覆盖范围**：句长与句式 / 扫读结构 / 术语与用词 / 认知负荷 / 标点与数字。
> **依据**：`docs/test-case-human-readability-baseline.md`（ISO 24495-1、WCAG 3.1.5、中文技术写作惯例、扫读与认知负荷研究）。

## 句式：让一句话一次读懂

可读性首先是句子能不能一次解析。以下阈值为软预算，用于提示与改写，不作机械扣分。

**句长预算**：
- 逗号分隔的构件以 20 字以内为目标；20–29 字可接受；30–39 字须语义清晰；超过 40 字必须改写
- 单条步骤或预期不超过 100 字；超出时先删修饰，再拆句
- 拆分优先于压缩：拆成两步不丢信息，压成一句容易丢条件

**四条改写规则**：

| 规则 | 难读 | 易读 |
|------|------|------|
| 一句一个动作 | 点击「保存」并确认列表中出现记录 | 点击「保存」。列表出现「订单通知」记录 |
| 动词直用 | 对 Endpoint URL 输入框执行清空操作 | 清空「Endpoint URL」输入框 |
| 主动语态 | 提交请求被系统拦截 | 系统拦截提交请求 |
| 修饰不超过两层 | 在用于接收订单创建事件通知的 Webhook 配置弹窗中清空 Endpoint URL | 在「Add webhook」弹窗清空「Endpoint URL」 |

**指代与术语**：
- 「其」「该」「此」「这」必须有唯一指代；可能出现歧义时重复名词
- 一条步骤最多出现 1 个需要额外解释的术语；控件名称、产品原文、接口字段属于界面事实，不计入
- 首次出现的术语用一句话或括号解释；同一条用例内多次出现时只在首次解释
- 同一概念全文用一个词；界面本身有多个不同按钮时（如「保存」与「提交」），按界面原文区分，不视为同义词混用

**标点与数字**：
- 中文正文使用全角标点；英文原文、代码、字段值保留原样，不强制转换
- 数字、版本、金额在同一用例内保持同一形式；数值范围统一写 `1~2 天`
- 阿拉伯数字与英文单位之间留空格，如 `16 GB`、`200 ms`

## 结构：让人扫一眼就能定位

读者通常先扫标题，再扫步骤首词，最后看结果。结构服务于这条路径。

**固定顺序**：标题 → 元信息 → 前置条件 → 测试步骤 → 关键检查点 → 业务结果 → 后置条件 → 标签。不调换字段，不把检查点混进步骤。

**首词规则**：

| 位置 | 首词写什么 | 反例 |
|------|-----------|------|
| 标题 | 对象 + 条件，前 6–10 字可定位 | `关于 Webhook 的一些测试` |
| 步骤 | 动词：输入 / 点击 / 选择 / 打开 / 刷新 | `首先，我们需要…` |
| 预期 | 位置：页面 / 接口 / 表 / 缓存 / 消息 | `正确`、`成功` |

**就近原则**：
- 检查点紧跟对应步骤，写成 `步骤 2 后：…`；不集中到文末
- 同一动作的多条结果写在一起，不拆到不同段落
- 需要跨段引用时写步骤号，不写「如上」「见后文」

**分块与长度预算**（软）：
- 单条用例步骤超过 7 条时，按业务阶段分成若干组：每组前写一行阶段名（如 `准备`、`提交`、`校验`），组内编号连续，每组不超过 7 条；分块只改排版，不改变拆分判定
- 单条用例正文建议不超过 300 字（不含元信息）；超出时先删填充，再评估是否拆分
- 表格只用于同构对比（等价类、兼容矩阵、多组数据），不用于叙述流程；单元格不写超过 30 字的句子

**禁止**：
- 用整段文字叙述替代编号步骤
- 有序编号嵌套超过 3 层（`一、` → `（一）` → `1.` 即止）；用例正文一般只用一层
- 括号套括号；补充说明另起一句，或移到业务背景

## 术语与用词一致

同一动作、同一对象、同一概念，全文只用一个说法。执行人不需要判断「点击」和「点选」是不是两件事。

**动词首选**：

| 动作 | 首选 | 避免 |
|------|------|------|
| 单字段文本输入 | 输入 | 录入、键入 |
| 一组表单字段 | 填写 | 完善信息、录入资料 |
| 鼠标点击 | 点击 | 单击、点选、按一下 |
| 下拉框 / 单选框 | 选择 | 选中、点选 |
| 复选框 | 勾选 | 选择（与单选框混淆） |
| 打开页面或弹窗 | 打开 | 进入、跳转（「跳转」描述结果，不描述动作） |
| 重新加载页面 | 刷新 | 重新加载（界面原文如此时除外） |
| 关闭页面或弹窗 | 关闭 | 退出（「退出」用于会话或应用） |
| 等待状态出现 | 等待「保存成功」出现 | 稍等、等待加载完成 |

**对象称呼**：
- 首次出现用界面原文，后文沿用同一称呼；不自造简称，已定义的缩写除外
- 英文控件名保留原文（如 `Add endpoint`），不翻译、不混写中文别名
- 同一对象有多个叫法时（弹窗 / 对话框 / 浮层）选定一个，全文统一

**术语处理**：
- 业务术语首次出现时用一句话或括号解释；产品内部代号不写进用例，执行必需时在前置条件说明
- 新增术语前先检索同模块已有说法；不新造缩写

**环境与版本**：
- 影响执行或判定的环境事实写进前置条件，如 `- 运行环境：Chrome 120，构建 v2.3.1`
- 同一模块共用同一环境时写在模块级说明，不在每条用例重复
- 数据版本、时区、账号类型属于环境事实，影响判定时必须写明

## 认知负荷

**约束**（软）：
- 一步一个决策点：一次提交、一次跳转、一次状态切换；同一表单的字段可一并填写，但不得跨页面、跨判断分支
- 单步涉及字段建议不超过 5 个；超出时按字段组分步，如「基本信息」与「通知配置」
- 一条用例步骤建议不超过 7 条；超出先按「结构」节分块，再评估是否拆分
- 一条用例建议只使用 1 组主数据；需要对比多组数据时改用参数化表格
- 合并后若无法指出「哪一步、哪个字段」导致失败，说明粒度过粗，应拆分
