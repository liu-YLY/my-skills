# 人类易读性细则（按需）

> **何时阅读**：阶段 3 拿不准句式、结构或术语时查阅。要点与阈值已在 [writing-rules.md](writing-rules.md)「句式与结构」，本文件只提供对照表与示例。
> **依据**：`docs/test-case-human-readability-baseline.md`（ISO 24495-1、WCAG 3.1.5、中文技术写作惯例）。

## 句式改写四规则

| 规则 | 难读 | 易读 |
|------|------|------|
| 一句一个动作 | 点击「保存」并确认列表中出现记录 | 点击「保存」。列表出现「订单通知」记录 |
| 动词直用 | 对 Endpoint URL 输入框执行清空操作 | 清空「Endpoint URL」输入框 |
| 主动语态 | 提交请求被系统拦截 | 系统拦截提交请求 |
| 修饰不超过两层 | 在用于接收订单创建事件通知的 Webhook 配置弹窗中清空 Endpoint URL | 在「Add webhook」弹窗清空「Endpoint URL」 |

## 扫读结构

- 固定顺序：标题 → 元信息 → 前置条件 → 测试步骤 → 关键检查点 → 业务结果 → 后置条件 → 标签；不调换字段，不把检查点混进步骤
- 表格只用于同构对比（等价类、兼容矩阵、多组数据），不用于叙述流程；单元格不写超过 30 字的句子
- 禁止：整段文字代替编号步骤；有序编号嵌套超过 3 层（`一、`→`（一）`→`1.` 即止）；括号套括号

## 术语与用词一致

**动词首选**：

| 动作 | 首选 | 避免 |
|------|------|------|
| 单字段文本输入 | 输入 | 录入、键入 |
| 一组表单字段 | 填写 | 完善信息、录入资料 |
| 鼠标点击 | 点击 | 单击、点选、按一下 |
| 下拉框/单选框 | 选择 | 选中、点选 |
| 复选框 | 勾选 | 选择（与单选框混淆） |
| 打开页面或弹窗 | 打开 | 进入、跳转（「跳转」描述结果） |
| 重新加载页面 | 刷新 | 重新加载（界面原文如此时除外） |
| 关闭页面或弹窗 | 关闭 | 退出（「退出」用于会话或应用） |
| 等待状态出现 | 等待「保存成功」出现 | 稍等、等待加载完成 |

**对象与术语**：首次出现用界面原文，后文沿用；英文控件名保留原文（`Add endpoint`），不翻译、不混写中文别名；同一对象多个叫法（弹窗/对话框/浮层）选定一个；业务术语首次出现用一句话或括号解释；产品内部代号不写进用例；不新造缩写。

**环境与版本**：影响执行或判定的事实写进前置条件（`运行环境：Chrome 120，构建 v2.3.1`）；同模块共用的写模块级说明；数据版本、时区、账号类型影响判定时必须写明。

## 说人话：把术语翻成业务动作

**实现词换用户视角**（仅业务/UI 用例；接口契约与数据层用例按 writing-rules 写字段、状态码）：

| 不写 | 写 |
|------|----|
| 降级/熔断 | 暂时关闭「导出」，页面显示「服务繁忙」 |
| 链路/埋点 | 从下单到收到通知的整个过程 / 上报「保存成功」事件 |
| 鉴权/越权 | 未登录 / 用 B 账号打开 A 账号的订单 |
| 脏数据/兜底 | 上次没保存完的记录 / 出错时回到列表页 |
| 策略/机制/体系 | 删掉，直接说做什么 |

**判定问句**：① 把这条用例给一个没参与需求评审的人，他能否不追问就执行，并明确说出 pass 还是 fail？② 删掉这半句话（如默认正常废话、保存快照叮嘱、防作弊免责备注），懂基本常识的测试人员是否仍能准备数据、执行操作并判对错？能则立即删掉。

## 认知负荷

- 一步一个决策点（一次提交、一次跳转、一次状态切换）；同一表单字段可一并填写，但不跨页面、不跨判断分支
- 单步字段建议 ≤5 个，一条用例步骤建议 ≤7 条；超出先按字段组或业务阶段分块，再评估是否拆分
- 一条用例只用 1 组主数据；需要对比多组数据时改参数化表格
