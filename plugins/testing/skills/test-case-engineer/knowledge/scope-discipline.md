# 需求范围与用例取舍（场景淘汰门）

> **何时阅读**：阶段 2 提测试点后、阶段 3 落用例前必读（快速模式同）。

## 一、需求焦点三档与描述深度

判定唯一依据：**需求原文有没有这条，本次改动会不会改变它**。

| 档位 | 判定标准 | 用例待遇与字段深度 |
|------|----------|--------------------|
| **焦点** | 需求明确新增/修改/删除的行为，有原文出处 | **写透**：完整覆盖正反向，按需多步、就近设关键检查点、改状态必填后置条件 |
| **回归** | 需求提到但本次不改，或焦点的直接上下游 | **只冒烟（≤1 条）**：到达入口 → 一次关键操作 → 1 条最终结果；不设检查点 |
| **范围外** | 需求未提，本次改动也不影响 | **0 条用例**：写入测试点清单「裁剪说明」 |

- 焦点项通常 1–3 条（>5 条回阶段 1 收敛）；找不到原文出处的候选一律降级（提过 → 回归，没提 → 范围外）。
- 需求本身明确要求容错（重试、降级、超时处理、幂等防重）时，该容错条目**就是焦点**。
- 优先级按业务风险判定（见 [test-standards.md](test-standards.md)），范围外直接不写，不讨论优先级。

## 二、范围闸门（候选点必过三问）

| # | 闸门问题 | 通过 | 淘汰（写裁剪说明） |
|---|----------|------|--------------------|
| 1 | **需求依据**：需求/变更说明/接口契约有明确条目（本业务独有规则，非通用挂机异常）？ | 有出处与专属规则 | 仅凭「一般都该测」 |
| 2 | **变更影响**：本次改动会新增或改变这条的预期结果？ | 会变 / 本次新增 | 不会变，顺手测测 |
| 3 | **失败归属与真实可测**：失败归本次责任方修，且无需关停共享服务、无需虚构工具、有真实业务动作即可复现？ | 是 | 归运维/平台，或靠虚构夹具/纯查配置 |

## 三、三类默认淘汰的膨胀用例

### 1. 服务故障与伪造异常类（默认 0 条）

断网、5xx、超时、依赖不可用、宕机、消息丢失**默认 0 条**；仅当「① 需求有明确容错/重试/提示条目 + ② 写清失败后用户可见状态/文案 + ③ 由本次改动引入或修改」三者全满足时才写。

**动笔前直接划掉的 4 类伴生废案**：
- **虚构未交付夹具**：环境未实际提供对应能力时，严禁凭空假设「隔离 Stub 返回 503」「受控响应篡改器」「推进可控服务端时钟」等虚拟工具。
- **同兜底逻辑按状态码机械裂变**：多种底层错误码（如 400/429/503）走同一套业务失败处理分支时，只留 **1 条**代表性用例，禁止按码拆多条凑数。
- **不可达脏数据**：禁止假设手工改库造出正常业务链路不可能产生的矛盾状态。
- **非测试伪任务与框架常识**：禁止把「查阅配置、核对模板清单、找负责人确认口径」写成用例；框架自带的畸形 JSON 解析与无特殊规则的纯 CRUD 不入库。

### 2. 边界值膨胀

仅当字段**同时满足**「① 需求给明确阈值 + ② 本次改该校验 + ③ 临界易算错（金额/配额/时限/权限数优先）」时取边界：
- **只取一组三点**：临界内、临界、临界外（如上限 20 字 → `19 / 20 / 21`）；对称区间只取一端。
- **等价异常合并**：空值、格式错误、非法字符合并为 1 组参数化（如昵称 1–20 字：空值 + 19/20/21 字 + 字符类型参数化组，共 4 条+1 组，严禁拆成 14 条）。
- 需求未给阈值的字段禁写「超长/非法字符」用例，先记入「原文问题清单」。

### 3. 非重点内容展开

- 非焦点旧功能最多 1 条冒烟，禁止因「来都来了」铺开多步校验或把 UI 文案/埋点/兼容单独成组。
- 顺带发现的疑点记入「原文问题清单」，不写成完整用例。

## 四、裁剪说明规范

写在测试点清单「裁剪说明」列，明确交代未落用例的原因：
- `范围外：PRD 全文无对应条目` / `范围外：依赖不可用归平台容错，需求未要求`
- `回归：仅冒烟，见 TC_PROFILE_EDIT_004`
- `低风险：字段无阈值，不取边界`
- `风险已知：影响面小，已记入待确认清单第 3 项`

**禁止**写 `暂不覆盖`、`后续补充`、`根据情况` 或留空。交付前确认：标题连读体现**本次变更焦点**而非模块通用全集。
