# 用例怎样在评审会上查阅

先让读者看清一个测试点有哪些场景，再决定深入哪一条。原版普通券的“余额刚好够与少 1 分”有 8 条用例。打开时可以一眼对照四个入口及各自的 100 分、99 分场景；需要核对扣分流水时，才展开相关用例。可用[独立 HTML 样板](../assets/swimlane-review.html)查看这一布局。

## 从测试点进入

- 在测试点旁显示“查看用例”和当前范围的数量。桌面图类页面使用双栏，窄屏可切换图与测试点用例。规则表使用通栏，点击规则后定位到表格下方的阅读区。
- 头部显示测试点原 ID、名称和对应用例数。“返回测试点”“上一测试点”“下一测试点”“展开／收起全部用例”保持可达。相邻点按当前可见范围切换，到首尾停下。已有搜索时，另标明命中数与总数。原稿还可“记一笔”，项目需要现场留意见时再接入真实记录功能。
- 同组多条用例初次打开只列标题；只有一条时直接展开。用例直达链接要打开所属组、展开并定位指定用例。允许多张卡片同时打开。已经展开过的同组卡片，在当前页往返时可保留。

## 一条用例怎样写、怎样排

标题行放折叠箭头、原始用例 ID 和业务标题。收起时显示“展开”，打开后同一位置显示“收起”。点文字或标题都切换这一条，键盘焦点保持在标题上。ID 用稍小的等宽字，场景名占主要位置，长标题可以换行。白底卡片之间留出间距，展开后用浅灰蓝底和清楚的小标题区分正文。正文依次展示 **前置条件、测试步骤、预期结果**，三组分别编号。操作和结果各自保留输入顺序，只有源材料明确对应时才逐步配对。必要的表格或查询示例跟在所属步骤下。

用例原有的口径说明紧邻该卡片。摘要须标明；待删除记录保留编号、标题和原因，可在组头同时提醒，避免参与执行统计。

标题负责展开或收起。每张卡片旁单独提供定位入口。反查时保留当前用例和同组已经展开的其他卡片，再从业务位置返回原卡片。从规则行或状态转移进入时，用例按实际关联筛选，可点“查看测试点的全部用例”切回该点的完整范围。

## 核验阅读路径

打开至少含两条用例的测试点，同时展开一对边界用例，核对各自的输入和预期。试一次全部展开、全部收起、切换相邻测试点，再用 Esc 和“返回测试点”回到原范围、入口和阅读位置。从单用例点、用例直达链接及待删除记录进入，分别检查自动展开、内容定位和状态提示。最后核对新旧稿的用例 ID、字段与顺序；页面展示检查与业务执行结果分别记录。
