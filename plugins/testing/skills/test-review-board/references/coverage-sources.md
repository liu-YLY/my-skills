# 覆盖缺口与来源依据

结构错误阻止生成，因为错误 ID、越界引用或重叠坐标会使读者看到错误关联。设计缺口可以随草案展示，让评审人决定怎样补齐。生成器和离线页面采用同一组缺口含义，统计按记录与缺口类型计算。

| 发现的情况 | 保存与展示 |
| --- | --- |
| 节点没有直接关联测试点 | 列入缺口，点击后定位该节点。只有环节入口时仍保留“环节关联”的说明。 |
| 规则或状态转移尚无关联测试点 | 点击待核对项定位规则行或状态转移。状态转移的起点和终点具有关联上下文。 |
| 规则或转移的测试点有用例，但用例都定位到了其他分支 | 单独列出此规则或转移没有可执行用例。若测试点本身就没有可执行用例，保留测试点的待补提示。 |
| 起止或交接节点无需独立测试 | 节点填写具体的 `no_test_reason`，在选中节点时展示。此理由免除“无测试点”提示；断开的连线仍需核对。 |
| 测试点尚无用例 | 保留 `cases: []`，显示待补充用例。点“查看用例”可看到空态说明并返回。 |
| 此点只有待删除用例 | 保留历史记录，但仍显示“尚无可执行用例”。 |
| 测试点暂时没有流程映射 | 保留空的 `nodes`，在 `unmapped_reason` 说明原因。 |
| 规则表中的测试点没有关联规则 | 显示待定位规则，评审时可进入测试点。规则表按规则映射核对。 |
| 用例尚无所属测试点 | 放入顶层 `orphan_cases`，保留原用例字段与 `unmapped_reason`。页面提供未映射用例入口。若能确定流程位置，可填写 `nodes`；缺少依据时省略。 |
| 多节点图中一个节点完全没有连线 | 显示“与其他流程节点未连通”，供评审确认是否漏画交接。 |

缺口数量表示需要核对的设计关系。一个节点可以同时缺测试点和缺连线，因此可能有两项提示。节点已有测试点、测试点已有用例，只能证明存在关联。各分支和业务规则是否被充分验证，仍需人工审阅；运行状态需要执行证据。

## 来源与状态字段

顶层 `sources` 为来源记录，每项含唯一 `id`、`title` 和可定位的 `location`。位置可以写需求章节、评论编号、文件及行号、执行记录或 URL。点引用名称可在当前页面查看出处，提供了 `url` 时可打开材料。

节点、测试点、用例和规则对象都可填写 `source_ids` 与 `fact_status`。

| fact_status | 用于什么材料 |
| --- | --- |
| documented | 所提供资料明确写出的事实，需要引用来源。 |
| inferred | 从已有材料推导出的规则，保留推导依据和需要确认的条件。 |
| pending | 内容尚待决定，直接说明未知项，来源可以为空。 |
| confirmed | 有明确确认记录的规则，需要引用确认依据。 |

`changed: true` 表示本期变化，可与任何事实状态并存。事实状态与“未执行、通过、失败”等执行结果属于不同信息。

既有 `rule` 字符串数组继续可用。规则各有不同依据时，把对应条目写成对象，例如：

```json
{
  "text": "通知失败后的自动恢复规则待确认。",
  "fact_status": "pending",
  "source_ids": [],
  "changed": true
}
```

来源字段是增量能力。旧数据没有状态时，保持未标记；生成过程不会把旧规则自行确认为已批准。有 `source_ids` 时校验引用存在；标为 documented 或 confirmed 时要求非空引用。脚本能检查引用结构，来源内容与确认人的身份还需核对实际资料。

## 用例仍可对应具体分支

一个测试点可以关联成功与拒绝两个节点。成功用例关联成功节点，拒绝用例关联拒绝节点。用例显式 `nodes` 应为父测试点节点的非空子集；省略时继承父点关联。顶层未映射用例没有父点，只检查其可选节点是否存在。节点归属和分支表达的调整都应有来源依据。
