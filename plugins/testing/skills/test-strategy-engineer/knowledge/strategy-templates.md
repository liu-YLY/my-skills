# 测试策略文档模板

> **何时阅读**：strategy skill 输出测试策略文档时按此模板填充结构与内容。
> **覆盖范围**：策略文档主结构 / 风险矩阵模板 / 分层策略模板 / 准入准出 checklist / 可选附录触发条件 / 反例。

## 1. 测试策略文档主模板

strategy skill 输出时按以下结构填充，每个 `{}` 必须替换为基于项目特征的具体决策，禁止保留占位符：

```markdown
# 测试策略文档：{项目名称}

## 1. 项目特征
- 项目类型：{后端服务/前端应用/全栈/微服务/遗留系统}
- 规模：{小<10人 / 中10-50人 / 大>50人}
- 关键质量目标：{SLA / 合规 / 用户体验}
- 约束：{时间/资源/技术栈}

## 3. 测试分层策略
| 风险 | 所选层与方法 | 可观察结果 | 现有覆盖与投入依据 |
|------|------------|------------|------------------|

## 4. 测试范围与优先级
- 必测（P0）：{}
- 选测（P1）：{}
- 不测（P2）：{}
```

## 2. 风险矩阵模板

5 维评分定义、评分锚点与风险等级映射**以 [risk-matrix-framework.md](risk-matrix-framework.md) 为唯一权威源**（§1 评分表 / §2 等级映射 / §3 空白模板），本文件不复制数值定义，避免双源漂移。填充时使用以下空白骨架：

```markdown
| 功能模块 | 业务复杂度(1-5) | 变更频率(1-5) | 历史缺陷(1-5) | 外部依赖(1-5) | 数据敏感性(1-5) | 总分(5-25) | 风险等级 | 测试优先级 |
|---------|-----------------|---------------|---------------|---------------|-----------------|-----------|---------|-----------|
|         |                 |               |               |               |                 |           |         |           |
|         |                 |               |               |               |                 |           |         |           |
```

**使用规则**：
- 评分必须基于事实数据（Bug 数、变更记录、依赖清单），禁止主观感觉
- 缺维度标待补，正式总分/等级未评估；完整5维才求和，临时优先级与代理指标另列
- 已确认发布阻断单列规则、当前缺陷和复核证据，不能以低总分抵消

### 覆盖情况报告（兼容可选输入）

| 覆盖层 | 分母与依据 | 已覆盖/未覆盖/未评估边界 |
|---|---|---|
| 需求条目 | `requirement_baseline` 的source/version/items | 通过confirmed `requirement_links`（item_id/scenario_ref/confirmation）关联设计；无需求基线为未评估，不能用模型总数替代 |
| 模型转换 | 当前模型版本与既有transition/forbidden清单 | 保留旧覆盖字段和forbidden规则级语义；结构覆盖不能证明业务需求全覆盖 |
| 适用场景设计 | `design_baseline` 的source/version/items与适用性信息 | applicable缺设计为缺口；not_applicable单列；unknown为未评估，待确认设计不计为已验证 |
| 实际执行 | `case_baseline` 的source/version/items与执行记录 | 未提供执行记录(None)时执行层和通过率未评估，明确空记录([])只说明未执行；设计完成不能写测试已通过 |

- 执行记录消费 `case_id/baseline_version/run_id/status/evidence_ref/evidence_status/evidence_check_source`（verified/unknown/unreachable/missing）；报告绑定准确基线与运行，verified 仍记录核验来源；缺证据、核验依据或版本不匹配单列未评估。
- 覆盖关联使用显式版本化产物 ID/trace_refs；stable_ref 仅作内容标识，不用展示编号或列表位置代替；候选关系不计 confirmed 覆盖。
- 各层报告分子、分母、来源/版本、缺口和未评估项；空集合/无适用项/输入缺失分别写空基线/不适用/未评估，不统一返回 0% 或 100%。
- 同一基线项、用例或执行记录按稳定 ID 和 run 去重；不同 run 分别报告；聚合规则缺失时不自行选择最佳结果。
- 四层输入均可选；独立策略任务可交付已有证据的范围，无法计算的层标未评估，不要求额外造完整追溯图或执行结果。

## 3. 分层策略模板

按 [test-pyramid.md](test-pyramid.md) 填风险、层与观察项。跨系统验收时写明依赖、版本和证据边界。

## 4. 准入准出 checklist 模板

阈值与完整清单以 [entry-exit-criteria.md](entry-exit-criteria.md) 为唯一权威源，文档中只列可勾选项：

```markdown
### 准入
- [ ] 开发自测通过，单元覆盖率达标；提测单含变更说明与影响范围
- [ ] 测试环境、依赖服务与测试数据就绪
- [ ] 需求/接口/设计文档齐全，用例已评审

### 准出
- [ ] 用例执行率、需求覆盖率、高风险模块覆盖率达标（按项目档位）
- [ ] 当前范围 P0/P1 缺陷按准出规则收敛；独立发布阻断项已复核
- [ ] P2/P3 修复率、回归通过率达标；遗留缺陷有责任人和时间窗
- [ ] 性能、安全达标；测试报告与回滚方案就绪
```

**使用规则**：checklist 项必须全部勾选方可准入/准出；阈值可按项目类型分档调整（见 entry-exit-criteria §3），调整必须标注理由；遗留缺陷禁止"待跟进"。

## 5. 可选附录触发条件

附录章节非默认生成，仅在用户明确要求时输出。触发条件如下：

| 附录章节 | 触发关键词 | 未触发时标注 |
|---------|-----------|------------|
| 资源估算附录 | 用户提及"估算人力/环境/工具" | 未生成（用户未要求） |
| 进度排期附录 | 用户提及"排期/里程碑/时间表" | 未生成（用户未要求） |
| 风险跟踪附录 | 用户提及"风险跟踪/跟踪清单" | 未生成（用户未要求） |

**判定规则**：
- 关键词需用户主动提出，strategy skill 不主动追问、不主动生成
- 触发判定基于用户原始输入，禁止从上下文推断
- 同一附录只生成一次，禁止重复输出
- 触发后附录内容必须完整填充，禁止半成品占位
- 未触发时主模板第 7 章整体替换为单行：`附录：未生成（用户未要求）`

## 6. 反例（不要这样做）

- **模板填空式输出** → 每个 `{}` 必须替换为基于项目特征的具体决策，禁止保留占位符。
- **默认生成资源/进度附录** → 仅在用户明确要求时生成。
- **模板照搬不引用知识库** → 评分维度、分层依据、checklist 必须与 risk-matrix-framework / test-pyramid / entry-exit-criteria 一致。
- **策略文档过长（>20 页）** → 聚焦决策（测什么/不测什么/何时停），执行细节交由测试计划。
- **软化措辞** → 禁止“建议/可以考虑/灵活把握/视情况而定”，必须给出明确决策。
- **分层脱离风险** → 说明所选层能观察哪个风险及为何值得投入。
