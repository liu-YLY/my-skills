# 路由失败模式与反例

> **何时阅读**：意图歧义、需要降级、子 skill 不可用、上下文丢失，或核对路由/安装反例时。路由顺利时不读。

## 失败模式与 Fallback

| 触发条件 | 一线修复 | 仍失败兜底 |
|----------|----------|------------|
| 意图不明确（含「测试」但未指明策略/用例/性能/Bug/状态机/变更/前端/数据） | 追问并列出 8 个子 skill 能力（🔴 CHECKPOINT） | 持续追问，不默认路由；仅用户明确「你来决定」时默认 test-case-engineer，并在首行标注 |
| 混合意图判定争议（如「防御性用例反推」边界模糊） | 有实际故障证据先诊断，再转生成用例；只有用例质量问题直接进用例修订 | 用户明确只要用例时直接 test-case-engineer |
| 子 skill 未安装 | 提示安装对应 skill 并给安装命令 | 标注「子 skill 不可用」，给方向性模板：bug-analyzer 五步定位；case-engineer 四阶段；strategy 五阶段；performance 四阶段；state-machine 五阶段；frontend 五步 |
| 评审类意图歧义（用例评审/评审方案/覆盖度汇报/规模化） | 按交付物：问题清单 → R2 评审；对外材料 → 评审方案；>100 条或排期 → 规模化 | 仍不明确则追问要意见、材料还是抽样方案（🔴 CHECKPOINT） |
| 混合协同失败（上游完成但下游不可用） | 输出上游中间产物，提示手动转交或自行处理 | 标注「协同中断」，仅输出上游报告，中间产物按 schema 作附录 |
| 子 skill 执行失败 | 捕获错误，回 bundle 层报告原因 | 提示直接调用子 skill 重试，或降级为方向性模板 |
| 上下文传递丢失 | 路由时按 schema 显式传递 | 标注「上下文不完整」，要求子 skill 向用户确认缺失信息 |
| 「性能 Bug」路由歧义 | 默认 performance（资源/架构层优先），内部判断是否转交 bug-analyzer | 用户明确为代码逻辑缺陷（死锁/N+1）时直接 bug-analyzer |
| 「测试计划/测试策略」双义 | 含项目级/测试计划/分层/风险矩阵/准入准出 → strategy；含单功能/某功能/某模块 → case-engineer | 追问是项目级还是单功能策略（🔴 CHECKPOINT） |
| 转交重复请求确认 | 展示转交依据，继续已授权分析 | 仅缺关键信息、范围变化或未授权写操作时询问；用户要求逐阶段确认时遵循 |
| 多链同时命中 | 按 mixed-intent-chains.md「链冲突裁定」执行最高优先链 | 无法判定则列候选链让用户选择；用户「你来决定」按默认顺序 |
| strategy 与 case-engineer 协同失败 | 输出分层策略与优先级，提示手动转交 | 标注「协同中断」，仅输出策略报告，分层策略作用例依据附录 |
| test-data-generator 未安装/依赖缺失/规则未确认 | 保留上游用例、规则来源与数据需求，报告缺口并按目标 skill 说明处理 | 不用少量手写样例替代批量执行；未运行标 not_run，无法检查的规则保留 incomplete；数据校验通过不代表系统测试通过 |

**上下文传递 schema**（路由/转交时必须按此 JSON 传递）：

```json
{
  "original_request": "用户原始请求全文",
  "upstream_artifacts": "上游 skill 输出（防御性测试点清单 / 分层策略 / 瓶颈定位报告等）",
  "completed_steps": ["已完成步骤摘要数组"],
  "downstream_task": "下游 skill 需执行的任务描述"
}
```

转交 test-data-generator 时，`upstream_artifacts` 保留用例编号/文件位置、固定组合维度、字段与关联约束及来源、数量、种子、输出位置和未决规则；只传已获得的资料，系统执行状态保持 not_run。

## 路由反模式

| # | 反模式 | 替代做法 |
|---|--------|----------|
| 1 | 不判断意图直接调用子 skill | 按路由决策表判断；不明确时追问（🔴 CHECKPOINT） |
| 2 | 在 bundle 层重复实现子 skill 能力 | bundle 只路由，能力由子 skill 承载 |
| 3 | 路由后不传递上下文 | 传原始请求 + 已收集上下文 + 已完成步骤摘要 |
| 4 | 混合意图不按先上游后下游 | strategy → case-engineer；performance → bug-analyzer（瓶颈指向代码缺陷时） |
| 5 | 已授权协同仍逐段暂停 | 报告转交依据；已授权只读分析连续执行，仅缺关键信息、范围变化或未授权写操作时询问 |

> 路由方向性反例（性能 Bug 路由到 bug-analyzer、项目级策略路由到 case-engineer 等）已编码在失败模式表，不重复。

## 安装反模式

| # | 反模式 | 替代做法 |
|---|--------|----------|
| 1 | 只装 bundle 不装子 skill | 整体安装 testing plugin（bundle + 8 个子 skill） |
| 2 | bug-analyzer 单独安装不告知降级 | 安装时提示「缺陷模式库会降级，同时安装 test-case-engineer 获得完整能力」 |
